# ConWU

在外面用 Moonlight 连自己的电脑，碰上 UDP 限速时，可以试试 ConWU。它在两台设备间建立直连通道，默认使用 FakeTCP＋HTTP，支持 Windows 和 Linux。

原名 StreamLink。当前开发候选为 `1.1.0-preview.2`，恢复 1.0.5 的界面布局，加入可共用的连接配置和双机多网络。候选包与已发布版本分开，实际串流由使用者确认。

[已发布版本](https://github.com/MrSGSA/StreamLink/releases) · [入口与配置](docs/ConWU-入口与配置.md) · [Linux 安装与使用](packaging/linux/README.md)

## 怎么连接

- **自主打洞**：两端使用同一个 HTTPS 协调服务，输入配对码，核对校验码后批准。无协调时也可分享直连邀请，但仍取决于主机是否取得可达入口。
- **已有入口**：填写公网地址、端口映射或其他工具提供的地址／订阅，直接向主机 ConWU 发送短配对码申请，无需协调服务。
- **多个网络**：每网一主一从，通道双向；同一设备可同时创建和加入不同网络，概况统一显示。
- **共用配置**：多个网络可使用一份配置，修改后一起生效。想单独调整时，再复制一份。

先在创建或加入页选好配置。配对成功后，把对方的虚拟 IP 填入 Moonlight 即可。Windows 平时在托盘运行，WebUI 用于操作；Linux 同样提供 WebUI 和 CLI。

ConWU 自带协调能力。协调设备不自动加入网络，也不转发串流。没有公共协调服务，没有业务中继；外部域名和订阅由用户自行维护，本版不包含内置 DDNS 发布。

## 使用范围

已有入口模式不会同时自主打洞，协议失败时也不会自动改走 UDP。订阅支持按标签区分主机，例如 `域名#streamlink1`。

不同 NAT 和限速策略的效果会有差异。FakeTCP＋HTTP 外层不是 TLS，内层数据经过认证加密；HTTPS 用于协调、管理和订阅。新候选的定向验证不等于长期公网大码率串流验收，具体记录随包提供。
