# ConWU

在外面用 Moonlight 连自己的电脑，碰上 UDP 限速时，可以试试 ConWU。它在两台设备间建立直连通道，默认使用 FakeTCP＋HTTP，支持 Windows 和 Linux。

原名 StreamLink。当前开发候选为 `1.1.0-preview.9`，直连邀请改为可手输的 16 位直连码，旧 SL6 邀请仍可粘贴使用。每个网络独立保存设置，第一次加入由主机批准，设置自动获取。候选包与已发布版本分开，实际串流由使用者确认。

[已发布版本](https://github.com/MrSGSA/StreamLink/releases) · [入口与配置](docs/ConWU-入口与配置.md) · [Linux 安装与使用](packaging/linux/README.md)

## 怎么连接

- **自主打洞**：两端使用同一个 HTTPS 协调服务，输入配对码，核对校验码后批准。也可分享 16 位直连码，直接联系主机；是否能连接仍取决于入口可达性。
- **已有入口**：填写公网地址、端口映射或其他工具提供的地址／订阅，可通过已有入口和六位配对码申请，也可使用直连码。可选协调服务只帮助首次配对发现。
- **多个网络**：每网一主一从，通道双向；同一设备可同时创建和加入不同网络，概况统一显示。
- **独立设置**：每个网络分别设置和保存，新网络从默认值开始，不联动其它网络。

主机在创建页设置网络，从机输入配对码或直连码即可申请；核对双方校验码、批准后自动获取设置。直连码按 `XXXX-XXXX-XXXX-XXXX` 分组，含 IPv4 入口，不必另外填写地址；五分钟内用于首次申请。配对成功后，把对方的虚拟 IP 填入 Moonlight 即可。Windows 平时在托盘运行，WebUI 用于操作；Linux 同样提供 WebUI 和 CLI。

ConWU 自带协调能力。协调设备不自动加入网络，也不转发串流。没有公共协调服务，没有业务中继；外部域名和订阅由用户自行维护，本版不包含内置 DDNS 发布。可选 PKARR 只发现入口，不承担业务中继。

## 使用范围

已有入口模式不会同时自主打洞，协议失败时也不会自动改走 UDP。订阅支持按标签区分主机，例如 `域名#streamlink1`。

不同 NAT 和限速策略的效果会有差异。FakeTCP＋HTTP 外层不是 TLS，内层数据经过认证加密；HTTPS 用于协调、管理和订阅。新候选的定向验证不等于长期公网大码率串流验收，具体记录随包提供。
