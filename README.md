# ConWU

在外面用 Moonlight 连自己的电脑，碰上 UDP 限速时，可以试试 ConWU。它在两台设备间建立直连通道，默认使用 FakeTCP＋HTTP，支持 Windows 和 Linux。原名 StreamLink。

首次连接只需分享 16 位直连码，由主机批准。从机会自动获取网络设置，之后继续发现和更新入口。

[下载最新版](https://github.com/MrSGSA/ConWU/releases/latest) · [版本说明](docs/releases/1.3.0.md) · [使用文档](docs/README.md)

| 系统 | 下载与安装 |
| --- | --- |
| Windows x64 | 下载 Release 中的 `.msi`，安装后从托盘打开 WebUI |
| Linux x86_64 / glibc | 下载 `.tar.gz`，解压后执行 `sudo ./install.sh`；提供 WebUI 和 CLI |

## 怎么连接

1. 主机打开“创建网络”，填写名称和网络设置，生成直连码。
2. 另一台设备在“加入网络”输入直连码，核对双方校验码，由主机批准。
3. 直连成功后，把对方的虚拟 IP 填入 Moonlight 等串流软件。

直连码显示为 `XXXX-XXXX-XXXX-XXXX`，不区分大小写，有效五分钟。生成前主机需要取得可分享的 IPv4 入口；创建网络本身不代表 NAT 已经打通。

## 选哪种入口

- **自主打洞**：默认配合 PKARR 自动发布和查询最新地址，无需注册域名。希望自行掌控发现服务时，可在高级选项中使用自己的 HTTPS 协调服务器。
- **已有入口**：填写公网地址、路由器转发、第三方工具打通的地址或 HTTPS/TXT 订阅。后续自动查询保存的订阅；静态地址变化时需要重新填写。多主机订阅可用 `#streamlink1` 等标签区分。

每个网络一主一从、通道双向。同一设备可以同时创建和加入多个网络，概览合并显示，每网设置独立保存。

## 使用范围

效果取决于两端 NAT 和实际限速策略，ConWU 不保证所有网络都能打通。已有入口模式只使用所填来源；本版没有业务中继，也不自动回退 UDP。1.2.0 新增可选的纯 TCP 和 HTTPS 承载；使用新协议时需主从两端一起升级并创建新网络，原有 FakeTCP 网络可以继续使用。

本版提供 **Phantun**，可在新网络的“连接协议”中选择。它使用 TCP 格式承载数据报，复用 ConWU 的审批、配置继承和端到端加密；主机需有可达的 TCP 入口。新协议需要两端使用相应新版并重新配对，同一接收端口只能共享相同协议。

本版另提供实验性的 **Mimic** 与 **TCPRAW**。Mimic 使用报文转换承载数据报；TCPRAW 由系统完成真实 TCP 握手后，通过原始 TCP 报文交付数据。两者不等待外层可靠字节流重传，Windows 使用现有 WinDivert，Linux 使用原始报文收发；主机仍需可达，TCPRAW 仍需要 TCP 建连成功。新协议需要两端升级并重新配对，不自动改变已有网络。

自主打洞优先尝试短期 UPnP 映射，处理外部端口占用与续租；端口设置中可选 PCP／NAT-PMP 后备。已有入口模式不申请映射或启动另一套打洞。路由器的 NAT1 等功能仍由用户设置，网关授权或 STUN 候选均需对端认证验证。

本版为纯 TCP 和 HTTPS 提供可选的“按流分离连接”，在网络设置的“连接方式”中开启。不同流使用独立连接，同一流保持顺序；不增加网络或重新配对，对端不支持时使用单连接。默认关闭，适合大流量影响控制或音频时按实测开启，不保证提高视频吞吐。

FakeTCP＋HTTP、Phantun、Mimic 与 TCPRAW 的外层都不是 TLS，内层数据经过认证加密。PKARR 和可选协调服务帮助发现入口，串流数据直接在两台设备之间传输。域名及外部订阅由用户维护，本版没有内置 DDNS 发布。
