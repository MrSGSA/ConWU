StreamLink 下一阶段：提高 TCP / UDP 打洞效率与成功率
2026-10-11；源码基线 09fa672；本文件为研发决策，不是新增能力的发布声明。

目标与优先级
用户已确认现有 udp2raw 网络效果满足当前需求，下一阶段资源转向打洞。
优先 TCP / FakeTCP，随后完善 UDP；面向一般 Windows 用户及不理想 NAT，
不将 Akane / Thinkbook、固定路由器或手工 Lucky 规则写成算法前提。
现有 FakeTCP + HTTP 为已验证的数据通道，吞吐仅做变更后的回归检查。
最多八成员、业务始终直连。协调服务只交换身份、候选和尝试进度。

一、已确认的实现基线
1. TcpMapping：固定源端口 TCP STUN + 持续保活 + UPnP 转发；也可使用
   手工入口。至少一端入口可达时，另一端主动连接。2026-10-11 双端实测
   已证明该路径可独立于 Lucky 工作，但未证明双端同时打开。
2. 原生 client.cpp：client_tcp_handshake 只接受来自指定 IP:端口的
   SYN+ACK，并校验 ACK 序号；对交叉到达的裸 SYN 会返回非预期包类型。
   native_backend.cpp 的客户端 WinDivert 过滤器也固定对端 IP:端口。
   因此两个现有客户端同时运行，不构成 FakeTCP 双主动打洞。
3. MeshTransport 未为客户端指定 --source-port；client.cpp 可随机选择
   并占用源端口。探测端口必须与实际承载资源对应，不能只在公告写个端口。
4. UdpTraversal 已实现同 socket 的 STUN、认证检查、真实来源学习和
   数据接口；66 项既有回环/模型检查通过，尚未接入默认 MeshRunner。
   现用 UdpMapping 仍依赖 UPnP，不是一般的 UDP 双向打洞。
5. MeshAnnouncement 目前只有单个 IPv4 Endpoint，没有候选集合、协议
   能力、每对设备的 AttemptId、双方准备确认或候选提名。
   0.4.1 的本地循环为 100 ms；公告 GET 为未全连时 2.5 秒、全连时
   5 秒，稳定 PUT 为 15 秒。已与 HTTP 异步分离，但不具备打洞轮次同步。
6. NatObservations 区分观测上下文和映射证据，过滤行为保留 unknown。
   当前 NatLab 是 UDP 映射/过滤模型，端口按固定步长分配；没有覆盖
   原生 FakeTCP 的 SYN 状态机、随机分配、端口块或完整 TCP NAT 模型。

二、第一交付：共用的候选与打洞轮次
这是下一次代码工作的入口，随后接 TCP 原生实验，不继续以跑分作为主线。

计划的数据结构：
- 候选：身份、CandidateId、协议/承载能力、主机/反射/显式映射类型、
  本地端口资源引用、远端可用端点、接口及出口代次、观测时间、有效期。
  本地资源引用只保存在本机，不在协调服务器公开句柄。
- 尝试：设备对、AttemptId、双方代次、候选对、角色、随机挑战、截止时间、
  首次发送和首次认证时间、发包/端口成本、原始失败原因。
- 候选只表示可以尝试；双方认证和数据验证后才能显示已直连。

协商采用 Offer → Ready → Start → Check → Nominate/Confirm；超时、
重复、乱序、取消、旧代次和角色冲突均明确处理。对称的发起冲突用稳定
节点身份排序解决，网络创建者身份和谁主动发起连接互相独立。
Ready 必须指明同一 AttemptId 和候选代次；不能只等本机三秒就发完收工，
也不依赖两台电脑墙钟严格同步。对时序敏感的试验使用往返观测和有限重试。

已有可达入口优先尝试，不等待完整 NAT 分类。近期成功方向和候选参与排序，
切网后作废，复用前仍重新验证。没有 UPnP 的一端不能阻止主动连接另一端。
同局域网候选可提前检查，避免同一 CGNAT / hairpin 不支持造成无谓失败。

协调层优先实现有界长轮询和版本变化通知：每台设备一个订阅，合并多个
对端的控制更新，保留普通轮询兼容。需要能力协商、新接口和单独配额，
不能把多轮控制消息塞进当前最多 4096 字符的单端点加密公告。
先在隔离服务验证，再迁移正式协调。旧客户端继续使用现有公告接口。

主要文件：
  新增 src/StreamLink.Core/TraversalCandidates.cs、TraversalAttempt.cs
  新增 src/StreamLink.Service/TraversalCoordinator.cs
  调整 MeshDiscovery.cs、MeshRunner.cs、MeshPeerTransports.cs
  调整 Discovery/MeshRegistry.cs、Program.cs 或新增独立控制消息注册表
  扩展 TraversalTests、MeshConnectionTests、Test-Coordination.ps1
以上是计划文件名，不代表已经存在或完成实现。

三、TCP / FakeTCP：优先提高没有显式入口时的覆盖
保留现有入口路径，同时建立独立、可关闭的原生双主动实验后端。

前置实验先解决真实端口的所有权和观测：
- 查清原生端口占用、STUN 内核连接与 WinDivert 收包的关系，保持正确
  本地 IP、端口、接口及代次；观察反射目标变化时的公网端点变化。
- 不将短命的普通 TCP connect 成功当作可接管的 FakeTCP 通道。
  内核 socket 关闭时的 FIN/RST、TIME_WAIT 和 NAT 状态需要分别验证。
- 必要时由原生后端发起独立的反射控制交互，让探测和 FakeTCP 都使用
  其拥有的真实端口；公开 TCP STUN 能否直接支持这种组织是待验证事项。
  不预设“关闭 STUN 再让另一进程 bind 同端口”一定保留原映射。

原生握手实验内容：
- 支持 SYN 发出后收到裸 SYN、SYN+ACK、重复 SYN、乱序 ACK 的状态推进；
  区分 TCP 握手方向与 udp2raw/HTTP 上层角色，避免双方都等或都发请求。
- 严格校验序列号与状态；保留现有 FakeTCP 数据报语义。握手重试不为
  业务增加 TCP 可靠重传和按序等待。
- WinDivert 只覆盖本轮有限候选和实际端口；允许有限的新来源进入候选
  验证，不因未认证 SYN 就替换当前业务路径，也不粗暴捕获所有 TCP。
- 多成员分别拥有尝试状态；每台共享预算，取消一对不结束其他成员。
- 普通 Windows TCP simultaneous-open 可作独立对照实验，用来区分
  系统 socket 复用问题和原生状态机问题，不自动成为业务回退承载。

修改重点：transport/udp2raw 的 client.cpp、server.cpp、connection.h、
network.cpp、native_backend.cpp、native_server.cpp；上层 MeshTransport
增加实际端口与轮次控制。具体拆分以端口所有权实验结果为准。
首先验证双方映射稳定但过滤严格的组合，之后再引入端口预测。

四、UDP：先接好常规打洞和真实来源学习
把现有 UdpTraversal 接入同一候选/轮次框架，补全双方一致的候选提名、
保活、重启和出口代次。STUN、检查、获胜后的业务继续使用同一 socket。
首个 PoC 可用真实 MeshLink 加密帧验证获胜 socket；若直接承载 MeshLink，
必须标明是独立 UDP 承载，不能称为已通过 udp2raw 的 UDP 生产路径。
若保留 udp2raw UDP 封装，则在原生后端拥有 socket 或加入明确的收发适配，
不能以 Windows 两个 SO_REUSEADDR socket 冒充同 socket。

常规路径验证后，按观测证据逐项启用：
1. 一端映射稳定：认证后学习对端实际源端口，并触发反向检查。
2. 可重复的递增/递减规律：小范围预测，协商基线、发送顺序与轮次。
   目的端口变化可能同时改变本端源端口；不能固定本端映射扫一片端口。
3. 一端稳定、另一端端口不可预测：有界多 socket 概率打洞，保留获胜
   socket，并记录 NAT 映射资源回收延迟。当前 8 socket 全局默认预算
   不能无提示放大；增强模式先在实验环境逐档验证。
4. 双端随机的地址/端口相关映射和过滤：不套用单端稳定的生日概率模型；
   到预算就报告直连失败，不通过大量扫描掩盖没有可用策略。

UDP 打洞成功和 UDP 抗 QoS 是独立结论。不会因为 UDP 首个握手更快就
抢占已经验证有效的 FakeTCP 路径；路径选择沿用用户的传输策略。
IPv6、PCP、NAT-PMP 是后续候选来源；尤其 IPv6 需要原生后端同步支持，
不能只在公告放入 IPv6 地址就声称可用。

五、实验与验收：成功率、耗时、成本一起统计
1. 统一计时：点击启动→网卡就绪→本地资源就绪→双方 Ready→首包→
   双向认证→同一承载上应用数据可用。将网卡/服务启动与打洞耗时分开。
   现有 18.891 秒全进程重启、5.271 秒首次 ping 均不能直接当作打洞耗时。
2. 每种可复现场景先做 30 轮基线和候选策略对照，报告成功数/总数、
   失败原因、成功样本 p50/p95、超时上限和样本量；失败轮不从总数删除。
   使用不同随机种子和噪声流，分别报告新映射与保留映射的热重连。
   30 轮只是工程起点，不能据此推导所有用户的成功率或可靠尾延迟。
3. 矩阵覆盖 EIM/ADM/APDM 和 EIF/ADF/APDF 的组合，以及固定、递增、
   干扰递增、随机、端口块、多公网 IP、双层 NAT、hairpin 和 UDP 仅放行
   STUN。TCP 单测交叉 SYN 允许/丢弃/RST、SYN+ACK 丢弃及不同启动偏差。
4. 将真实原生 FakeTCP 收发接到可控 NAT/报文模型，再用 Windows 实机
   和实际路由器复核；模型通过不当作公网成功率。UPnP 关闭场景仅在实验
   路径禁用自动映射策略，不关闭用户路由器的全局 UPnP。
5. 检查失败、取消、休眠恢复、切网、对端晚到和八成员竞争；记录每轮
   包数、活动 socket、候选数、连接次数和控制请求。稳定链路不被实验
   重试反复拆掉，空闲状态不执行满带宽测试。
6. 每项新能力必须在同一获胜资源上完成双向认证数据，而不是仅有 STUN
   回包或 SYN+ACK；成功后少量实际报文检验，50 Mbps 留作阶段回归。

发布门槛
新策略在声明支持的 NAT 模型中可重复成功，且在至少一组相应真实拓扑中
验证后才开放实验选项。保留原稳定入口的回归结果，记录未覆盖拓扑；没有
证据时不承诺双 NAT4 必连。无法直连时给出实际失败阶段，业务仍不中继。

六、工作顺序
TRV-1 候选/轮次/日志与控制通道：下一项代码任务。
TRV-2 原生 TCP 端口观测与双主动 SYN：核心实验，优先于概率扫描。
TRV-3 UDP 现有模块集成、双向提名与同 socket 数据：复用 TRV-1。
TRV-4 有证据的预测与稳定端多 socket：依赖 TRV-2/3 的基础路径。
TRV-5 真实拓扑重复统计、切网恢复及实验发布。
每项均独立记录已完成/模型验证/实网验证；本次更新只确立方案和验收。
