# M5：预测准备阶段的 TCP 反射回退

基线 `3e3e749`。普通候选收集会尝试配置列表中的多个 TCP STUN 服务器，预测准备此前只使用首项；即使其他服务器可用，首项 DNS、连接或查询失败也会终止本轮增强。

## 接线

正式 `MeshCandidateFactory.GatherCoordinated` 的预测准备现在按既有配置优先级，尝试最多三个不同服务器。每项包含解析、源路由核查、独占 TCP helper、捕获就绪和同源查询；单项仍用 3.5 秒，准备总上限 12 秒，排队和准备继续受外层成对机会窗约束。

失败资源在下一项之前完全退役。不会将失败事务或另一条源端点的观察移交到获胜源；预约记录真实获胜反射目标。捕获/驱动初始化错误立即返回，换 STUN 不能修复捕获所有权错误。用户/Attempt 取消后不再创建下一条连接。

查询成功后才取观察器目录并进入原预约协商。新鲜原生观察仍由实际获胜资源完成；两秒首次预测发包门槛与共同八秒观察/握手期限保持。反射失败没有生成 Forecast，因此不会被当成两次真实预测失败来停用合格模型。共享高成本名额和 HTTP 预算没有增加。

## 验证

`artifacts/m5-helper-fallback-runner-v3-20261012.json/.log` 通过 36 检查：

- DNS 失败、拒绝连接、真实回环 helper 无回复后，下一项产生可用预约；失败捕获先关闭，预约期间没有对等原生 SYN。
- 在途取消、三项全部失败、捕获初始化失败均明确退出，归还高成本名额与实际源引用；捕获失败只试一项。
- 真实 HTTPS、TCP helper、C++、正式 Runner/Actor/Router，两种稳定端角色各一轮连接并传送完整双向业务；其中一轮两端都实际经历首项 DNS 失败，仍在同一机会窗完成预测。
- 新鲜映射不再符合稳定模型时，零预测对等 SYN、零选中路径。

两轮 Runner 选中时间为 27.737、26.621 秒，包含先失败的普通候选及协调额度等待，不是性能对照。校准训练、NAT、raw/IP 收发是明确的内存夹具；真实 Windows 驱动、Wintun、公网预测和严格 NAT 成功率 Gate 不因此提升。

早期测试夹具遗漏 `FreshWindowMs`，按产品能力核查被拒绝；补全该字段后通过。新增完整 Runner 回退用例曾缺 `System.Net.Sockets` 引用，修正后完成本次验证。失败日志保留在 `m5-helper-fallback-runner-20261012.*` 和 `m5-helper-fallback-runner-complete-20261012.log`，不计入通过证据。

`m5-helper-fallback-app-build-20261012.log` 的 App/Core/Service Release 构建通过。该能力仍以显式 TCP 预测开关和双方/协调/校准资格为前提；本次开发验证未部署现用服务。
