# 兼容客户端异步准备与取消候选隔离

承接 `c41b886`，独立开发分支；不改变该来源的0.5.6打包输入，不安装候选。生产仍运行0.3.2。

正式MeshRunner使用进程共享的启动队列，把可能同步阻塞的能力查询和原生进程构造移到后台。最多一个构造在运行、十六项等待；等待者取消不创建资源。在途构造不可强行中断的部分会完成后释放其Job/子进程，不发布迟到候选。主循环继续发现和维护。排队及构造计入原兼容十五秒轮次，不在完成后重置期限。

构造在启动原生客户端前将本机UDP桥端点登记为未启用。准备结果仍属于当前有效请求，才由主循环明确设置候选并发起新挑战。公告失效、机会窗取消或更换候选会取消准备；退出等待所有已拥有的构造，并清理其结果。

Router为显式取消的客户端端点保留每成员最多32条有界记录，删除其旧挑战，在AEAD状态处理前拒绝该来源。旧Pong和未经再次登记的Hello不能重新启动验证。新的明确登记允许复用端点数字，但必须返回新挑战。共享MeshLink序号/重放状态不重建。

本地验证：

- `out/startup-runner-final.json/log`：19项，包含真实后台阻塞构造、七等待者、排队/在途取消、旧Active保持、实际加密UDP迟到Pong/Hello及正式Runner发现继续、1280B业务、停止回收。
- `out/startup-connections-full.log`：100项完整连接回归。
- `out/startup-mesh-full.log`：40项组网与禁止成员转发回归。
- `out/startup-reserve-native.json/log`：实际C++/Windows管道/Router验证构造前端点登记，FakeTCP+HTTP及UDP双向完整业务通过（单轮，27项）。原生二进制来自未变的`c41b886`生产源码。

主测试使用正式组件及真实Windows UDP，IP适配器和同步阻塞构造是夹具；原生验证用独立回环backend。没有新增物理WinDivert/Wintun或公网数据，本次不宣称20.921秒样本已经改善，也不提高完整发布Gate。
