# ConWU 精简入口与三端更新

用户已确认精简预览，并要求移除概况中的本机入口、DDNS 两张卡片，更新笔记本、Akane 和 Linux 服务器供实机测试。本轮不发布 GitHub Release。

## 行为约定

- 设置分为本机、连接、端口、DDNS、更多；全局保存和撤销不变。
- 默认准备接收连接与加入申请，无需另选“提供网络入口”或“本机协调服务”。接收端口集中设置。
- 加入网络允许直接填可达设备地址、HTTPS/TXT/DDNS 来源或原直连邀请；六位配对码仍走 HTTPS 协调。所有新成员仍需审批并核对双方校验码。
- 不强制修改已有接收端口、服务器 Tunnel 的目标端口、传输协议、身份或网络。新旧程序切换期间保留独立的 EasyTier/SSH 管理路径。
- FakeTCP＋HTTP 和真正的 HTTPS 协调保持各自语义。可达设备入口在业务接收端口进行带审批的配对；HTTPS 管理仍使用安全的本地监听／TLS，不向公网开放明文协调。
- DDNS 删除独立发布开关：保存更新令牌后自动维护已取得的入口，未配令牌只发现。不为已有入口模式启用自主打洞。
- API Token 不进入状态、配置导出、日志或浏览器存储；仅在授权本机页面明确点击显示时临时读取，切页隐藏。清除需确认并保存。
- 原设置、网络状态和自动启动须在升级前后核对；本轮新增或改变的默认能力单独列明。

## 验证与交付

实现后先分开检查正确性／安全与产品／质量，再做受影响回归；冻结候选后进行必要完整核心验证、Windows 与 Linux 打包和实际安装。三端分别保留回退资料，核对文件清单、配置摘要、服务和健康检查；不把这些检查写成长时间大码率串流已验收。

候选版本为 1.0.6-rc.10，MSI 版本为 1.0.35。具体构建提交、核心验证和三端实际部署结果保存在 `artifacts/conwu-simplified-20261107/`；包内 manifest 标明来源提交，未完成的部署不能根据本文视为通过。

## 两轮独立检查

正确性／安全检查：成员身份仍由签名目录和批准后的 ECDH 加密凭据决定。公开配对承载本身不是业务密钥；未经批准不能进入虚拟网。原生资源使用有界会话，入口请求限速、单申请及五分钟到期；已有角色权限不会因升级扩大。令牌显式读取继续经过本机账户授权、面板会话、Origin 和 CSRF 检查，普通状态不带凭据。加入得到的入口单独绑定网络，保存设置不抹除它；运行时按地址去重，避免两个入口工作线程争用同一来源。

拒绝申请后可立即准备下一次申请，仅短暂保留上一申请者十秒的拒绝回执；回执严格匹配原会话和令牌，不授予成员资格，也不会覆盖新申请。入口刚轮换的短暂忙碌由客户端限时重试，另一项待审批或待交付授权则给出明确提示。

产品／质量检查：概况删除入口与 DDNS 信息卡；设置只显示五个分区，高级项折叠保留原值。增加地址时保持折叠区展开。保存按钮反映全部分区，退出后输入恢复可编辑；迟到状态和令牌显示结果不能覆盖后续操作。保持原端口、自启和身份，三端升级不用重新配置 Tunnel。

UDP 默认接收器还需与地址发现共用端口：绑定允许受控共享，WinDivert 分流标准 STUN 回复到原内核套接字。使用官方过滤器编译器及真实包格式评估成功、错误回复和普通业务，不以字符串检查代替过滤行为验证。FakeTCP＋HTTP 默认协议和无回退策略保持不变。

统一原生配对承载要求参与设备一并更新，旧版外层握手不能混用。本轮按用户要求更新三端，保留旧包及受保护备份；不把新的公开接收能力描述为 NAT 穿透保证，也不把这次验证描述为长时间大码率串流已验收。
