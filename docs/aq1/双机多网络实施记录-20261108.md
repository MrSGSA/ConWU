# ConWU 1.1.0-preview.1 双机多网络实施记录

执行日期：2026-11-07～08。接续提交：`89e2798c840e703831aa252573e228809ade3512`。当前为候选构建前记录，不能作为已发布或三端已更新的证明。最终提交、包哈希和部署结论以随交付证据为准。

## 本版行为

一个网络固定一台创建/审批主机和一台从机，通道双向。设备可以同时创建、加入多个独立网络；概览汇总所有网络，不以页面选择决定运行目标。网络之间不转发。最多保存 16 个本机网络配置，同时运行最多 8 条关系。

协调能力仍在同一个 ConWU 程序中，多个网络共用 HTTPS 服务；协调设备不自动进入任何网络。已有入口模式不执行自主 STUN、映射或打洞。默认 FakeTCP＋HTTP，不回退 UDP，无业务中继。

## 配置与身份边界

- 设备根保留 `profile.dpapi`（Linux `profile.json`）；设备身份、名称、Cloudflare 凭据、协调服务及创建默认值在根保存。
- 每网为 `networks/<本机配置ID>/profile.*` 和 `network-info.json`。本机配置 ID 负责本机操作和文件归属；两端共享网络 ID 负责授权、会话和 DDNS 命名，两者不可互换。
- 子配置从根读取共用项，不复制根设备私钥或 Cloudflare Token。Windows 使用 DPAPI/ACL，Linux 使用私有权限。根与全部子配置共用持久化门，跨网重复设备和端口检查与落盘串行。
- 单网和全局设置保存具有受保护事务记录。失败或崩溃只恢复设置，不回滚已生效的成员签名与撤销水位。仅明确修改过自启的事务恢复系统自启状态。
- 加入中断但尚未收到授权的临时配置在重启时退役；已保存授权但索引尚未更新的配置保留。退出后的普通空配置与其用户设置继续保留，需明确移除配置才退役。

稳定设备身份由根 ECDSA P-256 公钥派生；配对证明绑定这一次 ECDH 承诺。双机目录把两成员限制纳入签名。第三台不能扩为三成员；同一对设备的第二条关系会被拒绝。主机批准但加入端丢失交付时，只允许同一持久身份开始新的校验和审批；旧成员需在新审批后撤销替换，不能凭旧证明恢复权限。

## 与初始建议的差异

本版每网独立官方 Wintun／Linux TUN 和独立 `/24`，以确保退出、故障和恢复隔离，尚未采用初始提议的共享网卡与 `/30`。创建侧自动候选避开本机已知路由/其他 ConWU 网段；加入侧冲突明确拒绝，双方自动重编号协商尚未实现。

兼容网络共用物理原生接收器和接收端口，各自保留独立源端口。不同模式或独占实验出口不能强行共用。`CNW1 + 网络ID` 仅用于分流；内层 Router 继续验证对应网络的 AEAD/签名，路由提示没有授权能力。代理路由、操作队列和网络数量均有上限。

安装前追加复核确认：原创建流程会在不同协议冲突时移动接收端口，却原样保留固定公网地址或订阅入口。该路径已修复为创建前明确拒绝，提示先修改设备默认接收端口并核对映射；不生成临时网络目录，不改已有网络或设备设置。只有未对外发布的出站源端口继续自动分配。固定地址、订阅入口的失败复现及修复后检查、独立端口的另一协议正例均保留证据。

Windows 原生分类器显式识别一层 CNW1 后继续按内层帧分类，防止把业务误计为握手而受到控制包速率限制；截断和嵌套封装不获得业务豁免。Windows 原生资源设备总上限为 32，覆盖 8 条网络各自监听、Active/Candidate 和临时入网资源，实际共用监听时通常更少。全设备控制包预算未提高。

共用裸入口有多个同优先待配对网络时明确报歧义，不猜第一个网络。直连邀请及专属 `conwu-ddns://` 链接绑定目标网络；同持久设备重新申请优先定位其已有关系。新网络准备期间允许客户端有界重试。

DDNS 共用根域名，继续以 `e-设备ID.n-网络ID` 第三方候选记录和 `d-设备ID.n-网络ID` 签名记录隔离更新。只把服务端确认成功的一批内容显示为“已发布”。六位配对码仍依赖 HTTPS 协调，DDNS 本轮只负责发现与更新入口。

## 安装与兼容

版本为 `1.1.0-preview.1`，MSI `1.1.0`。本轮使用用户明确允许的全新安装，不静默迁移 1.0.x 的旧网络权限。旧程序、受保护数据和可安装回退包须先备份；不兼容配置在运行前明确拒绝，不按空配置覆盖。

全新安装只清理该产品实例记录的适配器/内核规则。Windows 维护枚举根及所有历史网络的精确 Scope，不全局删除共享 Wintun 驱动；Linux 取得实例锁并按私有资源日志恢复。独立 SSH/EasyTier 管理通道保留。

回退至 rc.10 的安装动作本身仍包含旧版全局驱动清理，不能仅靠新版“不调用 DeleteDriver”保证整个事务。Windows 专用全新安装流程在旧包可能运行期间持有独立、精确归属的官方 Wintun 保护适配器，并在每次启动 MSI（含失败回退）前核实进程代次与实际接口 GUID。旧维护必须据此保留其他适配器和共享驱动；只有确认安装或完整回退结束后才释放保护资源。MSI 超时、要求重启或恢复未完成时保留保护与私有证据，禁止盲目关闭保护后继续旧安装。

真实隔离 MSI 首次执行发现读取属性时 COM `Execute()` 向 PowerShell 管道写入空值，属性函数返回空值与产品代码的数组，导致 `ProductState(...)` 空引用，发生在全新安装停服之前。正式脚本丢弃 Execute 输出，要求属性为单个非空字符串，并改用仅从 System32 加载的 `MsiQueryProductStateW`；预检和回退使用同一状态判断，未知异常状态停止恢复并保留保护资源。具体真实重跑结果另记，不能把模拟检查写成实际安装通过。

后续真实保护检查发现，官方 Wintun 的设备描述可为 `StreamLink Tunnel`，不能要求描述包含 Wintun。已移除描述字符串过滤，仍逐次核验保护进程代次、精确接口 GUID 和 `SWD\WINTUN\{GUID}` 的当前 PnP 在场状态；使用实际描述的模拟回归通过，真实资源清理单独记录。

电量恢复后重跑 `82ba8074` 的 v5 核心，实际发现 `ChildJob.Dispose` 只等待系统进程退出，没有等标准输出、错误输出的 EOF 回调，日志仍被占用便返回。该轮失败及受控中止另行保留，不能记作电量中断或完整通过。修复追踪两路 EOF，在有界等待后关闭日志，再释放 Process；尾行观察和脱敏保持有效。启动注册、关闭及重复关闭使用同一生命周期门，失败启动关闭日志，单个子进程异常不跳过其他子进程清理。Linux 不再无界等待子进程退出，关闭失败显式报告。实际子进程回归覆盖尾行、文件独占打开、并发启动与双重关闭和失败启动；原生传输、观察器和关闭失败路径另跑受影响回归，再重新冻结候选。
