# 双机多网络产品与质量复核

日期：2026-11-08。集成负责人交叉检查 WebUI、CLI、安装与运行体验；与正确性/安全复核分开。本文记录开发期复核，最终冻结提交及包验证见交付证据，不能据此宣称正式发布全部通过。

## 产品约定核对

- 网络主机负责审批，从机不获得管理权限；Moonlight/Sunshine 的串流方向不受主从限制。设备可同时主持、加入不同关系。
- 概览汇总全部网络，不用选中一个网络才能看到其他连接；去重按认证 DeviceId，速率与流量取业务计数，持续时间显示天时分秒。
- 设置区分设备默认/共用项和单网络项，切换保留草稿；保存全部草稿是一次批量事务。默认值只供新网使用，不暗中覆盖已有网络。
- 配对码优先、加入申请独立导航；本机发布来源与远端入口编辑分别定位；轮询保持折叠和输入状态，后台恢复后清除过期提示。
- 既有入口只走既有入口；自主打洞要求 HTTPS 协调。DDNS 是可选发现/更新能力，候选地址、确认发布和实际直连分别展示，不把 STUN 地址当已可达入口。
- Linux 使用同一核心与明确网络目标的 CLI，协调只是可独立启用的能力，不占用每网成员位置或虚拟 IP。

## 复核发现与修复

1. 新网络尚未挂接共享接收器时，旧的已满网络可能过早返回不接收入网申请。已对无明确目标的准备期设置有界重试；多候选歧义仍立即提示，邀请绑定目标网络并等待接收器就绪。
2. 批准后加入端未领取授权便退出，会让旧交付占住申请位置。已允许同一持久身份绑定新承诺重新开始，必须新校验码和主机再次批准；保留虚拟 IP、撤销旧成员，不增加重复设备。开发期真实三个 worker 的授权交付丢失、重启与双向传包通过。
3. 加入中断的空临时配置可残留并消耗名额。已记录 PendingEnrollment，重启只退役未保存 Mesh 的未完成申请；已授权配置和正常退出后保留的用户设置不受影响。
4. 设置恢复和创建复制默认值可能交错。创建时同样取得共用设置门，避免把尚未提交或稍后回滚的默认值复制给新网络；取消与结束释放 CTS 在同一准入门中串行。
5. 损坏后续网络索引时，已打开的较早配置 lease 可能没有释放。构造失败统一回收所有已打开上下文；新增先损坏、拒绝、修复后重新打开的实际受保护配置测试。
6. Windows 全新安装脚本只复制维护 exe，无法携带多文件发布包的依赖。已改为核验 manifest、提交和全部文件哈希，复制完整候选运行目录后再维护；模拟回滚通过，真实 MSI 仍须单独验证。
7. Linux 真实 namespace 测试发现共享接收器新目录未创建，原生配置写入失败。共享接收器在 factory 前建立私有目录、失败时清理；Linux 原生传输也统一创建私有会话目录，覆盖直接地址/邀请配对路径。须以修复后的真实 TUN/FakeTCP 重跑结果为准。
8. 高吞吐复核发现 Windows 原生分类器不认识 CNW1，导致业务误入控制包预算。已添加单层封装分类、截断/嵌套负例，以及实际 C++ 双网业务突发和 BusinessPackets 计数验证。设备原生资源上限从旧单网的 15 调整为有界 32，匹配 8 条双机网络的监听、连接与临时入网；控制速率预算保持原值。
9. 每条网络的状态重复读取共享自启/服务信息，16 份配置时一次轮询会访问 SCM/注册表 17 次。子网络不再单独读取 Desktop，工作区只从设备根读取并提供完整共享状态，避免把系统服务查询延迟放大。
10. 实际回退编排复核发现 rc.10 的安装动作仍可能全局删除 Wintun 驱动，验证实例和生产失败回退均受影响。保护措施纳入正式 App 维护入口及全新安装事务，在旧 MSI 运行前验证独立持有的官方 Wintun 接口和进程代次；未确认结束的安装不释放保护。隔离 MSI 结果须明确是在该保护条件下取得，不能套用未受保护的旧包测试结论。
11. 回退重装旧 MSI 会自动启动服务，原服务处于停止状态时此前只恢复启动类型。已将原运行/停止状态恢复统一放入恢复函数，并模拟旧 MSI 自动启动及改为 Auto，分别验证恢复原 Running 和原 Stopped/Manual。发现后中断尚在早期的第二轮核心，保留中断证据；最终冻结后重新完成整轮验证。
12. v3 完整核心通过后，安装前复核发现创建不兼容协议时会静默移动接收端口，已填写的固定入口或订阅仍指向原端口。失败复现保留，修复为明确拒绝、提示调整设备默认端口，且拒绝前不产生网络目录；增加独立端口允许另一协议、出站源端口仍可分配、现有网络与设置保留的正反例。v3 包未部署生产，不作为修复后的最终候选。
13. Windows 真实隔离 MSI 首次执行时，正式 fresh 脚本读取 MSI 属性混入 COM Execute 的空输出，使状态调用收到数组并在停服前空引用；模拟安装未能发现。已丢弃空输出并校验属性标量，再改用 System32 的原生 MSI 查询并统一预检/回退判断，异常状态保留保护与旧数据。首次失败、受控清理和修复后真实重跑分别保留，不能用 mock 通过替代真实结果。
14. 真实保护网卡已就绪，设备描述却为 `StreamLink Tunnel`，旧检查要求描述包含 Wintun 而误判。已用精确 GUID 和 Wintun PnP 身份替代描述过滤，保留进程代次检查；使用实际描述的模拟测试通过。再次冻结后须继续真实安装验收，尚无生产部署结果。
15. 电量恢复后 v5 核心实际发现子进程已退出但日志仍锁定。已修复生产共用 ChildJob 的双输出收尾、启动/关闭并发、重复关闭及异常清理，测试直接在关闭后独占打开日志、核对双流尾行与脱敏，不用文件删除重试掩盖缺陷。该次 v5 失败证据保留，需要重新冻结；原已通过的 v3 不代替新结果。隔离 MSI 验证脚本也加强保护网卡等待期检查，并区分内部保护的历史隐藏行与实际 PnP 在场，尚须最终包真实验收。
16. v6 完整核心和 Linux 真包/TUN 通过后，真实 Windows fresh 的保护检查被 CIM GUID 字符串格式阻断。修复比较的双方类型，mock 采用实际字符串并加入格式及缺失/重复等负例，真实 guard 启停回归通过；v6 失败记录与安全清理结果保留，生产未更新，完整 fresh 不算通过。交付预检另确认 AKANE 缺 .NET 10，部署辅助工具改为自包含并在任何生产 fresh 前验证启动与加载的候选 Core 哈希；普通用户令牌环境预检通过，实际软件浏览器仍需验收。

首轮冻结核心共 58 步，仅旧治理测试仍按 64 KiB 拒绝 UI 消息而失败，其余步骤通过。新版接口为有界 1 MiB；已保留首轮失败证据，并把该检查改为旧上限以上可完整往返、超过新上限在写帧/读正文前拒绝，不能通过删除边界检查解决。最终结论须以修复后再次冻结的完整核心结果为准。

## 质量证据与边界

开发期已覆盖两关系共享入口、跨网拒绝、伪造/超长输入、单网退出不影响另一条、真实 HTTPS 协调配对和协调离线后业务继续、授权应答丢失、后台重启、排队取消/停止、并发重复身份提交和保存失败回滚。Windows 原生共享入口另使用真实 C++ FakeTCP＋HTTP 协议和父控制通道，通过完整 MTU 的双向业务；原始包载体为回环夹具，不能当作公网测试。

8 条运行关系、16 份保存配置、源端口和虚拟网段去重属于受控资源边界检查；使用内存适配器，不能代表八台物理设备或长时间吞吐。真实 Linux TUN/原生路径、实际 MSI 安装/回退、日用三端更新和物理串流各自记录证据。

本轮协议/配置不兼容 1.0.x，用户已允许备份后全新设置；不能套用旧“保留同一网络升级通过”的断言。以后相同设置语义的更新继续保留，未能迁移时明确提示。

剩余质量门包括冻结候选完整核心验证、包内 UI/命令验证、真实安装与资源生命周期、物理链路吞吐/恢复，以及 Moonlight 长时间高码率。执行条件和实际结果写入最终交付记录；没有做过的测试不记通过。
