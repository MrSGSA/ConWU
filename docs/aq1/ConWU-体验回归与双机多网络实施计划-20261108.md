最新范围决定：用户取消内置 DDNS。主线固定为“共用 HTTPS 协调服务器＋自主打洞或已有入口＋双机多网络”，以稳定双向串流为目标。此前关于域名 B、自动 DNS 发布、DDNS 短码配对的讨论全部退出本轮执行范围。

用户最终归纳：基本上是在 1.0.5 基础上改为双机多网络；有协调服务器时自动完成配对后的地址交换和建连，无协调服务器时手动提供主机入口。已有入口采用“一台主机一份明确来源”，或由用户按 ConWU 约定格式为共用来源标明目标。不继续开发无标识混合主机地址池的自动识别功能。

最新配置决定：创建网络前先新建或选择已保存的配置。网络引用配置，一份配置可供多个网络共用；在设置页修改并保存后，对所有引用它的网络生效。列表明确显示关联网络，未关联的配置也可独立保存。只有需要单独调整时才显式复制，不采用默认复制或隐式全局设置。

实施中最新确认（优先于下文此前的流程措辞）：

| 连接策略 | 配对与入口 |
| --- | --- |
| 自主打洞＋协调服务 | 协调服务与短配对码完成发现、审批、候选交换及必要的同步打洞 |

已有入口的多主机区分由用户维护，例如内容为 `streamlink1=地址`、`streamlink2=地址`，在配置中分别使用 `txt://域名#streamlink1`、`https://订阅网址#streamlink2`。也接受 `域名#标签` 的 TXT 简写。标签只筛选候选，配对仍须核对和审批。

执行者：由用户切换至 Sol，推理档位 max，单代理完成。不得新建或唤醒 Terra 及其他子代理。正确性／安全和产品／质量两轮检查由同一执行者分开完成，如实注明为自查。

本计划覆盖此前关于界面大幅重组、成员平等治理、内置 DDNS 等相冲突的要求。AQ-1 的真实性、安全、默认 FakeTCP＋HTTP、官方驱动、回退与交付原则继续适用。历史测试数量不作为本轮任务清单。

## 1. 最终产品目标

以 1.0.5 的界面、布局和操作习惯为体验基准，让一台设备同时维护多条独立的双机连接。每个网络只有一台创建／审批主机和一台从机，连接双向。设备可以在网络甲作为主机，在网络乙作为从机。

ConWU 保留统一的 Windows／Linux 核心和程序内协调能力。用户先保存一份连接配置，再用它创建或加入网络、输入配对码并审批；后续网络可以共用这份配置，也可以选择其他配置。程序自动管理网络身份和地址交换，业务流量在两设备之间直传，网络之间不转发。

| 范围 | 本轮约定 |
| --- | --- |
| 必须交付 | 1.0.5 UI 体验、创建前配置、可共用配置及关联管理、短码审批、双机多网络、合并概况、固定协议、自主／已有入口互斥、可靠保存／退出／重连、Windows 与 Linux 可运行包 |
| 基础设施 | 使用运行 ConWU 的可达设备作为共用 HTTPS 协调端；用户现有 Linux 服务器继续承担此角色 |
| 保留备用 | 手动输入主机固定地址或外部 HTTPS/TXT 订阅，按直接申请流程核对并审批；直连邀请用于分享目标身份和明确目标网络；无协调属于手动配置路径 |
| 移除 | 内置 Cloudflare／其他 DNS 提供商适配、DNS 凭据和界面、自动建／更新／删除 DNS 记录、域名 B 转发布、DDNS 短码索引 |
| 后续独立议题 | 公共托管发现、免费域名、无服务器自动发现、去中心化管理、更多抗 QoS 传输；不在此版本中继续扩展 |

默认流程：主机选择已有配置或填写并保存新配置（协议、连接策略、入口方式、HTTPS 协调地址等）→ 创建一条双机网络并生成短码 → 从机选择使用同一协调服务的本机配置并输入短码 → 核对和审批 → 获取双方候选并认证直连。主机有现成入口时在配置中保存地址或订阅，没有现成入口时选择自主打洞；两者共用同一配对与身份模型。多条网络选用同一份配置时建立引用关系，后续保存该配置会更新所有关联网络；不是每次读取都复制一份。

无协调流程：手动输入明确属于目标主机的地址／订阅，或粘贴该主机生成的直连邀请 → 直接申请 → 双方核对和主机审批 → 建立双机网络。裸地址无法区分同一设备下多条待接入网络时，明确提示使用对应网络的邀请，不猜选第一条、不自动替换已批准的从机。

此次“回到 1.0.5”指体验与必要功能的收敛，不把三端直接降级为旧二进制，也不重新引入后续已修复的缺陷。保留 ConWU 名称和既有统一图标／配色。

## 3. 网络、设备与入口的边界

### 3.1 身份与双机关系

- 设备 ID 属于本机持久身份，普通重启、改名、换 IP、加入／退出网络和升级不重新生成。
- 每次创建新网络生成新的网络 ID 和网络凭据。网络存在期间保持稳定，入口变化不重新配对；删除后重建使用新的身份。
- 网络名仅用于显示。密钥和授权必须按网络隔离，不能用相同域名、相同公网 IP 或设备名合并权限。
- 同一对已配对设备重试或重新上线应恢复原关系。批准应答丢失、退出重进、重复请求不能产生重复成员或第二条意外连接。
- 主从身份决定创建、审批和删除权限，Moonlight／Sunshine 的方向由用户决定。已经通过双向验证的通道支持任一方向串流。
- 保留当前网络目录的有界容量：最多保存 16 条网络、同时运行 8 条连接。新增配置库也需独立设置容量边界，不能按配置数量误计网络数量。它们是软件资源上限，不能冒称八台实机串流已验证。

### 3.2 配置中的入口与资源复用

本机的固定公网入口、端口映射或第三方订阅保存在选定配置中。多个网络引用同一配置时共用这些设置，修改后作用于全部关联网络；选用不同配置的网络互不改写。兼容网络可以复用同一接收器和入口解析结果，但每网仍有独立身份、会话、生命周期和统计。配置共用与底层资源复用分别管理，不能因为入口地址相同就合并配置或权限。

“一主机一入口”是来源归属约定，不要求一网络一地址，也不要求一主机一个域名。同一域名下不同 HTTPS 路径／不同记录可以分别服务不同主机；同一主机的一个来源也可包含它自己的多个候选。若多台主机共用同一份更新内容，用户须按约定格式区分，具体规则见 5.2。

不能把“入口一样”扩大为“任意 NAT 元组都可复用”：

- 公网监听、明确映射和第三方提供的通用可达入口，可以发布给多个网络。
- 对特定目的地址形成的 STUN 观测、临时打洞端口、Attempt／Lease 等按网络、对端和尝试隔离，只通过对应协调过程交换。
- 兼容资源按引用计数复用；不同协议或取得方式冲突时明确拒绝或要求独立端口，不能暗中切换用户已公布的接收端口。
- 已有入口模式停止该入口资源的自主 STUN、映射和打洞。切换来源要先完成原所有者的退出，不能同时争用端口。
- 相同订阅只进行一份有界查询；去重必须包含完整来源及凭据语义，不能把不同 token 的链接合并。

### 3.3 自主打洞与反馈

创建网络成功表示身份和配置保存成功，不能等同于公网打洞成功。创建后启动入口准备，沿用 1.0.5 页面中的状态与反馈区域，显示：

1. 网络已创建。
2. 入口准备中／已取得候选／入口准备失败，并给出可操作原因。
3. 对端加入后，正在建立连接／验证中／已直连。

从机主动连接可达主机后，返回流量通过同一已建立通道，不要求从机另有独立公网入口。部分 NAT 打洞仍需双方通过协调服务交换候选并同步操作；只有 STUN 地址、只有 SYN 或只有单向探测均不得显示“已直连”。

入口准备失败不删除网络，不清空设置。保持有界退避和手动重试；健康通道不因订阅刷新或有其他离线网络而主动拆除。

## 4. 程序内协调

- 安装并运行 ConWU 的设备具备协调能力，不要求部署第二套独立协调程序。每个网络所引用配置里的 HTTPS 协调地址决定实际使用哪台设备；多份配置可以填写同一服务，不强制全部网络使用同一地址。
- 内置协调采用异步监听和有界请求处理，不扫描外部网络寻找客户端。空闲时只保留监听及必要过期清理；请求、配对房间和记录有容量及频率限制。
- 协调服务按网络身份处理配对、审批消息和候选交换。网络 ID／网络密钥由网络主机生成，审批后经认证加密流程交付；协调服务器不得直接向任意查询者返回明文网络密钥。
- 协调设备不自动加入每个网络、不占各网虚拟 IP、不承载串流数据。如需串流，它以普通设备身份另行创建或加入网络。
- 每台设备可以同时参与网络和承担协调；选择某个协调地址不会使所有已安装设备自动进行多副本同步。
- 不增加普通用户的角色切换步骤。后台提供协调能力；本机协调服务的监听端口、公开 HTTPS 地址及必要证书／反代配置属于“本机设置”。网络选择连接哪个协调服务属于所引用的连接配置，两者不得混为同一个开关或保存范围。
- 运行程序不等于公网已可达。默认本机安全监听、通过现有 Tunnel／反代公开，或明确配置直接 HTTPS；不能默默公开管理 WebUI。
- 协调离线时保留健康业务通道，本机退出／移除网络仍可完成。全网撤销是否确认必须与本机移除区分，不能伪报远端已删除。

现有 Linux 协调路径为 `127.0.0.1:42864 → https://conwu.space4sgsa.com/`，执行时只读核对。业务接收端口与协调源站端口不同。Linux 的 443 被其他服务使用，不得擅自接管。

## 5. 发现、已有入口与自动重连

### 5.1 协调是默认发现途径

自主取得的候选或已解析的第三方候选通过现有认证／加密协调协议交换，按网络和设备隔离。普通用户无需另配域名、DNS 提供商、记录标签或 API Token。

六位码定位协调服务上的有期限配对会话，审批后交付网络凭据。地址变化只更新候选，网络 ID、成员身份和批准关系保持稳定；主机删除后重建使用新的网络身份。

协调服务负责发现和打洞消息交换，不保证所有 NAT 都能穿透，也不能消除数据面的丢包或 QoS。两端没有有效通道时准确显示原因；本轮无业务中继。

### 5.2 保留通用已有入口，不管理外部 DNS

- 支持固定 `IP:端口`、`域名:端口`、HTTPS/TXT 订阅及现有 `streamlink=` 格式。第三方只返回地址，不上传 ConWU ID、密钥或签名；不逐一适配打洞软件。
- 来源的创建、地址上报、外部 DDNS 和计划任务由用户自行选择的工具维护，软件提供简短格式示例和教程。
- 普通 A／AAAA 记录只提供 IP，需要另有固定端口；动态端口使用能返回完整 `IP:端口` 的订阅。
- 来源归属本机或远端必须明确；远端入口不能当成本机入口对外公布。默认来源只服务一台主机，第三方不需要身份字段。
- 多台主机共用同一订阅时，用户按随包文档提供带目标标签的内容。只约定一种有版本说明的通用格式，兼容现有单主机纯地址／`streamlink=` 形式；提供可复制示例，不要求上传私钥或网络密钥。目标标签只是筛选依据，最终仍核验设备身份。
- 不为多台主机混杂、没有目标标识的内容增加自动身份学习／登记服务。显式多主机内容缺少目标选择时报告歧义；单主机来源中的多个地址按有界候选处理，首次加入仍以核对和审批确定身份，不能声称软件能猜中用户意图。
- 继续定时解析订阅、去重和有界缓存。解析失败不拆健康连接；解析成功不等同于设备在线或直连成功。
- 去掉 ConWU 的 Cloudflare 更新客户端、DNS 凭据界面、自动记录维护、内置 DDNS 链接／短码发现流程。通用 DNS 解析和 TXT 订阅读取继续保留。
- 对已有 `conwu-ddns://` 配置明确提示需要改为普通入口或订阅，不静默转换为无身份保护的裸 TXT，也不清空其他可用来源及网络。旧敏感配置仅留在受保护备份中，新运行路径不再使用 DNS 编辑凭据。
- 移除功能不自动删除服务商上的记录，不改已有 Tunnel／STUN／Lucky 域名配置。需要清理的外部记录给出准确说明，由用户自行处理。

### 5.3 明确来源后的身份核验

通过协调配对、直连邀请，或手动指定单主机来源并核对审批，确定目标身份。订阅中的目标标签只做筛选，不能替代认证。复用现有有界候选与认证框架，不增加通用混合地址池发现协议。

顺序为：解析候选 → 尝试建立承载 → 验证目标网络／设备与本次挑战 → 审批及正式授权（首次加入）→ 双向路径验证。端口可达、能握手、名称相同或第一个回应均不等于配对成功。

必须覆盖两组不同主从机使用明确目标信息的情况：从机甲使用甲的配对信息，即使误配的候选让乙先响应，也不能接受乙。目标筛选有歧义时给出修正来源的提示；握手不能向不匹配目标泄露原始网络密钥或自动授予成员权限。

保留既有按网络保存的身份和候选缓存，地址失效后重新读取明确来源并核验。不要为本轮额外建设跨主机地址登记表。不能把针对一个对端的 NAT 元组推广成所有网络都可用的入口。删除一条网络只清理它的映射及资源。

### 5.4 直连邀请与地址变化

保留手动主机入口与直连邀请作为无协调路径。邀请交付目标身份与入口来源，可解决共享设备入口下目标网络的歧义；不再增加 DDNS 配对码或公网注册表。

当前源码的 `DirectInvitation.Entries`、`DirectPairInvitation` 与 `NetworkEntryEnrollment` 已有携带入口来源的结构，应审查和复用，避免重建另一套邀请系统。邀请及审批交付保留稳定订阅原文，不能只保存生成瞬间解析到的 IP:端口。

- 使用固定 IP:端口且没有更新来源：地址变化后需要用户更新入口；ID 和密钥无法推导新地址。
- 保存 HTTPS/TXT 订阅或固定域名加端口：重新查询来源，按已保存身份验证新候选；不因普通重启重新审批。
- 使用协调：重新从协调服务获取有期限的候选，再验证直连。
- 首次邀请／配对码到期不撤销已批准成员。新网络、删除后重建或身份丢失不能凭旧映射自动恢复授权。
- 两端都不可达且无协调时，准确提示无法发现／建立通道。已有入口不会自动转自主打洞，任何模式都不自动回退 UDP。

## 6. UI 范围：恢复熟悉的操作，只增加必需内容

以 `v1.0.5` 的 `index.html`、`style.css`、页面结构和主要交互为参照，不继续采用 preview.1 的全面重组方案。创建前配置和设置页配置管理是用户明确要求的调整，不能为了复刻旧页面而继续使用单网络全局设置。

- 保留“概况、创建网络、加入网络、日志、设置”及熟悉的设置分区。保持统一图标、Tokyo Night、六位码下划线、审批同意绿色／拒绝红色。
- 增加紧凑的网络选择／管理入口，按下面的配置流程调整创建和设置页。创建页可创建另一条独立网络，不再因已有网络整页锁死；加入页不要求先退出其他关系。
- 概况默认合并显示全部网络及对端状态、实际虚拟 IP、流量与连接时长；一条网络故障不显示为整个后台失联。
- 操作必须明确针对哪条网络。收到申请标明目标网络和设备；不在未明确目标时猜选第一条关系。
- 设备设置、可共用的连接配置和网络自身信息明确区分。切换网络、切换配置、切换模式、状态轮询不丢草稿，不把界面当前选中项当作所有操作的默认目标。
- 移除 DDNS 设置区、域名／Zone ID／API Token／自动发布状态及相关复制按钮。保留原“已有入口”的地址与订阅输入；默认配对流程使用配置中指定的协调服务，直连邀请保持备用。
- 本机已有来源 A 与目标主机来源清楚区分，避免重复输入。新增页面元素必须能解释它帮助用户完成什么操作。
- 保留已修复的按钮不可点、迟到状态覆盖、误报后台丢失、成功后错误不消失、输入框重绘、退出后设置清空等行为保护。

### 6.1 创建和加入前选择配置

创建网络页先展示“使用已保存配置／新建配置”。已有配置可查看和编辑，明确列出目前关联的网络；新配置填写名称、连接协议、自主打洞／已有入口、协调服务及该模式所需字段。选择某配置本身不修改它，也不复制它。

- 提供“仅保存配置”和“保存并创建网络”。未关联配置可以预先保存；仅保存未关联配置不创建网络、启动打洞或分配网卡。编辑在用配置后保存，则按关联关系更新现有网络。
- 使用已有配置创建第二条网络时，第二条网络引用同一配置，但生成独立网络身份和成员关系，不复用第一条网络的邀请或凭据。
- 如果创建页编辑的是已被其他网络使用的配置，“保存并创建”必须展示这些网络也会受影响；需要只改新网络时，显式选择“复制为新配置”。
- 加入网络也先选择或新建本机配置，不能继续偷偷读取某份全局设置。主从两端各自保存配置；本机共用不等于跨设备同步设置。配对绑定的目标身份、协议约束及来源归属必须核验，不能被所选配置静默覆盖。
- 创建／加入失败时保留已保存配置和用户草稿，区分“配置已保存”和“网络创建／加入失败”；重试不得产生重复网络或悬空关联。

### 6.2 左侧设置管理配置与关联网络

“设置”入口展示配置列表，并保留独立的“本机设置”。配置支持新建、查看、编辑、显式复制及删除。每份配置显示名称和“未关联网络”或“用于 N 个网络”，可直接查看具体网络名称及状态；离线、暂停、未直连的网络也算关联，不能只统计正在运行的连接。

例如：“家中主机”配置用于“主机—笔记本”和“主机—另一台电脑”；编辑并保存该配置后，两个网络都接收修改。需要让“主机—笔记本”使用不同策略时，用户复制出另一份配置并让该网络改用它，原配置和其他网络不变。

- 编辑区的保存作用于当前配置的全部分区，并明确显示将影响的关联网络；不是保存全库，也不是只更新当前显示的网络。未保存时高亮，无改动时不可点击。
- 撤销恢复当前配置最近保存值；恢复默认只改当前配置草稿，保存后才影响关联网络。本机设置独立保存，不与连接配置混成一笔隐式全局修改。
- 为网络更换引用的配置前，检查角色、身份、协议及端口是否兼容；需重连的改动明确列出影响，不能用换配置来替换已批准的对端或绕过审批。
- 退出／删除网络只清除该网络的关联和自身运行数据，不删除配置、不改其他引用者。最后一个关联网络移除后，配置保留并显示“未关联网络”；断开连接、重启、离线均不解除关联。
- 未关联配置可以直接删除；仍被网络引用的配置禁止直接删除，列出需先改用其他配置或移除的网络。不级联删除网络，不用默认配置悄悄替换。
- 创建、加入、删除和换配置后，列表关联数与实际记录同步；同名网络不能靠名称判断身份，页面显示足够信息供区分。

先提供基于真实 1.0.5 布局的静态预览供查看，再接入真实状态和操作。预览期间核心实现可继续推进；不得把静态页面当作软件已可用。

## 7. 配置、Linux、安装与管理

- 保留稳定本机身份、按网络隔离的受保护凭据、原子设置事务和共用资源归属。配置库使用稳定配置 ID 与版本；网络记录引用配置 ID，并独立保存网络身份、成员凭据及运行状态。引用不能只是初始化时复制一份设置；关联关系以网络记录为准，避免两份名单不一致。
- 本机设置包括设备身份／名称、开机启动、日志等级、服务注册及本机协调服务监听。可共用配置包括连接协议、连接策略、入口来源、访问的协调服务及其信任设置、业务端口与 STUN 等参数。网络 ID、配对会话、密钥、已批准成员、实际虚拟 IP、候选租约、流量和连接时长不得进入可共用配置。
- 配置中如保留虚拟地址偏好，只作为分配条件；每网最终地址仍独立核对冲突。主机入口与目标主机入口保持明确语义；不同角色或目标不兼容时不能强行共用，不得将远端来源改解释成本机发布来源。邀请及审批交付的目标信息按网络保存，不反写共用配置而污染其他网络。
- 保存配置前核对版本和全部关联网络的适用性；绑定、解绑和保存并发时保证一致性，不遗漏新关联网络，也不恢复已删除关系。复制只复制用户设置并生成新配置 ID，不复制网络、凭据或运行状态。保持敏感来源与证书信任设置的存储保护。
- 保存后向所有关联网络分发生效：可热更新的立即应用，需要重建通道的明确提示和执行重连；停止的网络在下次启动读取最新版本。分别报告“配置已保存”与各网络“已应用／等待重连／应用失败”，不能因其中一条成功就声称全部生效。
- 已知角色、端口或身份冲突在保存前拒绝并指出具体网络；运行时失败保留已保存配置及准确的各网应用状态，不静默丢弃修改或回写其他配置。能保留的健康通道不被无关网络失败拆除；需要重连的通道遵循用户选定协议，不回退其他协议。切换协调地址若需要重新登记或配对，应明确告知，不能假装原授权能自动跨服务器迁移。
- 每网使用独立 Wintun／Linux TUN 和地址空间，先保留现有隔离方式，不在本轮重做共享网卡。同配置下各网的打洞尝试仍按对端隔离；资源复用不能合并尝试身份或造成端口抢占。
- 自动分配地址避开已知本机路由和其他网络；加入侧冲突要明确提示，不能抢占现有路由或静默改变已经发布的地址。未实现自动重编号就如实标注。
- Linux 保留与 Windows 一致的双机网络语义、配置库及核心能力，CLI 明确配置与网络目标，提供关联查询和修改影响反馈；协调专用运行不强制要求 TUN／串流资源。
- 日常退出、删除、加入、切换显示及升级不清空用户设置。移除的旧功能字段可以不再使用，但原文件先保留；当前多网络配置能继承的应继承。
- 上轮“全新安装”许可不自动等于本轮可以再清空全部配置。无法迁移时明确说明受影响项，在旧配置上安全停止，不当成空配置覆盖。
- 旧版按网络保存的设置迁入配置库时保留各自内容，不能仅因值相同就自动合并为共用引用；用户明确选择共用后才建立联动。旧运行状态不得回写覆盖用户保存的配置，新版本迁移保留配置 ID 与网络引用关系。
- 继承后续 MSI、进程退出、日志 EOF、Wintun 精确归属和安装回退修复。构包使用高于已安装 MSI 的有效版本号，不覆盖 `v1.0.5` 标签或 Release。
- 服务器远程设置便利性仍是待办：复用恢复后的同一 WebUI，管理认证、Cookie、CSRF、Host／Origin 与协调接口隔离。现有未验证 remote-admin 草稿须单独完成检查后才能纳入，不得因开启协调而自动开放管理权限。

## 9. 必要验证与停止边界

用户已明确实际串流由本人测试。本计划不授权重新进行两机 WAN、吞吐、压力或长时间 Moonlight 实验，也不以这些实验阻塞可运行候选交付。实施中的编译、定向单元／接口／受控回环、认证和必要安装检查用于验证代码正确性，结果不得写成实机串流结论。

定向检查应覆盖以下行为，而非追求测试数量：

1. **身份与隔离**：跨网络记录、错误设备 ID／密钥／签名、重放、过期、删除重建、重复加入和应答丢失；第三台加入已有双机网络被拒绝。
2. **双向与独立性**：受控通道双方发送完整 IP 包；单网停止／失败／取消不释放其他网络的监听、适配器和连接。
3. **自主与已有**：第三方只返回地址即可解析；错误归属来源不能当作本机；已有模式绝不调自主候选；不能把 STUN 观测当可用通用入口。
4. **候选身份**：单主机多候选、按标签区分的多主机来源、明确目标下错误主机首先回应、裸入口目标歧义、目标离线、同地址被其他设备复用、伪造身份及跨网络回复；全部地址可达也不能绕过核验与审批。
5. **缓存与生命周期**：来源／端口变化、订阅失败、停用、退出、删除、重启、邀请到期后已批准关系恢复；旧候选不能无限续期，健康业务不被刷新拆除。
6. **设置与界面**：配置未关联／关联单网／关联多网，离线网络仍计入关联；创建和加入选用同一配置、保存更新所有引用者、未关联保存不启动网络、显式复制后互不影响；删除网络保留配置、阻止删除在用配置、换配置与保存并发、应用部分失败及重启后读取新值；各配置草稿／版本冲突、模式切换、刷新、后台标签页恢复、取消／超时后可输入、成功后错误消失、审批颜色与目标、汇总不重复计费。
7. **协调与远程管理**：空闲监听无外部扫描；请求有界；协调离线本机可退出；管理未登录不能读设置，跨站及会话失效不能修改设置。
8. **安装与配置**：旧网络设置迁移不自动合并，升级保留配置内容及网络引用，不把运行候选／邀请写入共用配置；不兼容变化明确提示；更新停止真实旧进程；Wintun／Linux 资源只清理精确归属；保留可用回退。

增加移除回归：旧配置启用了内置 DDNS 时，新版不能继续构造写入客户端或执行遗留发布任务；迁移提示不会清空其他设置；普通域名和 HTTPS/TXT 订阅仍可读取。此版本无需 Cloudflare 编辑凭据或 DNS 写入验证。

发布前固定一次候选，做匹配本轮功能范围的必要核心验证；保留／调整旧 DDNS 和治理测试清单时说明新契约。不恢复历史 30 轮或全研究矩阵，不把删掉失败测试当修复。
