# 1.0.3 修复与全面检查

基线：`0ade939`（1.0.2）。本轮先修复、定向回归与分离检查，冻结候选后完成必要核心验证，交付并上传 1.0.3。保留 1.0.2，不用研究传输替换产品默认协议。

## 已报问题与调查

- 退出后重入：来宾退出只删除本机凭据，主机仍保留旧成员；再次审批随机签发新成员会留下旧身份。需要基于旧成员签名证明关联重入，禁止依靠名称/IP 猜测同一设备。审批完成时原子替换旧成员并回收旧连接，保持不同设备独立。
- 端口占用：两机日志有 `AddressAlreadyInUse`。区分固定接收入口、STUN 内部源端口和旧资源未退出；自动端口必须公告实际绑定，固定公网转发入口不能静默换端口。
- 创建/配对超时：Akane 日志 21:48:34 的 create 与 21:49:24 的 pair-poll 使用同一个泛化“对端或网络请求超时”提示。检查 HTTPS 请求阶段、状态提交顺序和重试幂等性。
- 提示残留：正常状态渲染未清除连接中断 banner。审查状态、配对、操作与字段提示的来源和恢复生命周期。
- 审批：同意在左、绿色；拒绝在右、红色，视觉权重一致。确认弹窗也必须使用对应语义。
- 侧栏：总设备数与“与其余 n 台设备直连”分行；直连数排除本机且与实际健康状态一致。

原始两机日志和仅包含公开字段的配置摘要保存在忽略目录 `artifacts/release-1.0.3/`。原始日志不直接作为 Release 附件；不得输出或上传生产凭据。

## 独立抗 QoS 实验

在修复版交付后使用独立实验链路，不加入 1.0.3 产品代码或菜单。真实 TLS 单/多连接、QUIC DATAGRAM、时限队列与纠错分别对照 FakeTCP＋HTTP；视频码率暂定 50/100/150/200 Mbps，重点大码率动态场景。统计稳定视频码率、延迟尾部、冻结/断线、实际线路字节、额外冗余与资源。先筛选再长测；硬件/物理容量单列，不经 EasyTier 数据隧道冒充公网物理直连。

## Wintun 实机调查与恢复设计

同一 GUID 复开、换 GUID 立即重开、仅保持官方 DLL 和单次重试都留下了失败证据。单独 ctypes 调用固定哈希的官方 Wintun（无 StreamLink 网卡桥、无 IP 配置）也在第二次创建出现 4319，官方日志为设备问题 0x38；因此不能归因于串流协议或凭测试次数掩盖。`CMP_WaitNoPendingInstallEvents(0)` 已返回空闲，仍可失败。官方 API 对照中关闭后等待 30 秒的三轮成功。

恢复使用稳定本机 Device 范围的独占锁，加当前网络/成员的兼容锁；实际网卡使用新 generation GUID。受管理员/SYSTEM ACL 保护的有界记录识别自身缓存，跨网络删除/重建和批准重入仍保留归属。仅在自身接口没有 PnP 节点、GUID/名称/类型匹配且还有缓存时，根据关闭时间最多等待 30 秒；显示阶段/倒计时，支持取消，等待后重核。正常无缓存接口不延迟。未知、活动或其他产品的网卡不接管、不删除。

更新器不再重建旧 GUID 来清缓存；可清理休眠的本实例 PnP 节点，缓存接口或其他 Wintun 仍在时保留共享驱动。Windows 原生接口/IP 表布局由本机 MinGW SDK 的 sizeof/offsetof 实际验证，避免全量 IP/DNS 枚举拖慢状态准备。最终候选及正式包的实机结果单独记录。

定向结果：重入核心/主机与来宾实际服务、真实 HTTPS 503/超时/恢复、51 项配对、97 项 Web 和 41 项实际浏览器断言已通过。Wintun 三轮本进程、取消等待、槽位轮换、两轮新进程及同 IP 新网络通过；维护 14 项保护与三轮清理复开通过。冻结后的核心及包结果另附，不把失败的早期方案删除或并入最终全绿。
