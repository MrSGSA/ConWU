# ConWU 与 Cloudflare DDNS

2026-11-06，`feat/unified-host-linux` 开发分支。用户确认产品显示名为 **ConWU**，命令和域名用小写 `conwu`。试验共用域名为 `conwu.space4sgsa.com`。

ConWU 1.0.6-rc.8 完善入口与 DDNS 的配合；rc.9 修复自动配对轮询禁用按钮，rc.10 精简为五个设置分区并支持直接填写设备入口申请加入。旧安装包和受保护数据备份保留用于回退。DDNS 默认关闭，不会因升级自行开启或修改已有连接设置；新版在用户保存 DDNS 设置时，按是否配置令牌自动决定发布或只读。实际 Cloudflare 发布仍需要有效的本机令牌，模拟验证不等于真实公网发布已验收。

## 2026-11-07 使用路线澄清

已有入口和 HTTPS 协调保持原有功能。DDNS 主要提供软件自主入口的地址发布与发现，不增加新的传输模式，也不代替首次入网审批。

- 自主模式：用户完成网络与 Cloudflare 配置后，ConWU 会尝试取得映射；成功后自动发布、续期，并跟随映射变化更新地址。这个过程不需要用户另建 DDNS 计划任务。但 DDNS 不能使任意 NAT 自动可入站；当前默认自动入口依赖 STUN 与可用的 UPnP 路由能力，可选网关端口控制另受相应功能设置约束。不能把“已配置域名”当作“已打通网络”。
- 第三方工具：继续接受通用 IP:端口、域名:端口、HTTPS/TXT 来源，不逐个编写 Lucky 等专用适配器，也不新增供第三方覆盖签名记录的更新任务。没有地址输出或更新接口的工具，ConWU 无法可靠知道它的外部端口。已有稳定更新链接直接使用即可，不要求再经由 ConWU DDNS 转发。
- DDNS 与手动路由器转发：可用的通用方案是公网 IPv4、固定局域网设备地址和 TCP 端口转发，由路由器或用户已有 DDNS 更新器维护普通 A 记录。已有入口填写“域名:外部端口”。例如外部 TCP 44680 转发到游戏主机的 ConWU 接收端口 44680。该普通入口域名使用 DNS-only，不经过 Cloudflare 网页代理。只有运营商内网 IPv4 时，单独新增路由器规则和 DNS 记录不能打开运营商的上层 NAT。

上述第三方和普通路由器 DDNS 路线是现有通用入口的用法，不代表本机签名记录可以由第三方直接写入。自动生成 Lucky 专用记录/任务配置不是当前交付功能。

rc.9 同时修复 WebUI 自动配对轮询占用全局忙碌状态的问题。自动轮询不再禁用退出、删除、保存等显式操作；后台可取消的读取会让位给同一授权用户的新操作，已经进入不可取消的成员提交则继续完成。迟到轮询结果不会覆盖后来的操作，正常让位不显示成“操作已取消”。

## 入口如何配合（1.0.6-rc.8）

DDNS 负责更新和发现地址，不是新的传输模式，也不替代首次入网审批。

| 用法 | ConWU 的工作 |
| --- | --- |
| 自选服务器、自主打洞 | HTTPS 协调维持配对与发现。若开启 DDNS 发布，即使暂时没有在线对端，也会尝试取得本机有效映射，接收器启动后发布。单独的 STUN 返回值不会直接进入 DDNS。 |
| 自选服务器、已有本机入口 | “提供网络入口”中的本机地址或 HTTPS/TXT 订阅也会读取并发布，不再被连接方式忽略。 |
| 已有入口 | 只使用所提供的入口，不调用自主 STUN、映射或候选打洞；可选择继续使用 HTTPS 协调，或沿用直连邀请。开启 DDNS 不改变这个约束。 |
| DDNS 入口链接 | 在发布设备复制 `conwu-ddns://…`，粘贴到接入设备的“加入网络 → 可达入口”申请加入；已有成员也可保留在连接设置的高级入口中。接入设备不需要 Cloudflare 令牌。首次入网仍需审批及校验码确认。 |

入口链接携带域名、网络和设备标识、设备槽位、公钥，没有私钥或入网权限。它在同一网络身份下随公网地址与端口变化继续使用；删除网络或重建设备身份后应重新复制。接入端按链接中的公钥核验 DNS 内容，不能信任 DNS 自报的替代公钥。老版本不识别此链接，需要更新到支持该格式的版本。

“域名自动发现”中自动按已批准成员公钥读取的方式仍保留。链接中的公开验签信息只用于发现；即使能查到公网地址，也需要通过原有配对审批和业务认证。

### Lucky 沿用原来的更新方式

Lucky 继续负责自己的打洞、动态域名和计划任务。ConWU 不接管 Lucky，不新增 webhook、本机文件导入或通用调度器。

1. Lucky 映射最终通向本机 ConWU 的接收端口（默认 `44680`），不是 Lucky 的管理端口或其他软件的接收端口。保持与 ConWU 选定协议兼容。
2. 在提供入口的设备上，把 Lucky 已更新的 HTTPS/TXT 链接填入 ConWU“提供网络入口”。多个应用共用订阅时，继续使用 `streamlink=公网IP:端口`，来源可加 `#streamlink` 限定标签；不用改成新的产品名前缀。
3. 点“测试地址”，确认实际解析出的 IP 和端口。该检查不代表已经打通，直连还会核验成员身份与双向通信。
4. 要由 ConWU 继续发布自己的稳定入口，在“DDNS”中启用功能并保存 Cloudflare 区域及令牌，再启动网络；不再单独勾选发布。可在更新状态中复制 DDNS 入口。已有 Lucky 稳定订阅时不必重复套一层 DDNS。
5. “提供网络入口”和“连接设置”共用订阅刷新周期。读取只更新运行时地址，原订阅链接与保存的设置保持不变。

HTTPS/TXT 故障时保留健康连接，失败来源的旧地址不会被反复续期为新的 DDNS 记录。签名 DDNS 的地址到期或收到签名空记录时，停止把它用于新连接；业务上仍健康的连接不会因此被拆除。普通订阅沿用用户设置的间隔；含签名 DDNS 链接的来源实际检查间隔最多 60 秒，以取得有效期较短的续期记录。DNS 缓存与网络故障仍可能造成发现延迟。

## 当前实现

- WebUI、托盘、安装界面和产品元数据使用 ConWU。Windows 新入口为 `ConWU.exe`，Linux 主命令为 `conwu`。
- 设置中的“DDNS”默认关闭；填写令牌后自动维护本机入口，未填写时只读取成员入口。
- 一个用户填写一个共用域名，各设备自动维护各自的 TXT 记录。用户不必手动申请每台设备的域名，也不需要把所有设备挤进同一条记录。
- TXT 内容含协议、IPv4 地址和端口、有效期，以及设备签名。记录不含成员私钥、配对秘密、设备名称或完整成员列表。
- 自动成员发现按当前已批准成员公钥验签；用户粘贴的 DDNS 入口按链接固定公钥验签。域名、网络、设备、协议、有效期都必须匹配。DNS 本身不提供入网资格或在线证明，业务仍须通过双向认证。
- 查询与更新独立于业务循环。查询失败保留尚未过期的已验证记录；地址变化不拆健康连接；离线设备使用有界重试和退避。
- Cloudflare API 只查询精确记录名，确认单条 TXT 及本设备所有权标记后更新。发现外来记录或重复记录就停止写入，不做整域替换或删除。
- API 令牌保存在本机受保护配置，不出现在普通状态、设置导出、邀请或日志。授权的本机面板仅在用户明确点击显示时读取一次，切页、恢复或保存后隐藏，不写入浏览器存储。Windows 使用 DPAPI 与目录 ACL；Linux 使用私有文件权限，本机 root 仍可读取。

## Cloudflare 配置

1. 确认 `space4sgsa.com` 的权威 DNS 在自己的 Cloudflare 账号下。共用域名填写 `conwu.space4sgsa.com`；不需要先建立一条同名 A 记录，也无需配置通配解析。
2. 在该域名概述页复制 **Zone ID（区域 ID）**，不是账号 ID。
3. 在个人资料的 API Tokens 中创建令牌，可使用“编辑区域 DNS”模板。权限选择该区域的 DNS 编辑，资源限定为 `space4sgsa.com` 这一个区域；不使用 Global API Key。
4. Cloudflare 的常规区域令牌权限通常覆盖整个区域，并非仅授权 `conwu` 子域名。软件自身只操作专用记录，但令牌泄露后不能靠这个软件限制来保护同区域的其他记录。只把令牌交给可信的自用设备；条件允许时可使用独立区域进一步隔离。
5. 在 ConWU 的“设置 → DDNS”启用功能，填写共用域名。需要发布的设备填写 Zone ID 和令牌，然后全局保存；未填令牌的设备只发现其他成员。
6. 各设备目前需要分别填写同一个共用域名。令牌不会随邀请、网络成员同步或设置导出分发。只读取其他设备入口的客户端无需 Zone ID 和令牌。
7. 先通过现有配对方式加入同一网络，再查看发布与读取状态。“Cloudflare 已确认发布”仅指 API 返回了匹配记录；对端还需等待 DNS 缓存更新并完成直连验证。

不要在聊天、命令参数、工单或截图中公开令牌。已保存时显示“已填写”；清除按钮需要确认并保存。恢复默认设置或前一组设置不会恢复旧令牌。

Linux 可通过 `conwu config show` 导出公开设置，编辑 `Network.Ddns` 后用 `conwu config apply 文件` 保存。先保持 `Publish=false`，从仅当前账号可读的文件安全传入令牌，再启用发布：

```sh
sudo conwu ddns token < /安全位置/cloudflare-token
sudo conwu ddns status
```

令牌文件由用户通过安全方式写入并自行管理权限；CLI 不将令牌作为命令行参数，也不回显。运行 `sudo conwu ddns clear-token` 会清除令牌、停止发布并保留域名发现。

## 地址和网络边界

记录名自动形如 `d-设备ID.n-网络ID.conwu.space4sgsa.com`，内容前缀为 `conwu-ddns-v1=`。这是软件内部的签名发现协议，与已有 HTTPS/TXT 订阅中的 `streamlink=` 标签不同；后者继续兼容，不需要修改现有 Lucky 上报。

TXT 是公开 DNS 数据。签名防止未授权的地址替换，不隐藏公网地址，也不能阻止 DNS 被屏蔽、删除或服务不可用。客户端运行期间拒绝比已见记录更旧的版本；重启后依靠签名有效期限制旧记录，尚无持久版本防回放机制。设备时钟须基本同步。

目前只发布正在运行的接收器对应的有效映射或已配置公网 IPv4 入口。TCP STUN 得到的临时、对端专用映射不能直接当作通用入口。DDNS 不能打开 NAT，也不能保证不同 NAT 之间一定打通；IPv6 尚不在本次实现范围。

检查间隔为 30–600 秒。地址变化提前安排更新；每条签名有效期为检查间隔的三倍，范围 180–1800 秒。Cloudflare API 使用 TTL 60 秒，但递归 DNS 的缓存、负缓存、网络错误及 API 限流仍可能延迟可见性。记录续期期间遇到故障，不会改走 UDP。

停用、退出或关闭软件后不自动删除 DNS 记录；记录会因签名过期而被其他设备拒绝。运行中没有公网接收入口时发布签名空记录，撤销旧地址提示。Cloudflare 控制台中已过期的记录可由用户自行清理。

本轮 DDNS 增强已经加入网络的设备发现，**没有替代 HTTPS 协调，没有增加协调数据库多副本接管，也没有实现无入口的自动入网**。已有入口模式仍只使用已有入口，不自动改为自主打洞；默认 FakeTCP＋HTTP 的数据语义保持不变。
