# ConWU 与 Cloudflare DDNS

当前候选为 1.0.6-rc.10。DDNS 负责地址发布和发现，业务仍使用用户选择的 FakeTCP＋HTTP 或 UDP；不自动切换协议，也不代替入网审批。

## 两种入口获取方式

在“设置 → 连接设置 → 连接策略与保留入口”选择：

- **自主打洞**：ConWU 自行探测、映射并取得可接收连接的入口，再更新自己的签名 DDNS 记录。已保存的第三方或手动入口不用于本机入口获取，也不会被清空。
- **只使用已有入口**：ConWU 不调用 STUN、自动映射或自主候选打洞。启用 DDNS 后，自动读取第三方维护的设备专属 TXT 记录；手动 IP:端口、域名:端口及 HTTPS/TXT 订阅仍保留作为备用。

无论本机采用哪种方式，都可发现其他已批准成员的入口。候选地址不等于在线证明。已经认证且健康的连接持续使用；DNS 地址刷新不主动拆除它。

DDNS 不能打开 NAT。自主模式只有取得实际可入站的映射后才发布；临时或对端专用的 TCP STUN 元组不会直接当作通用入口。

## 使用第三方直接更新共用域名

不用部署新的 HTTPS 更新服务，也不用逐个适配 Lucky 等工具。

1. 各设备使用同一个共用域名，例如 `conwu.space4sgsa.com`。在 ConWU 中选择“只使用已有入口”，启用 DDNS 并保存域名。
2. 创建或加入网络后，在“设置 → DDNS”复制**本设备**的第三方更新记录名。记录形如 `e-设备ID.n-网络ID.conwu.space4sgsa.com`，类型为 TXT。各设备有独立记录，不能共用同一个完整记录名。
3. 在 Lucky 或其他工具的动态域名/更新任务中，让该工具更新这条 TXT，内容为 `streamlink=公网IPv4:外部端口`。也接受带该标签的地址列表。端口转发最终必须通向本机 ConWU 接收端口，旧安装通常保留为 `44680`。
4. ConWU 按 DDNS 检查间隔自动读取地址和端口，不需要再填一次 Lucky 的 HTTPS 订阅。其他已批准成员也自动读取该设备的记录。
5. 首次加入时，可复制“第三方入口链接”，粘贴到另一设备的“加入网络 → 可达入口”。双方仍要核对校验码并批准。该链接是 TXT 来源，不包含入网授权。

读取第三方 TXT 不需要在 ConWU 中填写 Cloudflare Token；更新工具自己需要相应 DNS 写权限。ConWU 中已有的令牌继续受本机保护。如果也配置了 ConWU 发布，它会另外维护自己的签名记录，不覆盖第三方 TXT。

手动备用地址仍位于连接设置和端口设置的高级区域。也可继续沿用原有 Lucky HTTPS/TXT 订阅；多个应用共用订阅时使用 `streamlink=`，来源可加 `#streamlink`。

创建新网络或更换网络身份后，应重新复制本设备的记录名；原记录不属于新网络。普通软件升级保留身份及全部设置，不要求重配更新任务。

## 为什么有两类 TXT 记录

- `e-设备ID.n-网络ID.共用域名`：供第三方更新，内容为 `streamlink=IP:端口`。它只提供未认证的地址候选，不能批准成员、撤销成员或改变设备公钥。
- `d-设备ID.n-网络ID.共用域名`：由 ConWU 自己维护，内容前缀为 `conwu-ddns-v1=`，包含设备签名、网络身份、协议和有效期。第三方不得覆盖此记录。

普通 A/AAAA 记录只包含 IP，不包含变化的外部端口。固定外部端口可手动填写“域名:端口”；端口会变化时，应使用上述 TXT 或原 HTTPS 订阅。TXT 不经过 Cloudflare 网页代理。

同一个共用域名可以另有 Cloudflare Tunnel 的 HTTPS 入口，子域 TXT 与它用途不同。Tunnel 应转发真正的 HTTP/HTTPS 协调监听地址；服务器现有目标为 `http://127.0.0.1:42864`。不要把 FakeTCP 接收端口作为普通 HTTP 代理目标。

## Cloudflare 配置与凭据

ConWU 自行发布时，填写共用域名、Cloudflare Zone ID 和限定该 Zone 的 API Token。使用 API Token，不使用 Global API Key。填写并保存令牌后自动维护本机签名入口；未填令牌时只读。

Token 不进入普通状态、日志、配置导出、历史或浏览器存储。WebUI 保存后显示“已填写”，明确点击显示才临时读取；切页隐藏。清除需确认并保存。

Linux 使用相同功能及配置，可通过 `conwu config show` / `conwu config apply 文件` 管理设置。令牌从受保护文件经标准输入传入，不放在命令行：

```sh
sudo conwu ddns token < /安全位置/cloudflare-token
sudo conwu ddns status
```

`conwu ddns clear-token` 清除 ConWU 的令牌并保留发现配置，不会清除 Lucky 的 DNS 权限。

## 发现、优先级与失效

第三方 DDNS 候选优先于备用的手动来源；软件自己的签名 DDNS 提示放在这些已有入口之后。地址去重，网络入口识别与按成员连接不同时占用同一目标的外发工作线程。健康连接保持，不因优先候选变化而强制切换。

第三方记录按 30–600 秒的配置周期查询。查询失败只短暂保留候选，最多两个检查周期（60–1200 秒），不会通过失败刷新无限续期。过期候选停止用于新连接，已认证的健康连接继续工作。模式、域名、网络或成员身份变更会废弃旧查询结果。DNS 缓存和负缓存仍可能延迟地址变化。

签名记录继续校验成员公钥、网络、协议、有效期及进程内版本水位。签名不隐藏公网地址，也不能防止 DNS 服务不可用；重启后的长期版本防回放不在本次范围。设备时钟应同步。

本轮保留 HTTPS 协调。使用协调网络时，成员审批仍需协调端确认；没有把 DNS 变成权限数据库，也没有实现无任何可达入口的自动入网。

## 版本、升级与验证

Windows 保留 MSI UpgradeCode、安装目录、日用服务标识 `StreamLink-PersonalFeature`、受保护数据目录和自启项。Linux 保留 `/opt/streamlink`、`/var/lib/streamlink`、`streamlink.service` 及兼容命令。

现有端口、设置、网络身份和令牌须在更新前后核对。本轮模拟 DNS/Cloudflare API 与回环数据验证不代表真实 Cloudflare、NAT 或长时间大码率串流验收；三端安装与实际测试分别记录。证据位于 `artifacts/conwu-simplified-20261107/`，已构建但未部署的包不能据此视为三端已更新。
