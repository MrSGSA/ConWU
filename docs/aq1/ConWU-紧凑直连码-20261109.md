# 紧凑直连码

候选版本为 `1.1.0-preview.9`，Windows MSI 为 `1.1.8`。用户允许替代原直连邀请入口：界面只保留“配对码”和“直连码”，默认生成 16 个有效字符，四组显示；旧 SL6 仍可粘贴到同一个输入框，不另加第三种方式或完整邀请备份按钮。现有网络、入口配置、虚拟 IP 和启动设置不迁移、不重置。

## 载体和认证

直连码是可本地解码的定位信息，共 80 bit：版本及协议 4 bit、IPv4 32 bit、端口 16 bit、六位房间定位码 20 bit、CRC-8 8 bit。使用 Crockford Base32，不区分大小写，允许空白、连字符及常见易混字符。CRC 只检测输错，房间号只定位临时申请，不是密码或成员凭据。

批准前沿用承诺式 ECDH、设备身份证明和双方 SAS 校验，必须由主机人工批准。没有移除原认证材料、提前签发成员凭据或降低业务加密要求。配对房间仍为五分钟有效，保留单候选、限流、取消、拒绝和重新发码规则。新码复用已有六位本地房间；旧 SL6 的 capability-only 房间和签名校验未改变。

新动作是 `invite-compact` 与 `join-compact`；`UiPairingDto.Format` 增加可选载体说明。旧 `invite-direct`、`join-invitation` 和 SL6 读取接口保留。Linux `network invite <网络操作ID>` 默认生成紧凑码；`network pair-code <网络操作ID>` 生成六位码；`network join-code <直连码>` 在批准后自动接收设置，不需预建配置。

## 入口与设置

主机先准备接收器，解析已有来源或按原自主策略准备候选。验证可编码的 IPv4 后才替换配对会话；订阅解析失败保留旧会话及网络。生成的码只携带一个当前 IPv4，不证明它可从对端访问，不保证复杂 NAT 能连通，也不编码 IPv6。

从机先联系码中的入口，首次配对不登记或查询外部协调目录。批准后通过原加密通道取得网络身份、设置、原订阅来源及 PKARR 线索，保留主机已选的发现策略。协调网络不会因改用直连码而悄悄改成已有入口网络。已有入口不启动自主打洞；协议明确编码，不自动回退 UDP。PKARR 的公钥和其他较长资料在批准后传递，不塞入 16 位码，也未尝试新的六位公共目录方案。

界面保留两种方式的各自草稿；新码规范化后提交，旧 SL6 保留 Base64 大小写。重新编辑会清除上次输入错误。刷新后根据后台载体恢复显示，过期信息不能复制；没有配对地址时六位码仍禁用，直连码可独立申请。

## 验证范围

定向测试包含 34 项格式边界检查及全部 496 种单字符替换；隔离集成覆盖已有入口、不可用配对协调、自主直连、自主协调、自主 PKARR、显式 UDP 六种场景，并检查错误 SAS、取消、拒绝、重试、来源解析失败保留旧会话、批准后设置继承及认证包交付。

生产前端慢 API 测试为 97 项，实际 WebPanel 测试为 38 项，覆盖紧凑码输入、复制、过期、刷新、窄屏、旧 SL6 粘贴及真实后台拒绝输错后的控件恢复。原设置隔离、审批、后台响应和取消回归继续保留。

新增 PKARR 集成的首轮在隔离网关尚未发布公告时就断言重连，夹具对不存在记录直接抛异常。按原 PKARR 用例等待隔离公告发布后再检查发现链路，不修改生产入口校验、密码学流程或资源退出要求。

冻结后的 CandidateCore 增加 `compact-code` 和 `compact-integration` 两步，实际结果、源码提交和安装包哈希随候选保存。此单轮回归不代表长期公网、大码率或普通账户全部门禁已通过；不进行 Moonlight 实际串流。三端更新前保留完整受保护备份，升级后递归比较同语义设置。GitHub 正式发布和额外清理仍暂停。
