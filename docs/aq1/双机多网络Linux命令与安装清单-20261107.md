# 双机多网络 Linux 命令与安装改造清单

日期：2026-11-07。本文记录实现状态与验收边界；不授权清理或部署。

## 命令行为

- `network list` 输出本机配置 ID、显示名称、身份角色、实际网络 ID、连接状态和本机虚拟 IP；同时区分协调服务状态。配置 ID 是本机操作目标，实际网络 ID 是身份核对值，两者不能混用。
- `network status <配置ID>`、`network invite <配置ID>`、`network poll <配置ID>`、`network approve <配置ID> <校验码>`、`network reject <配置ID>`、`network leave <配置ID>`、`network close <配置ID>`、`network remove <配置ID>` 和重命名均携带明确目标。破坏性操作同时核对目标实际网络 ID；审批须核对设备身份和校验码。
- 创建与加入总是以空配置 ID 建立新关系，接收后台返回的配置 ID 并输出。迟到响应、查询与取消须继续绑定原操作 ID 和配置 ID；不能重试提交已受理操作。多个网络时省略目标必须报错，不从最近选择猜测。仅有一个网络时是否提供省略快捷方式，必须保持无歧义。
- `config show/apply` 应区分设备共享设置和单网设置，并明确保存影响的网络。草稿或局部补丁不覆盖其他网络；凭据不在导出中回显。共享配置事务和回滚由服务端保证。
- `ddns status` 分别展示查询、服务端确认发布内容和时间、实际直连状态；`coordinator status` 是设备级状态，不暗示协调设备已加入网络。默认 FakeTCP + HTTP，已有入口不启动自主打洞，不自动回退 UDP。
- Host 已提供显式配置 ID 的多网络命令；`network remove` 仍表示移除成员，`network remove-config` 删除本机网络配置。独立 Linux 网络命名空间中的实际 Host 已验证设备设置、两次创建、单网设置隔离及移除一网；实际 WAN、共享接收器和串流不属于该 CLI 检查范围。

## 安装、卸载和全新设置方案

- 现有安装器保留 `/var/lib/streamlink`，升级时若存在旧 Mesh/Pair，新版拒绝启动；不能把当前“设置已保留”文案当成兼容承诺。普通安装继续保留数据，检测到不兼容配置应停在清晰诊断，不自动清除。
- 此次用户允许全新设置；正式执行前增加独立显式的全新安装流程：先核验目录物理路径、服务 unit 归属、备份位置、当前服务启用和运行状态，以及独立 SSH、EasyTier 和其他管理连接；停止仅属于 ConWU 的服务后，将产品数据整体移动到同一文件系统的受保护、唯一时间戳备份目录，不对共享路径执行递归删除。备份包括设备配置、网络目录、协调数据及权限；新目录由程序建立。
- 备份、安装、启动、健康检查、恢复需要记录事务阶段；任何失败应保持原备份，能将原程序链接、服务定义、启用/运行状态和数据恢复至一致版本。若无法安全恢复，停止并明确给出恢复位置和失败原因，不以新空配置覆盖旧配置。若协调角色原来开启，新装验证时单独恢复或按用户选择重新配置，不自动加入网络。
- 不对 Cloudflare DNS、Tunnel、系统转发、其他服务、共享驱动或第三方虚拟网卡做清理。沿用已确认的 `/opt/streamlink` 及服务归属标记检查，并在清理前拒绝符号链接和路径逃逸；卸载默认继续保留数据。`--no-start` 不应意外启动服务。
- 安装测试必须在独立 mount/network namespace 和模拟 systemd 中覆盖旧配置拒绝、备份/恢复、停服失败、写盘失败、首次安装失败、符号链接与非本产品同名服务拒绝、保留协调角色及其他管理服务不受影响。实际 systemd、三端管理通道及真实网络另做验证，不把模拟结果当成实机证据。

## 多网络适配器清理边界

首版每条网络拥有独立 AdapterScope 和系统适配器；共享业务接收器按网络身份分流、分别认证，不是串流中继。停止或删除单网时只释放该配置 ID 拥有的适配器、地址及路由；卸载或全新安装应先查询并逐一记录各网络的资源所有权，等待工作线程退出，再核对目标资源确属 ConWU 后清理。不能仅查设备根配置就断言资源已释放，也不能按网卡名称前缀批量删除未知适配器或其他应用的路由。并发预算和最后引用释放须在独立实例测试及真实 Linux 网络验证；当前每网 /24 的冲突检测和地址协商尚需实现与验证。
