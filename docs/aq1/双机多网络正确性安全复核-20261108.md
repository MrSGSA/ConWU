# 双机多网络正确性与安全交叉复核

日期：2026-11-08。复核人为实现分工中的产品/交付负责人；范围为当时工作区的 Core、Service、Discovery、Web 控制边界和维护入口。工作区持续变化，本文不是冻结提交的安全证明，也不是 WAN 或串流验收。以下“已核验”限定于明确的代码路径或测试条件。

## 发现与处置

1. **跨网络重复身份及网段并发提交**：初查曾发现不同 Context 的审批可能各自读取旧快照。当前 `ProfileStore.Save` 已在工作区共用 `persistenceGate` 内执行 `ValidateNetworkProfile` 和写入，校验读取其他网络的受保护文件。新增 `PairWorkspaceConcurrentIdentity.cs` 通过屏障同时向两份真实网络配置签发同一 DeviceId：恰有一项成功，磁盘最终仅一份。原竞态结论撤回。此测试覆盖同身份冲突，不替代断电、恶意存储修改或大规模压力测试。
2. **停止与准入**：初查 Stop 的接受标志和 mutation 快照未共用锁。当前 Stop 与 Handle 的准入登记均使用 `admissionGate`。新增 `PairWorkspaceOperationTests.cs` 实际持有目标网络门，验证排队、同 ID 同请求复用、同 ID 不同请求拒绝、排队取消，以及停止后拒绝新操作并等待已受理操作。测试使用受控调度，不能证明所有线程时序均已覆盖。
3. **单网设置 WAL 的自启状态**：初查单网恢复使用 profile 自启而非真实 SCM/systemd 前值，且无条件调用 setter。当前单网和批量事务均记录实际启动状态及是否需要恢复，仅在需要时调用 setter。新增前台 Linux 测试，在空 systemd 目录的隔离 mount/user/network namespace 中恢复单网和批量 WAL，未注册服务也能启动并恢复设置。断电恢复、写盘故障和成员授权并发仍需结合核心事务回归核对。
4. **共享驱动**：初查 `WintunMaintenance.PrepareUpgrade` 在无其他网卡时可调用全局 `WintunDeleteDriver`。当前路径已移除该调用，保留共享驱动；维护按已保护配置的具体 scope 枚举。空 validation 实例 inspect/release 成功、Scopes 均为空，执行前后包含隐藏网卡的清单一致，证据 `artifacts/validation-maintenance-empty-20261108/`。该测试未创建或删除网卡，不能替代真实已有 scope 的升级验证。
5. **公共入口目标歧义**：初查多个关系共享入口时采用第一个匹配候选。当前带目标网络的 DDNS 链接/直连邀请和 rejoin proof 可定位网络；普通 IP:端口只在有唯一可接收关系时进入审批，多候选返回明确错误，准备阶段使用有界重试。普通地址本身不是网络身份。新持久身份恢复仅在已批准、同有效 DeviceId 证明且仍须新 ECDH/SAS 和人工审批时使用，不能自动复活撤销成员。代码边界已审阅，最终以集成负责人的实时配对、应答丢失、撤销及并发回归为准。
6. **共享接收器归属与回收**：初查出口策略仅单向检查、退役 route 未等待/释放 CTS、未认证帧可占满共享表，以及个别 socket 错误可能终止共享泵。当前按双向独占兼容性检查，非配对新路径先认证，按网络限制 route 数，追踪退役任务并释放 CTS，处理常见单包 socket 错误。有限的 loopback 恶意输入和三实例联调已由集成负责人执行；恶意本机流量、异常路径、跨平台关闭与长时间资源稳定性仍需冻结候选检查。
7. **旧数据保护**：生产 `ControlWorker(pairNetworks:true)` 在迁移写盘和 Linux 资源恢复之前读取旧 profile，若已有旧 Mesh/Pair 则拒绝启动。Linux Host 已采用该构造入口；验收 App 使用新版受限 UI API。无根 profile 时维护枚举不再凭临时默认对象虚构随机 scope。全新安装脚本保留旧数据及回退包，不静默迁移旧授权；正式安装仍需完整隔离 MSI 和实机回退验证。

## 身份与授权边界

冻结修订补充：集成复核发现旧 rc.10 MSI 的安装/回退仍会进入旧全局驱动清理。正式 fresh 事务已增加独立、随机 scope 的官方 Wintun 保护，并核验进程代次、接口 GUID 及实际 PnP 在场；私有目录 DACL、目录句柄和原子报告防止不可信停止/半读状态。未定 MSI 保留保护，确认结束后才精确回收。`Test-DriverGuard.ps1` 真实验证短父进程退出后仍持有、坏停止链接被忽略、跨进程合法停止、自有 PnP 释放和外部网卡不变（开发期证据 `artifacts/driver-guard-evidence-20261108-v5/`）。正式包的实际 MSI 新装和回退仍需独立执行；此处不宣称无保护条件的旧 MSI 已安全。

- `NodeIdentityProof` 对长期设备公钥和本次 ECDH commitment 使用域分离签名；验证通过后 DeviceId 从公钥导出，配对会话继续核验 commitment 和双方显示的 SAS。设备私钥仅在根设备受保护配置中持久保存，网络文件写入时剔除该私钥和 DDNS token。
- `MeshDirectory.Pairwise` 被纳入签名材料，成员目录限两台；后继目录不能改变 pairwise 模型。公共可达地址和未认证的 CNW1 网络标识只用于定位，实际网络包仍由各自网络密钥验证。
- 旧交付丢失后的同设备恢复不等同自动恢复成员授权：必须验证长期密钥对新 commitment 的证明、仍存在的已批准设备身份，并执行新的 SAS 和主机批准。对撤销、伪造 proof、迟到旧应答和重复提交应保留独立回归。

## 验证与尚未关闭的交付条件

- 独立复核新增的并发身份和 workspace 操作门控测试通过；前台 WAL 恢复测试通过；空 validation 实例维护检查通过。测试均为隔离或受控夹具。
- Linux 真实 Host/TUN/FakeTCP 三命名空间回归已通过两组双向包、共用入口、单网退出、直连邀请和单端重启恢复；证据 artifacts/pair-linux-mesh/conwu-pair-mesh-_o9444do。首次回归暴露共享接收器会话目录未创建，修复后通过。Windows 实际原生共享入口、高吞吐、长时间负载与恢复、真实安装回滚及三端应用串流仍须各自证据。物理 NAT、Moonlight 使用和 60 分钟高码率不能从 loopback 或 namespace 结果推断。
- 本轮尚未进行三端更新，也未修改 DNS、独立 SSH/EasyTier 或共享驱动。冻结后须重新运行受影响测试、复核安装脚本与包哈希，再由集成负责人综合判定。

## 回环 route 饱和补充复核

共享接收器当前在数据 route 达到每网络预算时拒绝新 route，不再用新的 carrier 元组淘汰健康业务 route；仅在过期清理后释放名额。配对 route 仍有单独替换策略。集成负责人新增的 `SharedReceiverRouteTests` 使用真实 receiver、签名帧和 UDP 回包验证第五个 carrier 被拒绝、原 carrier 标识不变。该结果只证明受控回环条件下的资源归属保护，不证明对公网攻击或长期高负载的抵抗能力；冻结后仍需重跑相关测试。

## 原生分类补充

Windows native 原本仅按 SLM4 起始标识分类，CNW1 外层封装会使业务帧误归入受限控制预算。集成负责人已修正为剥离唯一合法外层后再分类，并报告 parser 29780 个样例及实际 native 双网每网 1200 包突发通过；此处记录该项由集成负责人执行，不代替冻结包上的复跑和物理链路质量测试。

## 安装前追加复核

原冻结提交 `213c1202` 通过 v3 的完整核心，但生产更新前发现两个实际缺陷，不能忽略或沿用该包作为最终候选。

- 创建不同协议关系时的自动端口分配会改变接收端口，固定公网映射和订阅入口仍保留原值。已先加入失败复现，再改为写配置目录前拒绝冲突；保存的入口、已有网络和接收端口保持不变。出站源端口可继续分配，明确独立接收端口后另一协议可正常创建。共享监听兼容性判断在创建与保存时共用，并同时检查 UDP 两侧的自主策略和独占出口。
- 真实 MSI 验收暴露 COM 属性读取混入 Execute 的空输出，使产品代码变为数组并导致状态查询空引用。丢弃空输出并要求属性为单个非空字符串，再使用 System32 的原生 MSI 状态 API，预检和回退统一判断；无法确认候选状态时不继续卸载或覆盖旧数据，保留保护资源及错误证据。模拟异常态与真实已安装/未安装态分别验证。
- 实际官方 Wintun 的描述可被创建者设置为 `StreamLink Tunnel`。保护检查移除描述过滤，继续以已认证的精确接口 GUID、保护进程代次及 `SWD\WINTUN\{GUID}` 在场状态核对，避免把已就绪的保护网卡误判为失效。此修复后再次冻结，未启动的上一轮核心不记为通过。

这些修复后的冻结核心和包验证须另记，不把旧提交的结果改名为新提交通过。所有生产端仍需在最终验收后更新。
