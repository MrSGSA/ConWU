# ConWU 正式版落地记录

用户已确认 `previews/ConWU-正式版界面预览-20261110-v5.html`，授权开始构建、实现。既有未提交的双向 PKARR 与稳定性改动一并保留、验证；HTTPS 实验不继续，不把纯 TCP 预留项当成已实现的传输。

## 本次范围

- 将 v5 的布局、帮助弹窗、16 位直连码分组输入与复制／删除、设置浮窗内部滚动接到真实后台，不使用预览的模拟状态或网络操作。
- 创建、加入只展示直连码。通过真实主机批准后继承入口订阅、发现方式及信任参数，每网独立设置；旧网络和适用设置保留。
- 自主打洞默认为 PKARR；私有协调为高级发现方式；已有入口不启动自主打洞、PKARR 或备用协调。
- 自选协调只帮助发现和更新入口。双机网络的创建、直接配对、批准、本机退出／删除不强依赖协调服务器在线。
- 删除独立协调页面；本机提供能力与网络选择发现服务器相互独立，保留原服务器 HTTPS／反代和受保护管理入口。
- PKARR 网关设置真正持久化、随批准交付，并用于发布与查询；更换网关不改变签名身份、序列检查或已验证业务连接。
- 现有 UDP 网络不静默改协议。新网络默认 FakeTCP＋HTTP；纯 TCP 显示为后续预留，不映射到 UDP。

## 实施和验证

1. 审计并修正真实配对／管理的服务器依赖及设置继承。
2. 实现正式 WebUI、默认列表、输入与设置状态、协调宿主的默认提供与兼容迁移。
3. 定向验证配置独立、协调离线管理、三种发现策略、网关切换、取消及审批；浏览器验证真实状态与慢 API。
4. 冻结源码后构建 Windows／Linux 安装包，执行适合此次变化的完整回归和安装升级检查。
5. 验证通过再替换笔记本、台式和 Linux 服务。保留回退与设置；实际大码率串流由用户验收。此次不恢复已停止的 HTTPS 公网实验。

## 源码冻结前验证

- 正式 WebPanel／隔离服务的浏览器验证通过 42 项；真实默认 STUN、自选发现网关、模式切换与独立设置均接入后台。
- 正式前端慢 API 验证通过 57 项，覆盖多网络配置隔离、旧共享配置单网分离、并发引用与删除、分组复制／粘贴／删除、取消观察、慢保存、只读从机和小屏滚动。
- 紧凑邀请集成通过 182 项，覆盖已有入口、自主手动、协调在线／离线、PKARR、旧 UDP、SAS 拒绝与批准及真实加密内层报文回环。
- 新发现／协调测试通过 21 项：真实证书、动态网关、兼容反代、自动提供能力，以及超过 32 次创建移除后仍可新建、重启清理与未创建草稿保留。
- 修复了协调离线时，已批准的直连引导入口被自主协调策略过滤的问题。入口与网络身份绑定，传输仍需认证，不改变所选发现方式。
- 移除网络不再无限积累隐藏专属配置；显式 CLI 模板和未使用草稿保留。草稿设置与虚拟 IP 在浏览器刷新后可继续使用。

源码冻结候选：`1.1.0-rc.1`，MSI `1.1.9`。后续构建、完整回归、安装升级与三端替换结果写入 `artifacts/release-implementation-20261110` 与对应本地发布目录；以这些结果为准，不能以本记录宣称测试已经完成。

## 升级核对补充

实际隔离 MSI 升级检查发现，自动提供协调能力更新了设备的真实监听配置，但设置 DTO 仍可能返回旧连接策略中保存的监听副本。已改为以设备实际监听为准，避免保存设备名或日志时关闭协调能力；新增了升级后设置显示及再次保存的定向验证。

公共 PKARR 双向验证通过：两个默认网关均接受主从发布，查询可取得更新后的入口，并返回对应入口版本的加密确认。仅使用临时身份及文档保留地址，不涉及已安装设备的身份、真实 NAT 或串流。

初次冻结的安装包不作为最终交付，最终以包含上述修复的后续冻结、构建和升级证据为准。


完整回归的 74 组检查收齐后，更新了两条与新规则冲突的旧测试：独占设置在最后一条引用移除后自动回收；刷新页面保留未创建网络的已保存草稿。其余 72 组通过，失败不作为最终通过证据。修正后两组分别通过 80 项后台检查与 42 项真实 WebPanel 检查。

协调初始化使用与设备设置写入相同的串行门，避免两者提交旧快照相互覆盖。设置回滚及启动恢复只在独立角色迁移版本确实推进时保留新监听；正常用户监听改动仍按事务回滚。新增两项定向检查。最终重新冻结、打包和回归，以新的全套结果为准。
