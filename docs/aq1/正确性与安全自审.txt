AQ-1 自审 A：正确性 / 安全
审查者：本轮同一执行者，采用独立检查视角；未声称外部审计或独立代理审计。

已检查并实施
1. 服务保留管理员控制管道与授权 SID 的 UI 管道分离。新增浏览器请求只调用受限 UI DTO；不代理全配置、日志目录、DPAPI 内容或原始邀请。
2. UI patch 原子性、操作 ID、队列内再次授权检查保留；网络设置另有原值摘要并在控制门内比较，防止旧草稿覆盖新设置。网络替换与成员撤销绑定当前网络 ID。
3. 本机 Web 宿主仅绑定 127.0.0.1 随机端口；核对 Host、Origin、Fetch-Site。一次性 60 秒启动票据仅经父子匿名管道送到浏览器片段，随后立即清除片段。HttpOnly / SameSite 会话 30 分钟过期；CSRF、请求体大小、并发、速率、重放和静态文件白名单均有边界。
4. Web 配对直接复用公钥承诺、ECDH、校验码和 AES-GCM；服务内保存密钥。批准绑定当前候选与校验码；批准回包丢失不再签发另一成员、不自动撤销已发凭据。浏览器使用 textContent，不将成员名、日志或错误作为 HTML。
5. 自研配置先保护备份再迁移，保持停止并显示提示；服务工厂仅允许官方 Wintun。默认包禁止研究 DLL/SYS 与旧组网二进制，CMake 研究测试默认关闭。
6. 原 FakeTCP HTTP/SEQ、认证、重放、捕获 owner 与获胜 UDP socket 所有权未重写。新增观测复用聚合计数；关闭失败仍保留 owner。
7. 测速不改变 manual-v2 线格式、20 秒发送、1 秒收尾及 90 秒冷却。新增重复/乱序计数，并拒绝发送报告范围外的序号；API 接受不当物理送达。
8. 安装只选个人实例；保留受保护安装目录、清单逐文件验证、来源未签名声明及失败回退。无旧服务或全局驱动清理。

自审中已修问题
- 取消默认自研驱动后仍有运行时类型引用：已从 MeshRunner 移除。
- Web cookie 原名称未区分随机端口：已按端口区分，避免并存隔离面板互相覆盖。
- 已停止或新开始测速时可能保留上次质量对象：已清空，防止把旧结果当当前连接。
- 原测速只比较总数量，未检查收到的最大序号是否超出发送报告：已收紧一致性检查。
- 原生 HTTP 控制队列用 GetTickCount64 的离散系统 tick 计算 32ms 间隔，存在缩短一个 tick 的风险；改用 steady_clock 截止时间并复核，250ms 过期与原控制预算不变。加入无密钥的实际注入间隔日志；接收端调度可把缓冲报文连续取出，不能单凭接收间隔推断发送违约。
- 核心首轮四个测试仍假设非个人版默认配置；改为显式构造拒绝／legacy／关闭状态，另验证个人版默认及显式拒绝持久化。首轮失败原样保留。

验证与边界
HTTP/服务负例、现有控制并发/权限、个人配置迁移与浏览器检查已有定向记录；最终结果以固定候选证据目录为准。
历史 linked-token 子进程在本宿主返回 Win32 267，保留其原始阻塞记录。personal.3 改用临时 InteractiveToken / LUA 任务启动真实普通权限客户端，任务结束即删除；证据记录 admin=false。此方法补充同一日常账户的真实普通权限验证，不代表跨账户 UAC 或无人登录冷启动。
公网 TCP SYN 观察能力未启用。历史条件预测 2000ms 新鲜性失败保留，未放宽期限，且个人默认不启用该能力。
真实官方 Wintun 的接口表记录与设备存在性已分开：IPHelper 行可以在 SetupAPI 的实际设备消失后继续存在。新增按 NetCfgInstanceId 精确识别的 DIGCF_PRESENT 观测，并在同进程同身份执行五轮；旧查询结果不改写。I/O、真实 PnP、重开和原 3 秒性能目标分别报告，不把延迟超标改成通过。

personal.3 第二轮正确性 / 安全检查（与产品检查分开）
- 原日用服务 UI 请求曾因 FileNotFoundException 断开，但异常未给出缺失文件名，不能声称已查明某一 DLL 缺失。取消服务内的客户端模拟身份路径：内核报告本地管道客户端 PID，服务在自身身份下查询该进程令牌的 SID。保留 SID-only ACL、拒绝远程管道客户、服务端再次核对 SID、客户端核对 SCM 服务 PID。句柄在 finally 释放，身份失败不返回受限状态。
- MSI 使用每次尝试新生成的 GUID 作为恢复事务标识。恢复记录仅 SYSTEM / 管理员可写；记录完整且允许开始变更后才恢复服务。服务授权记录独立恢复，不覆盖第三方新改授权。手工安装与 MSI 管理互斥，避免后续从旧 ZIP 重写 MSI 服务路径。
- 安装目录必须处于 ProgramFiles 的受管位置，既有祖先拒绝 reparse。只匹配精确 UI/Web 可执行文件名及受管路径，先请求退出，再有界等待；不终止服务或原生网络 worker。旧主版本为 0 且没有旧服务时拒绝强退可能承载网络的前台。卸载仅关闭本次 app 的界面；验证 MSI 只能作用于其 GUID 实例。
- 禁用 Windows Restart Manager 自动关闭应用，防止其扩大关闭范围。服务由 MSI 的 Stop/Install/StartServices 管理；失败后恢复原 ImagePath、启动类型、运行状态、失败动作、描述及授权。提交前检查服务真实 ready；不以 SCM Running 代替控制面就绪。
- 应用版本资源随 personal 序号递增，修复明确重新安装文件，防止 MSI 跳过同 FileVersion 的 DLL。默认数据协议、密钥格式、驱动边界和业务路径未改变。
- 新错误分阶段、分类返回并保持敏感细节脱敏。已增加真实 HTTP 用例，验证后台停止与授权提示可区分、未知异常不泄露内部消息、恢复后会话仍可使用。

复核依据为最终交付 verification 下的冻结核心、真实 MSI 生命周期和普通权限面板证据。开发验证夹具均标记 sourceDirty / DevelopmentFixtureOnly，不当作冻结交付源码。
