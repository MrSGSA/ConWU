# 1.0.4：已有入口独立连接与路径准备隔离

基线：1.0.3 / `239ac5f2`。本轮先处理反复直连失败，并按用户后续要求一并修复删除网络的超时路径。

## 日志定位

两端对同一 `55ae165a…` 尝试均到期，原生外层握手未认证；一端 bridge 探测 40 次，另一端零次。同期笔记本到主机自主发现的入口 `:8351` 已完成原生外层握手并收包，但主机较早开始 SO 后预留了受管路由，丢弃已有入口的 MeshLink 握手；客户端也会因该预留关闭原传输。两端机会窗起点不同，使可达入口被准备中的候选抢占，最终反复等待机会窗结束。

已提供的订阅入口 `:8463` 当时没有完成双向认证；`:8351` 来源于自主发现。不能把后者的成功写成前者可用，也不能保证任意 NAT 的 SO 都成功。

## 用户最新决定

已有入口模式只使用填写、订阅解析或对端签名公告的用户入口。不得自动回退到自主打洞，不调用 STUN、UPnP/NAT-PMP/PCP 映射或候选工厂。失败提示检查地址、订阅、协议和映射，用户自行选择“自选服务器”恢复自主打洞。

保留 HTTPS 协调配对、签名成员表、已有入口订阅定时刷新和原传输协议。无服务器直连邀请同样只使用已有入口。多地址在各自完整 15 秒准备/验证窗口后轮换；仅重试允许的入口，不混入自主发现端点。

新签名公告 `ExistingEntryOnly` 告知其他成员不要对此设备发起自主打洞；本机也不发布打洞能力。对端收到策略改变会取消并等待旧候选资源退出。切换两类模式需要确认后重建当前连接；仅编辑入口/订阅继续热更新，不重新创建网卡。

## 路由保护

候选准备预留与实际受管数据路由分开。仅通过本轮认证及包长验证的候选才能转交数据路由；此前已有入口可以继续握手。已有入口先验证成功时，取消并回收未完成的自主候选。实际注册边界再次检查已有路径健康，拒绝迟到候选，拒绝时资源仍属调用方。选定受管路径后的认证、共同提名、协议选择及单四元组所有权保护保留。

## 定向回归

新用例先在未改路由的 1.0.3 源码复现超时，再验证修复。检查真实回环 UDP 上的 MeshLink 认证、完整 MTU 业务、候选清理、迟到注册、已签名策略传播、对端不分配候选、策略切换取消、既有入口失败提示、订阅修正恢复、零映射/零候选工厂调用，以及两类设置的重建/热更新分类。

旧“已有入口失败后自主回退”验收按用户决定移除。多地址检查改为等待完整的 15 秒每入口验证窗，不放宽身份或包长断言。默认与显式编译发布版本设为 1.0.4，MSI 1.0.24。冻结后的核心、安装包与实际设备结果在忽略的 `artifacts/direct-expiry-20261103/` 记录。

正确性/安全自审：核对签名策略、完整身份与包长准入、注册边界赢家保护、拒绝资源归属、取消/释放证明、严格模式零自主 I/O。产品/质量自审：核对模式含义、保存确认、持久错误提示、订阅热更新、旧公告互操作与失败诚实口径。实机尚未覆盖的部分不能由回环通过代替，正式长时与八机门槛不因此改写。

## 删除网络超时

实际服务级回归在未改代码上复现：可选的配对房间 Close 抛出传输超时的 OperationCanceledException，原先只容忍 IOException，导致删除/退出还没执行就返回“对端或网络请求超时”。房间清理改为独立三秒上限；未获确认时结束本机等待，远端房间按 TTL 到期，继续执行本机操作。调用方主动取消仍传播，不伪装为成功。

主机有其他成员时，签名成员撤销仍是必需操作，不因可选房间关闭失败而跳过。相同 revision/signature 的目录 PUT 在当前协调端幂等；临时连接错误、503/网关错误或内部八秒超时仅重试一次，复用同一签名表。持续超时明确说明 HTTPS 协调确认未完成、网络保留；403 等拒绝不重试，也不删除凭据。资源退出阶段显示实际进度，继续等待真实 owner 释放。

新增实际受限服务与真实 TLS 故障端点回归：房间立即超时/不响应、用户取消、撤销已应用后返回503、撤销确认超时后复用原表、403 保留完整网络。首份 `86f05f34` 候选只包含直连修复，核心执行在新增本项后主动中止并保留记录；最终候选重新冻结并使用新目录完成必要完整核心验证，不合并为一轮全绿。
