# 安装界面更新（2026-10-31）

用户要求美化安装界面，并明确保留开源许可。此前“先不测试”的要求继续生效。本次只修改安装 UI、构建接入和图形生成，不修改网络实现；不构成新的正式候选验收。

## 实现

- 使用原生 MSI 控件替换默认 `WixUI_Minimal`，统一安装/更新、维护、卸载确认、准备、进度、完成、失败和取消页面。深绿品牌侧栏沿用现有 S 标志，右侧集中显示安装位置、操作说明和按钮。
- 首页保留默认未勾选的开源许可确认项；确认后才启用安装按钮。“查看许可”打开独立的可滚动窗口，包含 StreamLink MIT 与随包第三方许可原文。没有收费、激活或许可密钥机制。
- 进度页订阅 MSI 的真实执行步骤和进度事件；完成页按安装状态显示启动 WebUI 选项。没有固定倒计时或模拟安装进度。
- `scripts/Build-Msi.ps1` 已接入 `installer/StreamLinkUI.wxs`、`installer/Sidebar.wxi` 和 `scripts/Build-InstallerArtwork.ps1`。显示版本来自包内 manifest，构建元数据增加三份 UI 来源文件的 SHA256。
- 装饰位图由现有标志和几何图形生成，文字保留为原生控件；没有增加 WebView 或安装时需要的新运行时。

## 第一轮：正确性与安全静态检查

- WiX 6.0.2 编译完成，退出码 0，最终编译日志无错误或警告。首次编译发现的 `ProgressText` 写法已改为 `Message` 属性。
- 以 `WindowsInstaller.Installer.OpenDatabase(path, 0)` 只读打开生成的 MSI；未调用安装 API。检查了 UI 序列、按钮事件、条件、进度订阅和许可文本。
- 欢迎/维护/卸载确认位于磁盘空间计算之后、执行安装动作之前；空间计算等待条件为 `CostingComplete = 1`，空间不足不继续安装。许可未确认时按钮禁用，结束欢迎页的事件也要求确认。
- 修复保留原来的 `ReinstallMode=ecmus` 与 `Reinstall=All`；卸载先设置模式和移除事件，再退出确认页。完成按钮先按条件启动应用，再关闭窗口；维护、卸载和管理映像操作不会触发该启动动作。
- 生成 MSI 中许可文本与输入 RTF 一致，未在嵌入时截断；随包 `app/licenses` 和 `app/sources` 继续保留。
- 与真实 HEAD `e05263715c894f0bf390f1b9e50f0032403455fe` 比较，`CustomAction`、`InstallExecuteSequence`、`MajorUpgrade` 和标准安装目录定义未变。原有关闭客户端、服务更新、授权配置、回滚和就绪检查继续使用现有实现。

## 第二轮：产品与质量静态检查

- 分别查看首页、进度、完成和维护页的静态设计预览；当前示意尺寸下未发现文字截断、控件重叠或主要入口缺失。
- 安装位置、配置保留、更新关闭当前窗口，以及卸载中断连接均有直接说明。许可原文放在独立窗口，首页保留简短确认和查看入口。
- 预览按同一份 UI XML 的坐标与字体生成，并明确标注“设计预览”。示意图中的已勾选状态和进度条不是实际初始状态或安装记录，也不是 MSI 运行截图；按钮外观仍由 Windows 原生主题决定。
- 尚未确认实际 DPI 缩放、键盘焦点、读屏、高对比度、真实安装/升级/修复/卸载与异常回滚的交互。这些属于后续运行验证，不能由本次编译或预览替代。
