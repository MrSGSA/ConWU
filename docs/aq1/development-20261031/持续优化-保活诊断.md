# 持续优化：保活分段观测

接续 [恢复与隔离](持续优化-恢复与隔离.md)。本次针对原压力失败的解释能力修改代码；仍遵守“先不测试”，没有运行应用、压力程序、浏览器、安装、驱动或远端操作。

## 为什么补充这些观测

只读复核 `artifacts/formal-frozen/soak-600s.json`：约 601 秒记录判定为 Fail，出现 `ReturnPathTimedOut`。相应样本的有效接收年龄只有 1 / 21 毫秒，但往返年龄已达 13221 / 12091 毫秒。这说明当时仍收到业务，而同路径的往返证明过期；不足以区分维护未调度、本机拒绝、原生出口排队、对端拒绝或实际网络丢失。

该旧用例使用真实 MeshRouter、MeshLink/AES-GCM 与 native HTTP 事件循环，但网卡为内存实现，raw-wire 由 loopback 替代；不能据此判定 Wintun、WAN 或物理 QoS 是根因。本次没有产生新的运行证据。

## 实现与读取方法

`PeerLiveness.Keepalive` 自动随现有 UI 状态及诊断导出携带当前路径的只读快照。受管路径的 `MeshRouter.Paths()` 也提供每条资源的 `Keepalive`，便于后续观察备用路径。没有新增首页面板、网络探测或逐包日志。

| 字段 | 含义与边界 |
| --- | --- |
| `PathId` | 统计所属的实际路径。受管资源从备用转主或回退仍使用同一统计；不同 PathId 的累计值不能直接相减。旧入口选定新 Active 时重置。 |
| `Attempts` / `LastAttemptAgeMs` | 普通保活到达发送分支的次数及最近一次的单调时间年龄。结合现有 Router 维护调度统计判断本机是否仍在尝试。 |
| `SessionUnavailable` | 会话尚无可用对端 epoch，未能生成普通保活帧；不等于物理断网。 |
| `LocalAccepted` / `LastAcceptedAgeMs` | 本地队列或 socket 接受次数和最近年龄；不证明 native 注入、物理发出或对端收到。 |
| `LocalRejected` | 本地发送路径返回拒绝，含 Router 预算拒绝。传输未就绪、队列拒绝和预算拒绝不能全部解释为网络丢包。 |
| `RouterBudgetRejected` | 受管路径中 `LocalRejected` 的已知预算拒绝子集。旧入口在此层无法拆分，返回 null；原生路径注入阶段的 wire 预算拒绝不计入此值。 |
| `FreshReplies` / `LateReplies` | 认证成功、同资源、匹配仍在等待集合中的普通保活回复，分别在原 12 秒期限内/外。过期回复不刷新健康。 |
| `Pending` / `PendingEvicted` | 仍等待的普通保活，以及因原有 8 项上限被移除的未完成保活。被移除后才来的回复不能再归属；移除计数不是物理丢包计数。 |
| `LastFreshReplyAgeMs` | 最近一次匹配且及时的普通保活回复年龄。没有该类回复时为 null；提名成功可以已有往返证明，因此它与 `RoundTripAgeMs` 不必相同。 |

普通保活、恢复观测和质量诊断分开：共享 pending 表的诊断条目显式标记为非保活；普通保活即使恰好为加载诊断提供 RTT，也仍只按自己的发送来源计数。恢复组件的独立 nonce 集和处理方式保持。

所有计数读写在既有 Router 锁内；每条资源只新增固定数量的整数，不保存数据包、nonce、端点或历史列表。没有增加额外线程、定时器、探测、锁或逐业务包计数。年龄从本地接受/处理时刻计算，包含本机排队影响，不代表单向链路时延。
