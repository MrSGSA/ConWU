# 持续优化：WebUI 状态容量与操作结果

接续 [保活诊断](持续优化-保活诊断.md)。本次仍只修改源码、静态审查和编译/语法解析，没有运行软件、测试、浏览器、安装或驱动。

## 源码中确认的问题

本地控制协议一直以默认 `System.Text.Json` 编码并限制为 65536 字节。WebUI 原来只截取最近 40 条日志，没有按字节控制；长错误行、中文转义与多成员出口诊断叠加后，超过上限的回复会在 `ServiceProtocol.Write` 抛错。`ServeUi` 原先没有区分处理与写回复阶段，随后可能返回“内部错误，请修复安装”；命令已经执行时，这种结果会使用户误以为操作失败。

这属于静态调用链确认的边界缺口，没有执行超长日志复现；不能据此将用户此前的实际串流卡死归因为界面消息过大。

## 已实现行为

- UI 回复使用同一默认序列化器检查完整消息大小。协议读写仍为原 64 KiB 上限，仅提取共用常量，没有放宽输入边界。
- 正常大小的状态继续携带已有诊断。超限时优先减少较早日志，保留最近部分；仍超限才依次省略出口分项、传输阶段统计、上次测速明细、设备分段统计。每次省略后重新计算完整回复大小，包括说明本身。
- 裁剪只操作不可变展示副本，不修改 Runner 原始证据、日志队列、路径质量决策或实际连接。阶段统计、保活与丢弃统计被省略时使用 null/空分项并附说明，不能当成零损失或“没有出口”的完整证据。
- 非空状态始终保留完整成员列表、各成员连接判定、往返/接收年龄、阶段、所有设置、revision、配对身份及操作标识。不会通过删掉某些成员拼出一个看似完整的网络。
- 如果只剩必要状态仍超限，单独返回原操作结果和 `StatusNotice`，明确状态暂不可显示。`Ok`、操作 ID、完成/可取消标志和真实错误性质保持；页面将旧连接状态标为未知并继续刷新，不因此自动重发命令。托盘显示“状态信息过大”。
- 普通状态轮询没有独立命令结果时，也会从该份快照带出当前操作；页面仍在原操作栏显示任务进度，但不会因此恢复旧的在线状态或写操作按钮。
- “诊断与日志”中只在实际省略时显示说明，导出的 JSON 也包含该说明；连接首页不增加面板。后续完整状态恢复时说明自动消失。
- 展示用进度、网卡原因、质量摘要与操作错误先脱敏再限长；UTF-16 截断不拆开代理项。设置、证书、revision、配对码和校验信息不截断。去掉了每个进度详情重复执行两次脱敏的处理。
- 处理请求和写回复分别记录阶段；写回复失败后不再向可能已有部分帧的同一流追加一条“操作失败”回复。

## 范围与限制

此调整作用于正式 WebUI/托盘使用的受限 UI 管道。管理员旧 `ControlReply` 管道没有引入同样的裁剪；其完整配置与邀请值不能为了塞进消息而静默截断。两者的帧上限均未改变。

每次 UI 请求的容量处理在服务状态锁外进行，不新增数据泵锁、网络探测或后台工作者。正常回复会增加一次序列化检查；超限时最多对原有 40 条日志做六次减半，再处理固定的诊断类别。这里仅说明算法边界，未测量 CPU、分配量或响应延迟。

不能保证被省略的日志已写入文件：原日志级别可以关闭文件输出，或只记录错误。原队列和文件策略未改变，因此页面只说明“本次状态省略”，不承诺存在完整文件副本。
