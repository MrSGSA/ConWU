# 持续优化：第一轮正确性与安全静态审查

由同一执行者按所有权、并发、失败传播和接口边界单独审查；不是外部独立审计，未运行测试。

- `MeshRouter.DisposeAsync` 通过原子状态门只启动一次回收；完成源在取消回调执行前已存在，重复调用返回相同任务，成功和异常均不会在重复调用时丢失。
- 数据泵异常与资源释放异常分开：业务/诊断任务即使失败也必须全部等待结束；路径释放失败保留异常和实际 owner，不能被完成任务集合移除，也不能重新占用对应成员或 TCP 四元组。
- 清理顺序仍为取消/停止、等待生产与接收任务、释放会话密钥和本地 socket、关闭网卡、释放取消源。单独清理失败会被收集，不会跳过其余已经可以安全清理的资源；未完成的任务仍会等待，没有添加提前释放或强制超时。
- `RegisterPath` 与成员更新继续使用 Router 状态锁。关闭后拒绝增加新资源；候选时序参数无效时，不再先分配关联取消源。
- 传输关闭失败的路径由 Router 保留；Runner 继续使用现有 `CleanupFailed`/`MeshShutdownException` 隔离，而不是把等待结束当成资源已释放。相同成员隔离不会主动断开其它已有健康路径。
- WebUI 的读取代次只决定是否采纳旧响应；没有重试写请求、重发命令或变更服务端授权。服务端 SID、CSRF、操作幂等、revision 和配对校验继续使用原实现；忽略旧 401 不会绕过下一次请求的服务端检查。
- 状态名称和设备名称仍通过 `textContent` 展示；进度详情继续经 `PublicProgress` 脱敏和长度限制。移除按钮只调整位置，权限和确认不变。
- FakeTCP＋HTTP 数据报语义、MeshLink 认证/重放域、12 秒同路径证明、总出口预算、Wintun/WinDivert 与旧冻结包没有被本次改动替换。

剩余风险：并发关闭、释放异常注入与浏览器响应乱序尚未实测；官方 Wintun 调用自身的阻塞时长没有因此获得硬上限。编译仅证明当前源码可生成，不证明资源生命周期在所有时序下正确。

## 追加审查：启动交接、入口与成员目录

- `pendingAdapter` 只有在 Router 构造成功后才清空；工厂迟到返回和交接前异常均保留到统一关闭。Router 准备阶段失败只释放自己的资源，不与 Runner 重复关闭网卡。
- `retiringMapping` 与释放任务一同保留；失败后主循环不再创建同类入口，也不循环观察/重复释放。结束阶段不忽略释放任务的取消，真实 owner 进入 `unprovenOwners`。正常网关远端删除未确认仍沿用映射组件原有处理。
- 本机成员变更、协调快照安装与 Router 创建使用同一锁。版本检查与替换不再分开；关闭标志在 Router 回收前设置，后来的配置变更不访问已经关闭的 Router。
- `remember`、`report` 和 `log` 回调继续在 Runner 目录锁外执行，避免与控制服务的配置锁形成相反顺序；原签名、成员身份、自身撤销和最低 revision 检查保留。
- 公告的空项和 JSON 解码失败只影响当前公告；没有将无效公告转成可用端点，没有降低签名/AEAD/版本/到期校验。非预期代码异常仍由外层处理，不使用 catch-all 隐藏。
- 单次 Run 门只限制同一对象的重复执行；服务恢复已有的创建新对象方式不变。

以上为静态调用链和编译检查。真实并发交错、清理异常注入和旧快照竞态尚未执行；待验证项已单列。

## 追加审查：保活分段观测

- 新统计全部在 Router 的既有 `gate` 内读写；没有新锁顺序、I/O 或用户回调。快照只携带计数、路径标识及单调年龄，不输出 nonce、密钥或数据包。
- 回复仍先通过 MeshLink 的 AEAD、epoch 和重放校验，再在收到它的同一路径 pending 表中匹配。仅将匹配且未过期的原分支拆开计数，没有将入站业务、未知 nonce 或过期回复当成往返证明。
- 共享 pending 表新增明确的 `Keepalive` 来源标记。baseline/loaded 专用探测为 false，普通维护为 true；不能根据诊断 leg 是否为 -1 猜测来源。恢复组件独立的 nonce 处理继续执行，不作为未知维护回复拒绝。
- pending 容量仍为 8，移除顺序仍为最早发送项；只对被移除的普通保活增加该统计。受管资源携带自己的计数，旧入口选定新 Active 后连同原 pending 表一起重置。
- `LocalAccepted` 只来自原发送函数返回 true；预算拒绝为本地拒绝子集，旧入口无法分解时返回 null。原生 wire 阶段的拒绝不会伪装为此处已知预算拒绝。
- 现有 1.5 秒保活间隔、12 秒健康期限、出口预算、重放窗口及 FakeTCP＋HTTP 数据语义均保持。没有新运行验证，具体计数与并发情形列入待执行回归。

## 追加审查：UI 状态容量与结果边界

- 容量判断与实际写管道使用同一个默认 JSON 序列化方式、同一个 65536 字节常量；请求读取仍先校验长度，没有扩大允许的输入或更改 SID/CSRF/命令授权。
- `FitUiReply` 只替换展示记录及数组引用，不修改原状态/日志数组、操作账本或路径决策。串行裁剪在拿到快照后执行，不在 `sync`、Router 锁或操作锁内增加序列化工作。
- 非空状态不丢弃成员、不截断设置或版本前置条件；必要状态仍过大时返回无状态和明确说明，保留原 `Ok`、错误结果、操作 ID、完成和可取消标志。显示错误的长度限制不改变后台操作完成记录。
- 正确性审查后修正了省略说明：只有原来确实有出口分项/设备分段计数，才声明该类内容被省略。说明自身也纳入容量计算。
- 展示字符串先做凭据/邀请脱敏，再截断；代理对边界被保留。原先直接投影的操作错误和质量错误也经过相同脱敏路径；设置与配对字段继续走既有受限类型。
- 写回复阶段单独标记，避免部分帧写入失败后追加另一完整帧，也避免已执行命令仅因回复大小被改成 false。网络中断仍可能使客户端无法取得结果；界面按未知结果处理，不自动重发。
- JS 对缺少状态的结果取消旧在线判定；保存设置完成后的渲染也尊重离线状态，不重新将旧快照标成最新。以上均为静态审查，字节边界、浏览器行为和并发时序未运行验证。
- 后续静态审查补齐无状态轮询：优先返回本次命令的操作结果；没有本次命令时才使用该份状态的当前操作。两者不按相同 ID 假定合并。页面只更新原操作文字，保持连接未知和写操作禁用。
