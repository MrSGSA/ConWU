# 持续优化：第二轮产品与质量静态审查

第一轮代码修正后，另按状态含义、操作反馈、首页信息量和交付范围审查；仍未启动浏览器、软件或安装程序。

- “正在请求”只描述命令提交，不将点击、排队、读状态或计时结束显示为连接成功。连接成功仍来自服务端同路径双向验证。
- 未连通时保留阶段、等待时长和剩余预算；已连接设备的持续时长移入详情，复制 IP 仍是直接入口。全部直连后不继续占据首页的步骤条。
- 排队、回收、失败隔离和等待重试不再因公告过期被笼统覆盖。多机总览指出当前关注的设备，同时保留其它成员的正常进度和重试资格。
- 后台状态超过原有新鲜性期限后，所有设备行显示未知并清除旧 RTT/计时，避免旧绿色状态或隐形提示。没有因为 WebUI 断联而自动停止后台串流。
- 写操作期间保留一个状态请求的边界，旧请求可以等到原有超时再结束；因此下一次轮询可能稍后进行，但旧快照不能把操作结果改回去。没有增加频繁请求或轮询重启网卡。
- 网卡面板数字与详情复用同一次读取得到的统计，不将本地接受、拒绝或 API 返回成功解释成物理送达。
- 安装界面和许可保留上一轮实现；本次未重新包装旧程序为新网络修复版，没有改变日用安装或远端设备。

编译与 JavaScript 解析已完成，运行验证继续按用户要求暂缓。当前可以确认实现变化，不能确认串流卡死已消除、吞吐已改善、Wintun 4319 已根治或正式八成员组网已通过。

## 追加审查：恢复与故障隔离

- 入口释放失败不会仅清掉状态后继续创建新入口；界面明确该入口重建已暂停。已有健康直连和其它候选不会因此被主动重建，重试和网络唤醒也不能解除未证实的占用。
- 网卡创建后的过渡阶段现在有明确所有者；如果真实释放失败，采用已有的后台资源隔离反馈，不显示“已停止，可以重开”。没有修改官方网卡关闭耗时阈值或假设取消可以强制中断系统调用。
- 单个设备公告的解析错误不再把其它设备的同批信息一起丢弃，也不据此声称协调服务器断连。添加/移除设备的最新目录不应再被晚到的旧快照覆盖。
- 原 Wintun 记录中慢关闭主要耗时落在官方 API；本次代码修正不能拿编译结果替代该性能问题的复测。压力、吞吐、物理路由与实际串流证据仍没有更新。
- 新增提示复用现有状态详情，没有新增首页诊断面板、驱动选择或用户必须理解的内部资源编号。

## 追加审查：保活诊断的展示与解释

- 新快照经既有 `Liveness` 投影进入诊断导出；首页布局、设备主列表和操作入口不增加字段。备用资源的统计只提供给既有 Router 路径状态调用者，不宣称 WebUI 已显示备用统计。
- 字段明确区分尝试、本机接受、拒绝、及时回复、迟到及等待；缺少可分解证据的预算值使用 null。没有把本地接受或待回复移除解释成物理送达率/丢包率。
- 统计属于实际路径而非整台设备历史；备用转主使用同一资源累计值，换路径后需按 PathId 区分。路径退出后不承诺保留完整旧计数，后续压力验证必须定时采样。
- 编译不能验证计数准确性、控制消息大小或压力性能。新 DTO 属性沿原状态通路提供，64 KiB 控制消息上限未放宽；八成员状态与导出大小仍需后续受影响验证。
- 未改变成功、断线和恢复的显示判据，也没有据旧模拟压力记录将故障归因为 Wintun 或 WAN。正式版效果与实际串流结论继续等待运行证据。

## 追加审查：诊断增多时保持连接反馈

- 容量控制优先保留成员、连接与操作反馈，先省略展示日志和细分统计；没有为了呈现“正常网络”而隐藏部分未连接成员。
- 裁剪说明只放在已有诊断折叠区，默认隐藏，导出携带相同说明；首页保持原布局。部分统计为空不再可被当作完整的零丢包证据。
- 必要状态也无法显示时，页面和托盘明确未知/信息过大，不建议用户因为此情况修复安装，也不暗示后台串流已停止。已提交命令的结果仍单独返回，防止引导重复操作。
- 文件日志可能关闭或筛选，页面不承诺被省略内容一定存在于文件中；原队列和文件策略保留。
- 正常轮询多了一次容量序列化检查，超限处理次数有界但性能未实测。没有把编译、静态检查或字节预算设计说成八成员运行验证通过。
- 范围限于受限 UI 回复。旧管理员完整配置接口没有静默截断，不将本轮改动描述为全部控制接口已经通过容量验证。

## 追加检查：编译准备的报告口径

受影响的组网、出口、路径、UI 与官方生命周期验证工程已能编译。记录明确区分首次依赖清单缺失、恢复依赖后的编译成功与仍未执行的运行回归；不统计成“七项测试通过”，也不据此升级个人或正式就绪状态。研究驱动工程与历史研究集合没有被重新纳入本轮编译范围。
