## 实现变化

| 范围 | 已修改行为 | 尚不能得出的结论 |
| --- | --- | --- |
| 路由压力 | 每个 Router 使用一个独立维护线程；本机 UDP 同步发送改为非阻塞；持续接收每 64 包让出执行机会。保持同路径双向证明与 12 秒过期。 | 不能证明此前两次往返过期仅由线程池或全局锁引起，也不能声称掉线已消除。 |
| 控制与业务队列 | 原生桥仍最多 128 包，其中为控制预留 16 个位置，保持 FIFO；共享出口优先额度耗尽后，在普通 DRR 中最多连续选择两个控制包再服务业务。控制可淘汰数据尾包，但不能增加全机速率或队列总量。 | 数据突发可用位置变为 112，需要后续观察吞吐、拒绝率及延迟；未取得零丢包或目标吞吐证据。 |
| 损失定位 | 增加本机无健康路径、发送拒绝、认证/重放拒绝、来源/路径拒绝、网卡写入拒绝，以及原生桥入出队列拒绝和 socket 拒绝计数；记录维护延迟、锁等待与执行耗时。 | 这些计数不是物理丢包或应用送达；部分 OS/raw 回环内核损失仍未知。 |
| Wintun | 正式 Runner 使用可取消、带阶段反馈的官方网卡工厂；创建和关闭串行。旧身份等待可取消；官方 CreateAdapter 返回 4319 后最多重试两次，只在 15 秒恢复预算内启动重试；新建接口 IPv4 就绪等待最多 3 秒。 | 官方 CreateAdapter/CloseAdapter 调用本身不可被本补丁强制中断，15 秒不是整个创建调用的硬截止。4319、problem code 0x38、关闭偶超 3 秒仍未实测根治。 |
| 多机准入 | 新入站 Offer 和本机发起的候选进入同一轮调度，优先服务较久未得到名额的成员；后台工作仍让位前台。保留两条轻量、一条 FakeTCP 高成本并发及 60 秒含排队机会窗。 | 不保证每个成员在同一机会窗都能完成，也不代表八台独立 Windows 栈/28 条边已验收。 |
| 回收与反馈 | 未完成回收继续占名额；真实关闭失败保留所有者并报错，退出时上报 Runner，禁止假释放。新增本机排队顺位、等待对端安排、回收中、退出未证实、最近失败原因及未准入超时分类。 | 未知资源退出可能阻止同类新连接，这是保留所有权的结果；不能用重试按钮绕过。 |

FakeTCP＋明文 HTTP 前导＋MeshLink 加密数据报保持原语义，HTTPS 仍为控制面；没有引入业务可靠重传、真实 TLS 业务、新内核驱动或其它组网软件依赖。
