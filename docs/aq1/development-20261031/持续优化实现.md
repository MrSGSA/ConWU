# 持续优化：关闭完成证明与连接反馈

用户在安装界面工作后要求“先继续优化着吧，直到我回来”。本轮继续遵从“先不测试”，不运行应用、测试、安装、驱动或远端操作。接续 `e05263715c894f0bf390f1b9e50f0032403455fe` 的原有未提交修改，不覆盖冻结候选和历史失败。

## 本次修改

| 范围 | 源码确认的问题 | 修改 |
| --- | --- | --- |
| Router 关闭 | 第二次 `DisposeAsync` 在首次关闭仍未完成时直接成功返回；某一步清理异常会跳过后续清理。 | 所有关闭请求共享一个完成任务；等待全部数据泵和诊断生产者退出，逐项完成独立清理并汇总真实回收错误。关闭开始后禁止添加成员。 |
| 路径回收 | 接收泵吞掉传输关闭异常，随后完成任务可能被当成正常完成移除。 | 保留失败任务和实际路径 owner；相同成员或 TCP 四元组不能重新占用。关闭失败最终交给 Runner 的现有隔离机制。候选参数校验移到创建关联取消源之前。 |
| 多机状态 | 从未连接过的设备在上线信息过期后，可能把 `Blocked`、`Releasing`、`Retrying` 等真实状态覆盖成“等待设备”，并重新显示可重试。 | 只替换尚在寻找入口/等待响应的提示，保留实际准备、验证、排队、回收、隔离和退避状态；故障原因与下一步分开描述。 |
| 总览反馈 | 多机总览只取第一个未连接成员；即使正在回收或等待重试，也笼统显示“正在连接”。 | 优先显示需处理/回收等状态，多成员时注明设备名称；重试入口继续按其它未连接成员是否可重试判断，不绕过隔离。 |
| WebUI 状态顺序 | 早先的轮询响应可能在操作响应之后覆盖页面；旧请求的错误也可能把新状态改成离线。 | 操作递增状态读取代次；忽略旧代次的结果及错误副作用，写操作进行时不发新轮询，保持最多一个状态读取请求。 |
| WebUI 精简 | 已直连设备的计时与移除按钮长期占据主列表；失联时旧的隐藏属性可能让“状态未更新”不可见。 | 已连接计时和移除入口放入详情；未连接设备继续直接显示等待计时；全部直连后隐藏步骤条。后台状态失效时显示未知、清除旧 RTT 和运行计时。 |
| 操作与观测 | 点击后只有禁用状态；同一报告重复读取网卡统计，可能呈现不同采样时刻的数字。 | 立即给出“正在请求/提交”的文字反馈；每份报告复用一次网卡统计读取。原生计数仍是并发观测，不声称原子物理送达账本。 |

## 用户恢复测试后需要的受影响回归

1. 并发/重复关闭在首次关闭等待、成功及失败后均观察相同结果；各类数据泵、诊断和路径释放结束前不得关闭网卡，异常不得造成后续独立清理被跳过。
2. 受管路径关闭失败保留 owner 与失败信息；同成员/同 TCP 四元组不能重新占用，其它成员保持原准入规则；正常取消与业务泵异常不被误判为资源释放失败。
3. 未曾连通、曾经连通、对端公告过期，以及排队/回收/隔离/退避组合的反馈；多成员总览与重试按钮不产生错误承诺。
4. 轮询与命令响应乱序、旧请求的 401/503/超时、写操作期间轮询和授权真实到期；设置草稿保持、同一操作只发送一次。
5. 浏览器窄窗口、键盘与读屏；直连→状态未知→恢复时的 RTT/等待计时/详情和移除入口。现有安装、长时间串流、Wintun 和多机回归仍需另行执行。
