现有 HTTPS 订阅修复（1.0.6-rc.1）

基线为 Windows 1.0.5。本次保持原 HTTPS 域名、路径、令牌、TXT 标签筛选和
用户保存的设置，不增加独立入口，不改变 FakeTCP＋HTTP 业务承载。

现场确认
- 同一个 HTTPS 域名存在 TCP 建连和 TLS／响应头间歇性超时。
- 原生网络每轮刷新都会新建并销毁 ExistingEntryResolver，因而丢弃健康的
  HTTPS 连接。用实际已安装解析器做 8 轮交替对照：每轮重建成功 5 轮；
  复用同一解析器成功 8 轮。此短样本不代表长期成功率。
- 现有代理规则可能继续选择直连。指定本机代理端口不等于换了实际出口，
  不能据此把偶发成功归因于代理。Windows 订阅解析仍保持原来的直连策略。
- 地址上报过期会由订阅程序主动返回 503。该逻辑已在生产数据库的隔离副本
  中复现；没有修改在线记录或延长有效期。历史每次 503 的响应体未全部捕获。
- 服务器和客户端在失败时保存的最近地址不能冒充本次成功更新。成功响应的
  当前 TXT 与 HTTPS 地址相同；暂未捕获到两者不同的旧地址样本。

实现
- 网络运行器在本次网络运行期间持有一个解析器，结束、取消和资源退出时
  加入在途任务后释放；界面的“测试地址”也使用由控制服务持有的解析器。
- 连接池允许空闲 5 分钟，最长保留 10 分钟。每轮仍发出新的 HTTP GET，
  设置 no-cache／no-store，不缓存订阅正文。改订阅主机时使用其自己的连接池。
- 先验证完整 DNS 答案，再错开尝试最多三个已验证的公网地址。单个 TCP
  尝试允许 4 秒；优胜连接之外的任务全部取消、等待并释放。TLS 或响应失败
  后的重试优先尝试其他已验证地址。原请求、来源和整轮解析上限仍然保留。
- 请求发送描述性的 StreamLink User-Agent；保持证书校验、禁止重定向、
  禁止递归读取返回的 URL、禁止公网／私网混合 DNS 答案以及现有内容大小限制。
- 对有限大小 JSON 中的已知错误码给出“上报已过期”“尚未收到上报”等原因。
  不输出任意服务器错误正文、调试字段、URL 查询参数或令牌；错误详情读取
  自身有时间上限。未知 503 仍按有界暂时故障处理。

验证范围
包含真实回环 HTTP 连接复用、逐次变化的订阅正文、切换主机、释放生命周期、
超大及停顿错误响应、敏感内容不外泄、DNS／地址族切换、竞争连接释放、
取消、标签筛选，以及已有入口模式、网络运行器与控制服务的受影响回归。
两台实际设备使用原 HTTPS 订阅做隔离验证；详细结果另存本机忽略的诊断目录。

限制
这是现有 HTTPS 的客户端修复，不宣称已经修复运营商至 Cloudflare 的所有
网络丢包，也不改变 Lucky 的上报实现。首次连接、连接失效后恢复和上报端
仍需实际验证。候选不能冒充长期大码率、多机全部通过的正式发布。
