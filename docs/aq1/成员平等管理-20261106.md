# 成员平等管理

接续 `ea97d81`。2026-11-06 用户最终选择：网络及设备均为自己使用，采用成员平等管理，取代先前“指定多个管理员”的选择。本次完成协调网络的管理权限去中心化；保留 HTTPS 协调服务，不开展脱离服务器、托管发现或 Linux 普通节点工作。

## 使用方式

先更新协调服务，再更新网络内所有 Windows 设备。新建的协调网络默认采用成员平等管理。旧网络保持原权限，创建者在“创建网络”页面选择“启用成员平等管理”并确认，保留网络身份、虚拟 IP 和设置。启用后不能降级回旧授权规则；旧版设备不能正确验证新成员表，必须先升级。

每个获准成员都可以生成六位配对码、审批、移除其他成员和解散整个网络。批准加入时明确提示授予同等管理权限。没有固定主机或接任选举；每台设备持有自己的签名和交换密钥，不分发创建者私钥。

“退出网络”只撤销本机成员身份，其他成员继续使用；最后一个成员退出会关闭网络。“解散当前网络”关闭整个网络。概况中的断开操作仅暂停本机连接，保留身份。所有设备离线不会自动删除网络，恢复连接仍需要可达的入口及协调发现条件。

原无服务器直连邀请网络保持原管理方式。本次没有把它扩展为无需协调服务的多人管理协议，也没有改变 FakeTCP＋HTTP 数据语义、固定协议或已有入口禁止回退自主打洞的策略。

## 授权与恢复

根签名授权成员平等策略；此后的增加、原子替换、移除、退出和解散，由当时有效成员的设备密钥签名。完整历史绑定前一个状态，拒绝篡改、旧身份复活和分支替换。创建者被移除后，即使保留旧根私钥，也不能向已迁移网络恢复旧权限。

HTTPS 协调服务是管理变更的原子提交点，负责排序并发操作，不转发串流数据。成员自己的签名仍是权限依据。遇到并发批准，只有一个状态提交成功，另一方刷新后重新核对预分配 IP，不会偷偷换一个 IP 后继续审批。服务器持久化失败不确认变更，并恢复原可见状态。

客户端提交前将同一次变更和加密邀请写入受 DPAPI 保护的本机配置。丢失应答或重启后，复用同一操作“继续确认”；不会再次分配成员身份。服务器已批准但配对房间消失时，说明凭据未确认送达，保留成员供用户检查、移除后重新申请，不暗中撤销已经交付的身份。

成员表的变更只接受协调服务确认的历史。设备间继续交换已签名的入口公告；不能仅凭对端传来的新分支绕过提交确认。协调暂不可达时，健康的设备间直连继续；新管理操作等待协调服务恢复。协调数据卷必须备份，不能从任意旧副本推断丢失的撤销历史。

跨成员重新审批根据已验证的替换历史识别旧设备；主动退出后持原凭据重新申请，经任一成员确认，可用新身份保留原虚拟 IP，无需清空自定义 IP 设置。明确移除会使该继承关系失效。运行时入口跟随有效身份，保存的设置不被成员变更、退出或迁移改写。

## 容量与兼容

仍最多 8 个同时在册成员、254 个不复用的成员身份。授权历史最多 512 条、解压后 512 KiB；达到容量时明确要求新建网络。内部 HTTPS 和受保护控制通道增加有界容量，WebUI 的 64 KiB 限制保留。配对服务还限制所有已存密文的总量。

设备间同步不携带不断增长的授权历史；平等网络发送已知成员表摘要和入口公告，仍受原有分片、速率、队列及过期限制。授权校验缓存使用整个内容的摘要与独立序列化结果，不能仅凭历史末端摘要跳过被篡改的前文。
