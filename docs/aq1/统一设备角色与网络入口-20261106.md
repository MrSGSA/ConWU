## 用户确认的方向

- 每台设备都使用 StreamLink，可以作为普通组网设备、提供协调服务，或同时承担两种角色，不再要求用户单独部署另一套协调软件。
- Linux 作为完整普通节点，目标是具有与 Windows 相同的组网、管理、传输和恢复功能，不能把可执行的协调程序当作已经支持 Linux 组网。
- 用户连接的是一个网络。入口配置不再要求在“本机入口”和“目标主机入口”之间二选一，应改为该网络的接入入口。
- 成员继续平等管理；协调能力不授予额外管理权限。暂不推进脱离协调服务或 Cloudflare 托管发现。

## 设备角色

“参与网络”和“提供协调服务”是独立能力，允许同时启用。

| 参与网络 | 提供协调 | 设备行为 |
| --- | --- | --- |
| 开 | 关 | 普通成员，具有虚拟 IP、直连、串流及已获准的成员管理权 |
| 关 | 开 | 只提供发现、配对和管理变更确认，不占用普通成员身份或虚拟 IP |
| 开 | 开 | 同时提供协调并作为普通成员，与其他成员正常直连 |
| 关 | 关 | 保留设置与身份，停止相应功能 |

普通成员默认只启用参与网络；不因为软件具备协调能力就自动开放公网监听。协调服务启停不应重新创建虚拟网卡或中断健康业务连接。退出本机网络、解散网络和关闭协调功能是三个不同操作，界面分别说明影响。

统一软件、统一配置和更新入口，不要求所有功能挤在同一进程。进程安排以权限隔离、故障恢复和维护成本为准，用户无需安装第二套协调产品。Windows 使用服务，Linux 提供前台运行和后台服务方式。

## 网络入口的含义

网络身份由网络 ID、受信任的根及成员授权确定，不由某台设备、域名或 IP:端口确定。同一个网络可以有多个可用入口；地址变化不等于换网，知道地址也不等于获得加入资格。

入口在逻辑上属于网络，在物理上仍由某台设备或服务承载。软件必须识别并验证入口的实际能力：

1. **协调入口：** 提供 HTTPS 发现、配对、候选交换和管理变更确认。
2. **成员接入入口：** 通向某个已授权成员的 StreamLink 接收端口，通过认证后发现其他成员。
3. **地址来源：** HTTPS/TXT 等订阅返回前两类入口的候选地址；订阅本身不因此变成协调服务或成员凭据。

外部界面可以统一称“网络入口”，内部保留明确类型、网络身份、实际承载设备、传输能力、来源和有效时间。HTTP 地址订阅、HTTPS 控制和 FakeTCP＋HTTP 业务继续分开，不把可访问的网页、普通 TCP 端口或 STUN 映射结果视为已经验证的业务入口。

加入流程为：解析入口或邀请 → 建立受支持的接入通道 → 核验网络身份 → 提交加入申请 → 任一获准成员审批 → 分配虚拟 IP → 分别建立设备间连接。首次加入需通过邀请中的身份信息或配对校验确认目标，不能仅相信未认证的能力响应。

已有成员重新上线时，核验入口返回的网络与保存的身份一致，再更新运行时地址。订阅指向其他网络时拒绝自动切换并明确提示。入口故障只影响依赖它的发现或新连接，不应重建所有健康直连。

网络入口不是默认业务中继。B 通过 A 找到网络后，B 与 C 优先按用户所选方式直接通信；没有可行直连时报告原因，不默认经 A 转发视频流。

## 界面与设置

- **连接设置：** 保留固定协议及自主打洞/已有入口策略。统一提供“网络入口”多行输入与地址测试、来源刷新状态，不再让加入端手动选择某个成员 Slot。
- **创建/加入网络：** 邀请携带必要的网络身份和接入信息；六位配对码仍依赖可找到的配对服务或接入节点，不能单独定位一个未知网络。
- **本机能力：** 设置是否参与网络、是否提供协调服务，并显示各自运行状态。开启协调不能代替配对批准。
- **提供入口：** 为愿意承载入口的设备提供独立的本机发布设置，包含监听端口、外部映射或订阅。它不是加入网络时的“本机/目标主机”二选一。自动发现无法知道用户任意配置的 Lucky/路由器映射，必要时仍需用户提供。
- **概况：** 区分本机角色、网络入口可用性、协调状态和各成员的实际直连状态；不能用“协调在线”替代“串流可用”。

现有设置的升级迁移须按语义保留：本机发布地址迁入本机发布设置，目标成员地址迁入相应网络的入口候选，并保留原身份关联。不能删除 PeerSlot 后把旧本机地址当成远端地址连接，或把远端地址发布成本机地址。无法安全确定的旧配置保留原值并要求核对，不静默清空。

网络操作只改变身份和运行状态，不改写用户保存的设置。自动解析、角色切换、加入、退出、成员撤销、升级和恢复都要覆盖此约束。邀请带入的是运行信息，未经用户保存不能覆盖设置。

## 协调集成与协调接管的边界

当前成员平等授权已实现；管理变更的确认仍使用单个 HTTPS 协调服务的原子提交。将其内置到 StreamLink 可以消除单独安装步骤，但不会自动获得复制、选举或失效接管。

允许多台设备开启协调能力，不代表可以将同一网络交给几份互不同步的 Registry 同时写入。多个网络入口必须能验证同一个网络，并使用一致的已确认授权状态；不能因为另一个服务接受旧成员表，就将其标为当前网络的健康备用协调。

若继续扩展同一网络的协调接管，需要另外落实提交记录复制、明确的写入授权、并发冲突与网络分区策略。两台设备失去联系时，不能既允许双方任意批准/撤销，又宣称两边立即得到同一个最终成员表。未实现和验证这些机制前，应明确显示协调不可达，保留健康直连及待确认操作，不伪造接管成功。

所有成员离线不会删除本地网络身份，但没有任何可联系的入口时，保存凭据不能保证重新找到其他设备。统一入口模型不改变这一可达性条件。

## Linux 功能与构建

复用协议、签名授权、配对、成员表、连接调度、入口订阅、设置语义和统计；隔离操作系统适配。目标是同等组网能力，不要求 Linux 模仿 Windows 的驱动、MSI 或托盘形态。

- Windows 保留官方 Wintun/WinDivert；Linux 使用内核现有 TUN 和适合其网络栈的收发实现，不开发新内核驱动。
- Linux 必须实际实现并验证相同的 FakeTCP＋HTTP 数据语义、握手认证、包长、队列、保活与恢复。仅替换网卡或编译通过不等于功能对齐。
- 本机控制接口、密钥存储、文件权限、进程生命周期、路由和防火墙规则都需有 Linux 实现；不能在 Linux 调用 DPAPI、Windows SID、命名管道身份检查或 WinDivert。
- 操作提供 CLI；共享 WebUI 可复用设置和网络管理流程。无桌面环境不依赖图形登录，管理界面不因启用协调功能而自动暴露公网。
- 优先提供按 CPU 架构和运行库基线构建的自包含 Linux 包，明确支持范围。Debian/Ubuntu/Arch 等不应各维护一份协议代码；glibc、musl、x64、ARM64 的差异分别构建和验证，不能将单个 x64 包声明为所有发行版可用。
- 安装、升级和卸载保留设置与必要身份，管理数据和程序文件分离。卸载或连接失败只清理本实例拥有的网卡、进程和网络规则，不改变系统默认路由或其他软件通道。

## 改造前的代码核对与落地范围

- `StreamLink.Discovery/Program.cs` 当前独立启动 HTTP 服务，持有配对房间和 MeshRegistry。需抽出可复用的协调宿主与实例配置，避免嵌入后仍依赖全局环境变量，保留现有协调数据目录的迁移路径。
- `StreamLink.Service` 和 `StreamLink.Web` 当前面向 `net10.0-windows`。`ProfileStore`、本机控制、启动设置和运行期资源需从跨平台组网逻辑中分离。
- `MeshRuntimeServices` 已提供网卡、传输、发现和防火墙注入边界，可复用生产 Runner；不能另写一个功能不全的 Linux 简化组网核心。
- `NativeAdapter`、`MeshTransport`、`NativeAttachment` 和受管原生路径仍有 Windows 依赖，必须补足 Linux 数据面及资源所有权，而非仅让协调程序开启虚拟 IP。
- `ExistingEntry.PeerSlot`、`SavedNetworkSettings`、`RuntimeEntries` 和 WebUI 的入口归属选择共同影响连接逻辑，须整体迁移，不能只改文案。

## 验收要求

1. Windows/Linux 混合网络覆盖普通成员、仅协调、两者兼任三种组合；同等成员可配对、审批、移除、退出和重新加入。
2. 协调功能的启动、停止、异常退出与升级不错误清空身份、设置或中断不依赖它的健康直连。
3. 网络入口覆盖单地址、多地址、动态订阅、地址变化、身份不匹配、临时不可达和入口节点离线。已通过的健康连接不被地址刷新反复拆除。
4. 已有入口与自主打洞继续严格按用户选择运行；不自动跨模式回退，不切换到 UDP，不因两种角色同时开启而争抢端口。
5. 多成员同时审批、丢应答、重启恢复、撤销及旧记录重放继续验证。任何新增协调复制行为须有独立的一致性和分区测试。
6. Linux 真实 TUN、路由、原生业务包、退出释放和设置升级需实际运行；WSL/回环、实机 NAT 和大码率串流分别报告，不能相互替代。
7. 做正确性/安全与产品/质量两轮分离检查，受影响回归后冻结候选，再进行必要完整核心验证，提供 Windows 与 Linux 实际运行包。

保持现有 `1.0.6-rc.5` 候选与日用安装作为回退基础。新版本未部署到现有设备；没有实现协调多副本复制或自动接管。

## 本次实现与两轮检查

正确性与安全检查：协调路由复用生产 Registry；角色变更不重建数据路径。Linux 控制接口验证同 UID，原生受管接口验证父子 PID/UID 和授权元组，配置文件 0600、数据目录 0700。新入口使用成员签名、网络 ID、随机挑战和有效时间验证；不同网络、撤销成员及篡改响应不能自动绑定。未健康的入口绑定会重新识别。内核规则按实例、命名空间和锁定记录回收；客户端规则限定四元组，服务端成功占有端口后才安装规则，避免影响已有服务。

产品与质量检查：本机发布入口和接入网络的入口独立；旧归属保留；新增入口不要求选择创建者。Linux CLI 和 WebUI 复用后台操作、审批与设置事务。systemd 安装器保留设置和旧程序，卸载也保留数据；安装事务通过隔离文件系统与模拟 systemctl、真实后台进行验证，不冒充实际发行版 systemd 验收。Windows 原有保存、错误消失、输入状态、浏览器导航回归继续执行。

新增验证入口：`tests/StreamLink.UnifiedHostTests`；`scripts/Test-UnifiedLinuxHost.py`；`scripts/Test-UnifiedLinuxMesh.py`；`scripts/Test-UnifiedLinuxInstall.py`。构建分别使用 `Package-AqPersonal.ps1` 与 `Package-UnifiedLinux.ps1`。Linux 使用指南在 `packaging/linux/README.md`。

限制：Linux 当前原生 FakeTCP 为 IPv4，未实现 Windows 捕获 broker 专属的 IPv6 FakeTCP、来源端口学习和实验出口调度。UDP 只有用户主动选中才运行。新版匿名网络入口探测要求响应设备升级；旧版具名入口兼容保留。首次加入仍需要配对审批或直连邀请，裸 IP 不能证明网络身份，也不会自动变成 HTTPS 协调地址。
