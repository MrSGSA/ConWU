# 不再把空闲网络显示为持续等待

用户在 rc.3 修复候选验证期间补充：没有添加更多机器的意图，却仍看到持续等待。核对发现成员状态汇总会选择任何未连接成员作为主进度，没有其他成员时也固定为 WaitingPeer；添加设备页在没有配对任务时仍显示“等待申请”。这些显示容易把正常空闲误解为尚未完成的连接。

## 行为

- 没有其他成员，或所有已配对成员都没有有效上线公告且没有进行中的连接任务：显示“网络已就绪”，无等待计时、连接步骤和重新探测按钮。
- 一台已直连，其他已配对设备未在线：总状态保持“已直连”，明确列出未在线数量，设备列表继续显示各自状态。
- 对端没有有效上线公告且没有有界连接尝试：显示“未在线”，说明上线后自动连接。它不是由协调元数据单独证明设备已关机；仍以实际认证路径健康为先，健康路径即使公告过期也继续显示已直连。
- 准备、验证、排队、有限倒计时、退避、资源回收和资源回收失败均保留。正在执行的 WaitingPeer 不会被公告过期隐藏；无法回收资源仍显示需要处理。
- 未主动创建邀请时，校验码位置显示“—”。创建邀请后仍按原配对有效期等待申请，不自动添加下一台。

这次补充只改变反馈汇总和 WebUI，不修改成员授权、调度、入口生命周期、协议、保活、数据传输或后台低频成员发现。此前修复的“有健康直连时暂停无用入口探测”继续保留。八成员是容量上限，不是连接完成所需人数；已有直连不依赖凑齐更多设备。

## 正确性与安全复核

状态只由现有已授权成员和已认证路径导出；不生成占位成员、不撤销成员、不以公告代替双向健康证明。Offline 不覆盖正在执行的操作、期限或清理失败；主状态仍保留其他成员的真实错误。没有改变 WebUI 的鉴权、CSRF、纯文本渲染和控制能力边界。

状态用例覆盖空成员、离线成员、在线与离线混合、曾连接成员返回、过期公告但路径健康、有界握手及资源错误隔离，16 项通过。浏览器检查通过 26 项，包含真实 Edge 中的空闲状态、混合成员、配对占位、实际重试倒计时、后台失联与会话过期；测试状态通过隔离 HTTP 输入，不是 WAN 测试。

## 产品与质量复核

已检查浏览器截图：正常连接保留复制 IP 和断开入口，离线成员不再制造主连接进度；空网络使用中性的就绪状态。实际连接或恢复仍显示步骤和本轮期限，不用静态“就绪”掩盖工作。主连接时长改为已验证成员中最短的连续连接时长，不再从网络启动时计作连接时长。

前一冻结提交 `77d740f2` 的 Full 检查已完成：网络、资源、原生控制、Runner 各相关步骤及两个 30 轮组通过；唯一失败为托盘键盘用例 `Enter activates Exit only`。同一原始测试 DLL 在后续单独运行通过，带诊断的相同包测试也通过；原因未定，保留全部失败证据，不宣称已修复托盘竞态。
