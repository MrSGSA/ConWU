# ConWU：独立网络设置与统一配对入口

用户发现已有网络时再次创建网络，保存设置会更新先前网络。正式发布与三机清理暂停，本轮修复配置、移除已保存设置界面、统一首次配对地址输入并修正确认弹窗；不扩展 PKARR。

## 独立设置

原因是创建页自动选中第一份已保存配置，“再创建一个网络”没有清空这个引用。新版彻底移除 WebUI 的已保存配置、选择、复制和共用联动入口。新网络从默认值开始，独立保存设置与虚拟 IP；刷新、连续创建均不回到旧网络的配置。

旧版本已有的共用关系保持运行。编辑其中一条网络时准备独立副本，保存后只把目标网络指向副本，其它网络与原配置不变；取消不改引用。旧 CLI 配置接口保留兼容，WebUI 不再提供共用功能。

前端检查打开时的目标与配置身份，并在保存前再次检查引用；提交携带 `Independent=true`。后台在网络与共享设置门锁内校验：引用不属于目标或目标已删除时拒绝提交，不修改原记录，不产生无目标副本。确认弹窗期间新增加的引用也受此保护。失败保留草稿，再次保存可生成独立副本。

## 一个目标地址框

加入页仅一个地址框：“本次目标网络的协调服务器/已有入口”。配对码输入和申请在地址为空时禁用；邀请模式不显示该框。地址与可选协调指纹在原浏览器缓存中保留，不改已有网络或本机协调监听。

普通 IP:端口、域名:端口、HTTP(S)/TXT 订阅均可提供入口。HTTPS 无标签或查询参数时，先只查询协调健康信息；识别为兼容协调服务后才提交配对码。明确的信任、访问或网络失败不降级为未固定证书的订阅请求。无法提供协调能力的普通 HTTPS 页面才按订阅解析。查询参数、标签不会作为协调请求转发，返回内容也不会作为新 URL 跟随。

已有入口网络手动发码时使用本机短码会话；可选协调服务只登记该会话的签名入口线索。同一码可经主机入口或协调查询到入口后申请，仍须验证校验码并审批。登记尚未完成时，查询端提供有界等待与进度，不因地址来源变化启动自主打洞或运行时协调备用。活动码绑定原登记服务，不被后来的偏好修改偷偷改写。

裸入口默认 FakeTCP＋HTTP；显式 `udp://` 表示用户选择 UDP，不自动切换协议。自主协调网络和直连邀请保持原有发现语义。新无协调网络不自动创建隐藏的数字配对房间，需用户点击发码。

直接配对的申请方也持续执行可取消的后台观察；不因底层直连标记而漏掉审批结果，不要求手动刷新才能完成配对。

确认弹窗单独设置内边距、标题与说明间距、操作区间距及窄屏换行。实际浏览器检查 1440 和 390 宽度下标题与按钮边界，并保留截图。

证据在 `artifacts/creation-isolation-20261109`。原问题先复现再修复；检查覆盖连续三个网络的配置身份及虚拟 IP、旧共用关系单独分离、取消、编辑/确认期间新增引用、另一窗口删除目标、后台拒绝与正常独立保存。实际 WebPanel 保存前后逐项比较旧配置。统一配对使用实际本地 TLS 协调服务与回环传输，覆盖两类输入、错误信任、主机协调离线时走已有入口、审批前不下发配置及审批后单包认证交付。未进行实际串流或公开 PKARR 发布。
