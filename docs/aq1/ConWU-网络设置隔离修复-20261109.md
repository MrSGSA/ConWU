# ConWU：网络设置隔离修复

用户发现已有网络时再次创建网络，保存设置会更新先前网络。正式发布与三机清理因此暂停，本轮仅修复配置，不扩展 PKARR。

## 原因与行为

创建页初始化会自动选中第一份已保存配置，“再创建一个网络”只清空网络名称和虚拟 IP，没有清空配置选择。第一份配置已用于旧网络时，保存沿用旧编号，触发原有的共用配置更新。

WebUI 取消共用联动。新网络默认使用独立设置；“复制已有设置”仅复制可编辑内容，不选择来源的写入编号，不复制虚拟 IP。连续创建、重新进入页面、刷新和删除未使用设置均不回退到第一份配置。

旧版本已经共用的网络保持运行。编辑其中一条网络时，以原值准备独立设置；保存后只把目标网络指向新副本，其它网络与原配置不变。取消保存不改引用。正常的独立网络仍可直接编辑。旧 CLI 配置管理保留兼容。

## 并发保护

前端检查目标网络和打开时的配置身份；保存前再次检查引用，必要时另存副本。提交携带 `Independent=true` 及目标网络操作 ID。

后台在配置写入所使用的网络门锁与共享设置锁内检查引用。已有配置若被目标之外的网络使用，拒绝独立写入或绑定；目标已删除也拒绝保存，既不更新原配置，也不生成无目标副本。该检查覆盖用户停留在确认弹窗期间发生的引用变化。拒绝后保留草稿，再次保存可创建独立副本。

新增字段仅为操作约束，不改变持久设置格式、网络身份、传输协议或已批准成员。不更改现有网络的入口、虚拟 IP、连接策略、协调地址和开机启动。

## 检查记录

修复前，使用真实生产前端和隔离的 API 夹具复现“再创建网络默认选中首份配置”，失败记录保留于 `artifacts/creation-isolation-20261109/before-fix`。

正确性与安全检查覆盖连续三个网络的配置身份及虚拟 IP 隔离、复制不改变来源、旧共用关系分离、取消、编辑期间及确认期间新增引用、另一窗口删除目标、后台持锁拒绝、正常独立保存与旧 CLI 兼容。产品与质量检查覆盖草稿、恢复、刷新、原有配对及状态交互。实际 WebPanel 检查保存前后全部已有配置，不能因初始默认配置数量不同而放宽“原配置不变”断言。

新增测试最初误把操作请求的 `NetworkId` 属性写为构造参数，编译失败；已修正为属性初始化。实际 WebPanel 夹具中原有默认配置也被正确保留，复制检查因此改为比较基线数量增加一项，并逐项确认原记录不变。原失败证据保留。

候选 `1.1.0-preview.8`，MSI `1.1.7`。定向结果、冻结后的核心结果、实际安装包与三端升级记录随候选保存。只进行隔离功能与安装检查，不执行实际串流、公开 PKARR 发布或带宽压力测试。正式发布及清理保持暂停。
