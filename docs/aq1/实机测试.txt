StreamLink 1.0.1-rc.6 · Thinkbook / Akane 更新与串流复测

rc.3 实测冻结时为 UDP_DIRECT，恢复到 FakeTCP 后用户确认画面正常。本候选默认固定 FakeTCP，设置可选直接 UDP；运行中不跨协议回退。隔离回归不能替代本次实际串流复测，也不能单凭这次对照断言所有卡顿都由网络 QoS 引起。
同时修复 TCP STUN 备用查询取消后的资源泄漏，收敛健康直连旁的重复入口探测，并将辅助观察失败与网关租约维护分开。健康路径没有一分钟寿命上限。

开始前
对照测试时两台使用同一版 x64 MSI，并在 WebUI 底部核对 1.0.1-rc.6。已有安装通过 MSI 更新并保留配对；未安装的电脑直接安装。此版仅改变 Wintun 安装维护，不改变 rc.5 业务协议，台式机 rc.5 正常时无需为本次安装排障立即更新。安装器会自动清理本实例旧 Wintun 网卡和对应残留接口记录，保留其他程序的网卡；请先结束串流，观察能否免重启恢复。保留其他必要的远程管理通道。

本次协调入口 https://streamlink-personal.space4sgsa.com/ 已于 2026-10-31 恢复；更新不修改现有入口与配对。stun.space4sgsa.com:3478 继续是 STUN 地址，不能填入协调栏。

连接与串流
1. 普通打开桌面 StreamLink，在“添加设备”填写同一个可用的 HTTPS 协调地址。
2. 一台创建网络，另一台用六位码加入；核对双方校验码后允许加入。若已有同一网络配置，直接连接即可。
3. 两边出现“已直连”后，复制主机的 StreamLink 虚拟 IP，作为 Moonlight 等串流软件的目标地址。记录实际承载是否为 FakeTCP＋HTTP。
   两端“设置 → 连接设置 → 传输模式”应一致。开机服务自启，日常账号登录后有托盘，右键打开固定地址 127.0.0.1:47821 的 WebUI；不需要猜新端口。端口被占用时先处理明确错误。
4. 本机 Moonlight、Akane Sunshine。先用较低码率确认画面、声音和输入，再设为日常使用的分辨率、帧率、编码与码率。记录开始时间，连续使用至少 30～60 分钟，重点观察曾经出现的卡死、声音中断、丢包峰值和 -1 断线。
5. 正常结束后，可主动断开/重连一次，观察网卡准备、连接恢复和原虚拟 IP 是否正常。正式长时间及多成员验收另行进行。
6. 若看到 STUN 辅助观察重试，分别记录是否出现“PeerHealth ... connected=False”或新的业务 path 标识；辅助连接重试不等于正在使用的直连必然重建。新日志会注明 RemoteClosed、ConnectionReset 或查询超时。
7. 没有其他在线设备时，“网络已就绪”表示正常空闲；不需要添加更多电脑。已有直连时，其他离线成员不应让主状态一直等待。真正的连接尝试、恢复与资源错误仍会单独显示。

发生卡死或掉线时
先记录两边“连接”首页的阶段和时间；在两边“设置 → 诊断与日志”导出脱敏诊断，再尝试重新探测或重连。能保留第一次故障状态时，优先不要马上重启后台。
分别命名为 Thinkbook-时间.json、Akane-时间.json，并记录当时的串流码率、分辨率/帧率、是否自行恢复以及大约持续了多久。
若页面显示“状态未更新”，也记录串流本身是否仍在继续；页面失联与业务掉线分开判断。
诊断如提示省略部分日志/统计，该导出不是完整物理损失证据；程序仍会保留连接判定与操作结果。

范围
本机回环、API、资源回收和持续负载检查不能替代真实 Wintun/物理网络/应用帧质量。双机试用通过也不等于正式八成员组网或正式发布全部通过。
本包不自动部署或替换协调服务器，不修改现有 STUN 服务。安装/更新/卸载和 ZIP 备用方式详见“使用说明.txt”。
