StreamLink 1.0.1-rc.13 · Thinkbook / Akane 实机复测

先结束串流，分别更新两端 MSI，界面版本应为 1.0.1-rc.13。现有配对和配置保留；不要为了显示长邀请而删除当前网络。业务默认 FakeTCP＋HTTP，不跨协议回退 UDP。

本次重点
1. 按单独提供的 Lucky 配置说明新建 StreamLinkTCP 规则，通向主机 StreamLink 接收端口 44680。保留 EasyTier 11010 和现有管理通道。
2. Lucky 上报新 HTTPS 记录，并更新独立 TXT。两种来源解析结果应为同一新公网 IP:端口，不应继续返回 EasyTier 的旧端口。首次上报前 HTTP 404 是“尚未上报”，不是有效入口。
3. 两端设置 → 协调与连接 → 优先使用已有入口。主机填“本机入口”，笔记本填“目标主机入口”。当前服务器网络继续保留原协调地址与模式。订阅默认每 60 秒更新。
4. 保存入口来源应不重建现有健康网络；修改协议或监听端口会要求确认并等待安全重建。慢退出时观察进度，无需重复点击。真正超限或资源关闭失败会保留错误和所有权。
5. 概况中确认已直连、固定协议；日志查看“实际直连入口”。解析成功、TCP SYN 响应都不等于 StreamLink 已认证。
6. 本机 Moonlight、Akane Sunshine。使用 StreamLink 虚拟 IP，先低码率确认画面/声音/输入，再按日常配置连续使用至少 30～60 分钟。记录冻结、恢复时丢包峰值及 -1 断线的时间。
7. 新加入设备直接粘贴六位码或 SL5. 完整邀请，输入框自动识别。六位码仍需主机同意；长邀请是主机预授权，无需另填入口。当前有服务器的网络不因此自动变成无服务器网络。

发生问题时
在两端“日志”页导出日志，记录时间、码率、实际入口和协议。保持首次故障现场，区分页面操作失败与实际串流中断。订阅失败时记录 DNS / TCP / TLS与响应头 / 响应内容阶段、耗时和次数。

边界
本次隔离 Wintun 重开、浏览器和核心回归不能替代真实 Lucky 映射兼容性、公网首次连接及长串流质量。测试数据、首次失败与后续修复复测分别保留；正式八栈、跨网络长期可靠性仍未验收。新版未自动安装到日用设备。
