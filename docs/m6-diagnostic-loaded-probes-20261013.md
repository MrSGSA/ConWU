# 加载RTT采样绑定实际路径和测量窗口

0.5.6第二轮完整Package（`c41b886`）在`quality-native-fault`失败，原日志和JSON保留于`artifacts/m9-0.5.6-second-c41b886/`及独立整包日志。候选尚未发布。

失败来源是第3个测量窗口只有一个加载RTT样本；质量判定按原门槛返回`QualityUnknown / MissingLoadedTiming:3`，并正确保持原路径。该窗口虽有实际负载，只依赖普通1.5秒保活不能保证五秒内得到足够样本。

本次正式诊断发送阶段每500ms尝试一次同路径探针，每窗口最多10次，已有4个返回样本后停止额外探针。沿用`AdmitMaintenance`，与全机控制/维护计账共用；已有业务、路径失效或取消时不额外测量。只采样，不重传业务，也不延长测量或许可。

在真实发送时为保活/加载探针记录诊断leg。收到匹配nonce后，加载样本必须仍属于相同路径、相同leg和发送阶段；上一窗口、空载基线和无leg标记的迟到回复不再被误记。保留质量准入的至少两个样本门槛，不用一次RTT或小包推导容量。
