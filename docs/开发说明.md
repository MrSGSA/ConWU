# 开发与构建

Windows 和 Linux 共用 `rust/Cargo.toml` 下的主程序及组网核心。主程序嵌入 `src/ConWU.Web/wwwroot` 的页面，并使用 `src/ConWU.App/Assets` 的图标。构建身份、迁移和模块边界见 [Rust 说明](../rust/README.md)与[架构文档](../rust/ARCHITECTURE.md)。

## 构建与打包

- Windows 使用 Rust、MSVC 和 Windows SDK 编译主程序。`scripts/Build.ps1` 通过 CMake、Ninja、MinGW-w64 和 Cargo 构建原生组件。`scripts/Install-InstallerBuildTools.ps1` 安装 WiX 6.0.2。
- Linux 通过 `rust/build-linux-musl.sh` 构建静态主程序和原生组件。原生 FakeTCP 使用 C++，Mimic、TCPRAW 和 Phantun 在 `transport/phantun` 的 Cargo 工作区构建。
- `rust/package.py` 生成运行包和对应源码归档。Windows 通过 `rust/Build-Msi.ps1` 从暂存目录构建 MSI，Linux 运行包附带安装、卸载脚本。正式打包使用已经提交的构建输入，并从空暂存目录生成附件。版本、哈希、SBOM 和验证范围随正式发行包提供。[正式版](https://github.com/MrSGSA/ConWU/releases/latest)

随包保留原生组件的构建输入、源代码和许可证。`installer/` 保存 MSI 界面，`third-party/` 保存官方组件的头文件及许可。

## 回归测试

```sh
cargo test --locked --manifest-path rust/Cargo.toml --workspace --all-features
```

`scripts/Build.ps1 -Test` 还会运行原生 FakeTCP 的 `tests/protocol_loopback.py`。`rust/test-web-presentation.py --app <候选程序>` 检查实际嵌入的 WebUI。更新、回退、跨平台承载和网卡验证的入口及范围见 [Rust 验证](../rust/VALIDATION.md)。这些实验使用独立的测试数据目录。

## 主机入口诊断与隔离验证

`rust/native-nat-lab.sh` 使用 Linux 网络命名空间复现网关映射或双端协调。验收核对候选、实际发包、首次配对和重启后的双向数据。实验拓扑和复现命令见 [NAT 穿透实验](NAT穿透实验.md)。

## TXT 入口恢复

TXT 入口解析并发查询系统递归服务器和 HTTPS DNS 服务。解析器汇总并去重候选，连接仍由成员认证决定。配置了订阅来源的已配对网络按照当前订阅重连。针对用例位于 `rust/crates/conwu/src/tests.rs` 的入口解析和重启恢复测试。

## Android 与旧版源码

Android 预览继续使用 .NET。`ConWU.Android` 依赖 `ConWU.Mobile` 和 `ConWU.Core`，功能回归使用 `tests/ConWU.MobileTests`，构建及模拟器验证见 [Android 使用说明](Android使用.md)。`rust/compat/ConWU.DotnetOracle` 供 Rust 跨版本协议测试使用。

旧版 Windows／Linux C# 后台、测试项目及其打包脚本可从 [v1.4.5](https://github.com/MrSGSA/ConWU/tree/v1.4.5) 标签独立检出。该版本的开发流程见[旧版构建说明](https://github.com/MrSGSA/ConWU/blob/v1.4.5/docs/开发说明.md)。
