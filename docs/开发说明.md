# 开发与构建

本地更新和 UU 接管的针对检查：`ConWU.UpdateTests` 覆盖完整包校验、下载取消隔离、确认票据、旧任务隔离和恢复状态；`ConWU.MeshConnectionTests --local-update-ui` 覆盖授权与设置写入边界；`Test-UpdateUiBrowser.cjs` 检查下载进度、确认和设置草稿保留。`ConWU.UuTakeoverTests` 与 `Test-UuTakeoverUi.cjs` 覆盖多网络自动参与、单网离线、进程重建和实际流量状态；真实 UU 串流路径的私有证据保存在忽略目录，不随源码或安装包分发。

Windows 更新程序为静态原生 `conwu-updater.exe`，确认后复制到受保护更新任务目录运行。更名后的 MSI 先在升级事务中停止旧客户端、移除旧服务组件，再安装同名服务的新可执行文件；SYSTEM 发起的更新保留已有日常用户授权。更新程序不得持有跨卸载阶段的旧 SCM 服务句柄。打包要求所有构建输入已提交且无受跟踪修改；不参与构建的未跟踪研究文件允许保留，生产输入目录中的未跟踪文件仍会拒绝打包。

环境：Windows x64、.NET SDK 10、Rust 1.85+、CMake、Ninja、MinGW-w64；Phantun 的 Windows 构建还需 Visual Studio C++ Build Tools。原生测试使用 Python 3，MSI 使用 WiX。运行包不要求用户安装这些工具。

Phantun 使用锁定的 Cargo 依赖。Windows 静态链接 C 运行时，Linux 组件通过 Rust 自带 LLVM 链接器构建静态 musl 二进制。构建前执行 `rustup target add x86_64-pc-windows-msvc x86_64-unknown-linux-musl`。可用 `scripts/Build-Phantun.ps1 -Platform Windows -Test` 或 `-Platform Linux` 单独构建组件。

`ConWU.PhantunTests --native <组件目录>` 检查真实驱动启动与端口生命周期，需要管理员权限及完整 WinDivert 依赖。`scripts/Test-PhantunParent.py` 检查父进程异常退出。Linux 使用 `scripts/Test-PhantunNamespaces.py --app <测试程序> --components <组件目录> --output <证据目录>`，以 root 在临时网络命名空间中运行；测试程序需先通过 `dotnet publish tests/ConWU.PhantunTests -c Release -r linux-x64 --self-contained true -p:StreamLinkPersonalFeature=true -o out/phantun-tests-linux` 生成。该检查使用临时身份和内存网卡，覆盖真实原生承载与正式服务审批，不读取生产配置。

```powershell
.\scripts\Build.ps1 -Test
dotnet run --project tests/ConWU.Tests -c Release -p:StreamLinkPersonalFeature=true
dotnet run --project tests/ConWU.MeshConnectionTests -c Release -p:StreamLinkPersonalFeature=true
dotnet run --project tests/ConWU.WebTests -c Release -p:StreamLinkPersonalFeature=true
dotnet run --project tests/ConWU.StreamTransportTests -c Release -p:StreamLinkPersonalFeature=true
dotnet run --project tests/ConWU.PhantunTests -c Release -p:StreamLinkPersonalFeature=true
node scripts/Test-BackendFreshness.cjs
```

冻结并提交源码后，使用现有打包入口：

```powershell
.\scripts\Package-AqPersonal.ps1 -OutputRoot ..\releases -DependencyCache .\out\downloads -Version 1.2.0 -MsiVersion 1.2.3 -PublicationApproved
.\scripts\Package-UnifiedLinux.ps1 -OutputDirectory ..\releases\linux-build -Version 1.2.0
```

后续发布使用新的应用版本和递增的 MSI 版本；冻结的输出目录不能覆盖。打包清单仅表示构建及包预检完成，正式发布状态由 GitHub Release 元数据和随附 verification.json 记录，后者包含回归及三机升级的验证范围。

脚本名称沿用开发期命名。当前 Windows 打包入口是 `Package-AqPersonal.ps1`，Linux 是 `Package-UnifiedLinux.ps1`。依赖缓存需要官方 Wintun 0.14.1、WinDivert 2.2.2 及对应源码包；构建中会核对驱动签名与固定哈希。Linux 打包另需 WSL 中的 CMake、Ninja 与编译工具。

`src` 是应用与服务，`transport` 是原生传输及网卡桥接，`tests` 与 `scripts` 保存测试和构建入口。`out`、各项目 `bin/obj` 属于可重建产物；历史测试证据与私人配置应先归档，再清理 `artifacts`。

## Android 与更新检测

Android 从机构建使用独立的 `scripts/Build-Android.ps1`，不要求桌面端开发者安装 Android workload。依赖、测试签名与使用流程见[Android 使用说明](Android使用.md)。当前 Android 项目关闭裁剪、AOT 和原生 JNI marshal 方法表，使用托管 JNI 注册；后者避免 .NET Android 10 的增量 Release 构建遗漏变更后的 Activity 回调。升级工具链时应重新验证安装后的冷启动，不能只检查编译成功。

`ConWU.Mobile` 复用现有审批、签名身份与 TCP／HTTPS 承载。Android 仅给系统 VPN 配置一个本机源地址，按已批准主机的 `/32` 添加路由。`MobilePacketHub` 在系统 VPN 与各网络之间转换本机地址，更新 IPv4、TCP／UDP 校验和，处理承载校验和的分片与 ICMP 错误中的引用报文；线上仍使用各网络独立的已批准虚拟 IP，入站先经身份认证和目标核对。不能把多个不同网段的地址直接加入同一 Android VPN 后假定系统会按对端选择正确源地址。

`ConWU.MobileTests` 覆盖真实回环配对、审批拒绝／取消、协议隔离、证书绑定、恢复与地址转换。`Test-AndroidClient.py` 使用隔离模拟器及真实系统 VPN 验证双网 TCP／HTTPS、系统 ping、UDP 套接字二进制回声、应用重开和同签名 APK 覆盖安装；不操作生产三机。模拟器结果不代替实际手机、后台省电或 Moonlight 高码率验证。

更新检测由 `ReleaseUpdateMonitor` 合并请求，只读取官方 GitHub 正式 Release 的公开元数据，并按平台和架构选择附件。WebUI 的 `update-check` 在设备级鉴权后立即返回，HTTP 在后台执行；仅更新软件更新模块的 DOM，保留设置草稿及输入控件。`ConWU.UpdateTests`、`ConWU.MeshConnectionTests --update-ui` 和 `Test-UpdateUiBrowser.cjs` 分别覆盖解析／缓存、安全与非阻塞接口、界面更新和草稿保留。Linux 的 `conwu update check` 不依赖运行中的服务，也不写网络配置。

后续三机更新只保留当前版和上一个可回退版本。新版验证正常后，清理重复安装包、上传暂存、解压副本及测试临时目录；上一版只保留一套程序与匹配设置备份。当前安装维护所需的 MSI、生产设置、网络身份和用户日志保留。清理只针对可重建产物和确认闲置的文件，保留当前源码、Git 历史、开发工具及依赖缓存。

## UU 通道接管与文件命名

`UuTakeoverController` 将网络选择、进程变化与资源恢复同 Windows 收发实现分开。`WindowsUuTakeoverPlatform` 复核进程映像与创建时间，保留进程句柄；只对所选虚拟地址以外的 UU 显式绑定施加临时限制。套接字观察、IP 头统计与驱动启动在独立工作线程执行，状态接口只读取快照。启用状态与当前工作状态分开，失败后撤下限制并有界重试。

设备设置使用独立版本前置条件及可查询操作 ID；其他设置保存、旧网络配置写入和事务回滚不得覆盖此选项。WebUI 的开关与网络选择单独自动保存，运行状态原位更新，保留设备名与日志草稿。代码与文件更名不改已有的服务、数据目录、DPAPI 标签及配对线格式；MSI 在事务内先移除旧组件再注册新文件，避免旧服务组件在升级末尾删除已注册的新服务。

针对检查：`dotnet run --project tests/ConWU.UuTakeoverTests -c Release -p:StreamLinkPersonalFeature=true`，以及 `node scripts/Test-UuTakeoverUi.cjs`。前者使用隔离配置与可注入平台覆盖授权、版本冲突、排队进度、进程变化和资源恢复；后者通过真实隔离后台验证保存和草稿保留，流量元数据由测试构造。真实 UU、WinDivert 和两机路径证据另存本地忽略目录，不由界面测试宣称验收。

目录用途：`installer` 保存 MSI 界面，`packaging/linux` 保存 Linux 安装入口，`third-party` 保存官方网络组件的头文件及许可。根目录 `CMakeLists.txt` 与 `Directory.Build.targets` 分别管理原生和 .NET 构建，`.gitattributes` 保证 Linux 脚本的换行格式，不能按文件年代删除。

早期自研内核驱动、旧 CLI、独立协调部署脚本和旧版本打包工具已退役；对应代码可通过 Git 历史查阅。`tests/ConWU.HttpsPoc` 保留早期独立实验，实际 TCP/HTTPS 承载为 `StreamMeshTransport`，由 `ConWU.StreamTransportTests` 覆盖。

`scripts/Test-StreamDesktop.py` 以台式为监听端、笔记本为发起端，使用测试程序的生产传输及加密 MeshLink 回声，不打开日用 TUN、不读取生产配对凭据。临时密钥只经进程标准输入传递，服务器端有独立存活上限。支持回环、EasyTier 管理地址或台式公网入口；结果包含实际交付码率、是否达到目标、排空时间、尾延迟、CPU 与 TLS 版本，不把成功握手当作大码率达标。回声窗口有界，窗口自身也可能限制高 RTT 下的码率。

发布附件包含对应源码、SBOM、哈希和验证范围。版本标记为正式版，不代表所有网络、八台设备或长期稳定性矩阵都已覆盖；具体以版本说明为准。


## TCP／HTTPS 按流分离连接

网络设置 `StreamFlowLanes` 默认关闭，主机启用后由批准配置传给从机。修改开关重连原网络，不重建身份、虚拟 IP 或配对；从机可声明能力，实际启用仍由主机策略决定。设置仅在 TCP／HTTPS 显示，FakeTCP 与 Phantun 不使用扩展。

`StreamMeshTransport.Flow.cs` 将一个主连接和两个辅助连接绑定到同一稳定本机入口。CWF1 控制记录使用批准成员共享密钥派生的 HMAC，绑定网络、双方槽位、模式、方向和双向随机挑战；辅助连接必须绑定活跃主连接，重新核对当前批准成员，拒绝重复槽位和旧挑战。HTTPS 的每条连接都单独校验已批准公钥指纹，首次配对不开放分流。旧协议的 TCP 长度帧、WebSocket 子协议与批处理协商保持不变。

SLM4 的保留字节 7 中，0 维持原协议，1–3 只用于协商后的业务数据；每条业务通道使用独立 HKDF 上下文、计数和 4096 包防重放窗口。Router 仅在精确匹配的进程内已认证 stream 路由上允许扩展。共享监听的回环代理使用网络绑定、按所有者退役的别名，不另建候选路径。退出一个网络会关闭它的主／辅助连接，保留其他订阅。

按流分类采用固定映射：Sunshine 默认控制端口 47999／48010、音频 48000、视频 47998 分开；未知流按有方向的五元组散列，分片按 IP 对和协议固定分配。自定义 Sunshine 端口无法保证按媒体类型分开。启用多连接时通过主连接 FIFO 标记与确认排空旧业务；辅助失效后关闭对应旧读写、经主连接确认，再继续单连接发送该流；本机交付与退役确认同步，避免旧读任务越过确认。控制确认超时会走正常重连，防止有心跳却一直不释放业务。切换不重新派生已有 MeshLink 会话密钥或重置序号。

每会话总应用队列预算 256 KiB，其中 24 KiB 留给协议控制；视频通道最多排队 176 KiB。拥塞时拒绝新业务并在状态和 `StreamFlows` 日志中计数，本机交付采用非阻塞发送并独立记录拒绝，不阻塞 Router 心跳。独立 TCP 重传、内核缓冲和 TLS 仍有各自开销，分流不保证提升视频吞吐，也不能避免单条视频 TCP 本身的队头阻塞。监听器最多保留 80 条连接，未认证连接最多 16 条，已协商分流组最多 16 组；辅助不另开 UDP 公网入口。

针对回归：`dotnet run --project tests/ConWU.StreamTransportTests -p:StreamLinkPersonalFeature=true -- --flow-lanes`。`scripts/Test-FormalFlowNamespaces.py` 使用同一测试程序的 `--formal-flow-node`，测试完整 Router／共享接收器／承载路径，只有网卡和负载是合成的；在独立 namespace 中限速和注入丢包，关闭 TSO/GSO/GRO，结束后回收 namespace，不操作生产服务或配置。

## TXT 入口恢复

正常连接通过系统 DNS 更新 TXT，Windows 查询绕过本机答案缓存。已批准的对端在启动或断线后未连通时，恢复解析同时通过 HTTPS 查询 AliDNS、腾讯与 Cloudflare 的 DNS 服务；只发送已配置 TXT 域名的 DNS 问题，不发送入口标签、URL 令牌、网络身份或配对密钥。不修改整机 DNS，单标签与常见私有 DNS 后缀不发送给公共恢复服务。

HTTPS DNS 使用固定地址上的 DNS wire-format POST，不使用代理或重定向。连接超时为 2 秒，每批备用查询最多 3 秒，响应上限 8 KiB；检查响应类型、事务、原问题和报文边界。各后端独立筛选指定标签和协议，再交错合并最多 8 个候选，保留系统答案，不让一个后端占满全部名额。恢复时优先尝试不同于系统答案的候选，所有入口仍需通过原有成员身份与双向认证。

备用查询失败时继续使用系统答案；只有备用后端提供了有效的指定记录时，才将等待系统查询的总时长限制到约 3.5 秒。没有有效备用记录时保留原系统查询预算。健康连接恢复后停止额外 HTTPS DNS 查询，使用用户保存的普通更新间隔；不会因新的 DNS 候选直接撤销已认证健康路径。

多网络共享读取按完整来源、协议与恢复状态区分缓存，普通系统查询不能遮住同一秒内的恢复查询。每个订阅者独立取消等待，退出一个网络不会取消其他网络共用的解析。长期离线仍使用约 18 秒的有界尝试窗口，空闲重试从 5 秒递增，最多暂停 30 秒；地址变化、上线信息与手动重试可唤醒等待。

运行入口按当前保存配置绑定到对端；该对端存在配置来源或已认证 PKARR 绑定时，不再合并首次配对地址及旧的入网来源。配置取代历史观察不依赖当次解析成功，避免订阅故障时重新尝试过时端口。本机入口不会取代对端引导地址；没有替代来源的手动直连继续保留必需的种子。服务启动时重新整理已配对网络的派生入口缓存，不更改保存设置、网络身份和入网历史。`--entry-source-authority` 覆盖来源替换及旧缓存重启迁移，`--entry-restart-recovery` 覆盖实际加密回环中的订阅端口变化及自动复连；二者均不操作已安装服务。

针对回归：`dotnet run --project tests/ConWU.MeshConnectionTests -c Release -- --txt-recovery-only`，覆盖旧系统答案、备用后端意见不一致、标签与协议隔离、超时与取消、共享查询以及真实加密回环传输。`--resolve-entry-recovery txt://域名#标签` 只验证实际恢复解析，不启动原生传输、修改设置或操作已安装服务。

## 主机端口与可选数据报承载

`UpnpMapping` 在 STUN 前申请直接公网 IGD 租约，不依赖 STUN 上线。优先请求与本机接收端口相同的外部端口，遇其他所有者最多另选三次，均不覆盖原规则。租期 180 秒、正常续租间隔 60 秒；失败按 5–20 秒重试，租约过期、源地址消失或 WAN 变为私网后撤下候选。网络唤醒请求立即复核。删除前核对完整规则与随机描述。更新已有规则失败不能仅凭“原规则还在”就延长本地有效期。

直接 IGD 不可用时，TCP／HTTPS 与 FakeTCP 复用 `GatewayMapping.CreateTcp`：独立保留本网络的实际探测源端口 P，本层映射 P → 接收端口 Q，公网候选取自 P 的同一 STUN 连接。源端口占用时使用实际分配的新端口，不改接收端口，也不把外层公网端口当作本层 IGD 端口。网关工厂失败并回收资源后，`StreamMapping` 才观察 Q 自身的 TCP STUN 候选，这条回退不再猜测或申请内层规则。独立 PCP/NAT-PMP 仍由设备本地 `PortControlMapping` 授权，端口设置可开关；该权限不随主机批准配置强制传给从机。已有入口模式不走自主映射工厂。

`ConWU.StreamTransportTests --mapping-gateway` 使用回环 TCP、STUN、SOAP 与转发器验证外层端口、本层探测端口和接收端口均不同的链路，覆盖 TCP／HTTPS 收发、证书校验、源端口占用、外来规则保护、观察恢复与取消清理。`Test-StreamDesktop.py --autonomous` 验证正式默认工厂；`--gateway-helper --source-port <端口>` 可独立对照探测端口映射路径，两者均使用临时身份、独立接收端口和短期租约。

`conwu-raw` 是独立 GPL-2.0-only 进程，实现 Mimic 和 TCPRAW；MIT 主程序通过通用回环数据报与进程事件 ABI 调用。`PacketCarrierTransport` 复用 Phantun 的进程所有权、能力预检、共享接收器及驱动生命周期。原 Phantun API 保留，原组件仍独立运行。打包须携带三个原生承载、锁定 Cargo 依赖、GPL 与 TCPRAW MIT 声明以及对应源码；`Build-Phantun.ps1` 现在构建完整 workspace。

Mimic 按其零填充线格式旋转数据的前十二字节，自己处理握手、窗口更新和保活；数据 PSH 兼容原版接收逻辑，并减少用户态捕获前的 GRO 合并。TCPRAW 先绑定真实系统 socket 完成握手，再直接发送原始 TCP PSH 数据报；系统 socket 在握手后设置 TTL=1，由窄 WinDivert/nft 输出规则抑制，其读取端只排空系统缓冲。Linux 接收监听使用 SO_REUSEADDR，关联使用零 linger，避免抑制 FIN 后端口不能立即复用。业务不写入 TCP 字节流，也不进行外层数据重传或重排等待。

主进程持有捕获资源、规则与子进程。Mimic 继续独占源端口；TCPRAW 启动前释放临时端口探针，由子进程真实绑定并回报同一端点。每端最多 128 个连接，新增连接每秒最多 16 个，桥队列最多 512 项，未完成握手最多十秒。失败、退出与父进程死亡均释放资源；数据格式错误或短时发送容量不足不杀死其他网络的监听。完整 MTU 的边界见[后续计划](后续计划.md)。

针对验证：`ConWU.PhantunTests --native <组件目录> mimic`（或 `tcpraw`）；`Test-PhantunNamespaces.py --carrier mimic|tcpraw` 覆盖正式配对与多网络隔离；`Test-RawCarrierInterop.py --carrier mimic|tcpraw --host linux|windows --output <目录>` 使用 Windows 与 WSL 的内存网卡。后者可显式加 `--standard-wsl-mtu`，仅临时将开发 WSL eth0 设为 1500，结束后恢复原值；不修改 Windows 物理网卡、路由器、生产服务或配置。跨平台验证不等同于原版 Mimic/tcpraw 二进制互通，也不等同于公网抗 QoS 或实际 Moonlight 验收。
