# 协调服务与升级

ConWU 默认在设备上提供独立的协调能力。需要自行掌控入口发现时，在网络设置的高级选项中选择“自建协调服务器”，填写实际可访问的 HTTPS 地址。第一次配对仍使用 16 位直连码。

## 监听与访问

新安装默认生成本机 HTTPS 证书并监听 `https://0.0.0.0:47822`。访问时使用设备的可达 IP 或域名，必要时配置证书 SHA-256 指纹；`0.0.0.0` 仅表示监听范围。也可以沿用自己的 HTTPS 反向代理或 Tunnel。

协调服务开关、监听端口与可选证书位于 WebUI 左侧“对外协调”，通过“本机协调设置”编辑，和每条网络选用的发现方式分开。证书和私钥同时留空时使用本机自动管理的证书。已有的监听地址、证书、反向代理及信任设置在升级时保留。HTTP 协调只允许回环监听，公开访问需要 HTTPS。监听失败只影响协调能力，不应阻断 PKARR、已有入口或本机管理。

协调设备不自动加入使用它的网络，也不转发串流。多个网络可以使用同一台协调设备；网络身份和凭据分别校验。设备可以同时提供协调服务、创建网络和加入别的网络。

本机 WebUI 默认监听 `http://127.0.0.1:47821/`。Linux 的域名管理需要显式配置密码认证，见 [Linux 安装与使用](../packaging/linux/README.md)。协调接口本身不提供管理权限。

## 备份与恢复

Linux 可以查看协调状态：

```sh
sudo conwu coordinator status
```

先在“对外协调”关闭本机协调服务，确认没有其他程序写入同一协调数据目录，再进行离线维护。

```sh
sudo conwu coordinator backup /安全目录/coordination.slcoord
sudo conwu coordinator inspect /安全目录/coordination.slcoord
sudo conwu coordinator restore /安全目录/coordination.slcoord --confirm-rollback
```

维护命令与后台使用同一把目录锁。备份包含协调注册记录、清单和校验信息，不包含设备私钥、TLS 私钥、本机设置或内存中的临时配对房间。它不能替代完整的本机设置备份。恢复旧备份可能回滚后续审批和撤销记录，因此要求显式确认。

原独立协调数据可以通过维护命令的 `--data <目录>` 参数迁移。迁移前停止旧写入者，保留原 HTTPS 域名、代理目标和信任策略；先校验备份，再恢复到新设备的协调目录。不要把管理端口或业务接收端口当作协调入口。

## 软件更新

主从两端应使用兼容的新版本。Windows MSI 和 Linux 安装器保留同语义的设置和网络身份；旧单网络格式无法直接加入当前双机网络时，按提示重新建立。升级不会把旧 UDP 网络静默转换成别的协议。

Windows MSI 安装版在设置中检查官方正式版，先下载完整安装包并校验哈希，用户确认后交给受保护的独立原生更新程序。本机安装不依赖远程会话或原后台继续运行；完成后恢复服务、原先启用的网络和普通用户托盘，不强制重启。对端离线时保留原配置等待重连。Linux 继续检查更新并人工部署。

三机维护只保留当前版本和上一版本的一套回退程序及匹配设置备份。新版验证正常后清理重复安装包、上传暂存和测试临时文件；生产设置、证书、网络身份及用户日志保留。回退前停止服务，恢复原程序与对应的受保护备份。
