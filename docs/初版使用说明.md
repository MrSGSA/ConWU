# StreamLink 0.2.0 Windows 预览版

原生 Windows 双端 P2P 组网，内置 udp2raw、EasyTier、WinDivert、Wintun 和 .NET 运行时，无需预装 Lucky、EasyTier 或 WSL。软件提供虚拟 IP 和连接状态，应用用途由用户决定。

## 首次配对

1. 两台电脑解压完整安装包，保留 components 目录，以管理员权限运行 StreamLink.exe。
2. 任一端点击“创建网络”。程序安装自己的 Windows 服务并开始探测，点击“复制配对邀请”，通过可信渠道交给另一端。可以在校园网一端创建，不要求创建端具备公网入口。
3. 另一端把 SL2. 邀请粘贴到加入框，点击“粘贴邀请后加入”。程序自动选择可以提供映射的一端，完成实际握手后显示“已直连”。
4. 创建端固定虚拟 IP 为 **10.129.129.1**，加入端为 **10.129.129.2**。入口方向变化不改变这两个地址，双方都能发送和接收业务。
5. 任一端可点击“测 50 Mbps”，测量对端向本机发送 20 秒数据的接收质量。测速会占用带宽，避免与重要业务同时进行。
6. 在需要的应用中填写对端虚拟 IP 和该应用端口。软件不要求安装 Sunshine/Moonlight，不接管默认网关或全局 DNS。

邀请首次导入有效期 24 小时，包含配对秘密，只交给授权设备。导入后保存为持久配对，邀请过期不影响原配对。再次开机无需重新交换地址。当前每台电脑只管理一组双端配对；新建或加入另一网络会替换原配对。0.1.x 的 SL1. 邀请不能直接导入，升级后首次创建一次 SL2. 配对即可。

## 后台运行与停止

**关闭窗口继续组网；点击“停止网络”才断开。** 服务注册为 LocalSystem 自动启动，并保存上次的启动/停止意愿，不依赖登录桌面。GUI 只是管理入口，当前仍需管理员权限。

程序安装到 C:\Program Files\StreamLink\0.2.0，配置与诊断在 C:\ProgramData\StreamLink。配对配置使用机器级 DPAPI 加密，目录只允许管理员和 SYSTEM 访问。安装文件普通用户只能读取执行。

正常停止会清理自身组件、防火墙及路由器租约。点击“移除后台服务”停止并取消服务注册，保留程序、配置和日志以便恢复；这不是删除所有文件的卸载器。退出不卸载其他软件可能共用的驱动。

## 连接偏好与 STUN

“连接设置”提供自动、优先本机入口、优先对端入口三种策略。实际直连后记住成功方向，偏好不等于强制选择不可达端点。

TCP、UDP STUN 分别按每行 主机名:端口 编辑，可增删、导入导出 JSON；只导出列表，不导出配对密钥。当前默认内置公共 STUN 地址并非从 Lucky 闭源配置导出。最近成功的 TCP 服务器优先尝试，失败后顺序回退。

当前稳定传输使用 FakeTCP + 明文 HTTP 特征。UDP 列表作为后续实验配置保留，修改它不会把默认链路切成 UDP。此次网络的原生 UDP 与 UDP/STUN 形态仍受约 6 Mbps 限速，未发现可替代 FakeTCP 的纯 UDP 绕过方法。

高级用户可填写已有 Lucky 的公网 IPv4:端口，并将本机传输端口设为该规则直接转发的目标。此时由原工具维护映射；手填端点不自动读取 Lucky 地址发布网页。默认软件自己的 TCP STUN + UPnP 路径不依赖 Lucky。

## 发现服务

安装包已配置用户提供的服务器。发现服务只交换加密的端点公告和连接状态，业务始终经过两端 udp2raw 直连；不存在自动业务中继回退。已建立的直连在发现服务暂时离线时继续运行，首次发现或获取变化后的端点需要服务恢复。

“发现服务设置”用于自托管地址，必须使用 HTTPS。正规受信任证书可留空指纹；自签证书需显式填写 SHA-256 指纹。修改后只用于新建配对，既有配对保持原服务器。运维与迁移说明见“发现服务运维.txt”。

## 网络条件与已知边界

- 任一端通常需要可用 UPnP 路由器，以及允许另一端访问所发现 TCP 映射的上游 NAT；另一端可处于严格 NAT。STUN 返回公网地址不等于已连通，界面以实际对端握手为准。
- 当前采用 TCP STUN 保活加路由器直接转发，不是覆盖所有 NAT 的 TCP simultaneous-open。双方均严格对称 NAT、网关不允许自动转发时不保证直连；不悄悄改用中继。PCP/NAT-PMP、完整 UDP 打洞协调与多节点组网尚未实现。
- 固定使用 10.129.129.0/24，若冲突则拒绝启动。本预览版未提供任意网段选择。
- HTTP 特征不等于 HTTPS/TLS，不能承诺永久绕过运营商 QoS。发现服务自身使用 HTTPS，与业务传输伪装是两件事。
- 在现有两台机器已验证 Session 0 后台运行与服务重启恢复；没有为测试重启整台机器或注销正在使用的桌面，因此未将其写成真实冷启动未登录验收。
- Thinkbook 本轮部分虚拟网卡初始化或端点重连耗时约 30–55 秒，尚未达到 Lucky 单独发布映射的启动速度。映射发现和完整虚拟网卡就绪是不同阶段。
- 包含官方签名驱动，应用本身尚未签名。本轮复用两台机器已有兼容驱动，全新 Windows 与各类安全软件组合仍需验证。

## 回退

先在 0.2 点击“停止网络”，需要时移除后台服务，再运行保留的 0.1.1 或原 PoC。不要同时启动占用同一虚拟网段或映射端口的两套测试。生产 Lucky/EasyTier 配置、默认路由、DNS 和 WSL 未被本版接管。
