# StreamLink 0.3.0 Windows 预览版

提供两台 Windows 之间的虚拟 IP 和 P2P 网络。完整包包含 udp2raw、EasyTier core/cli、WinDivert、Wintun 和共享的 .NET 运行时，不需要预装 Lucky、EasyTier 或 WSL。组网后的应用用途由用户决定。

## 首次配对

1. 两端分别解压完整包，以管理员身份运行 StreamLink.exe。不要只复制 EXE；同目录 DLL、components 和 manifest.json 均需保留。
2. 两端打开“设置 → 协调服务器”，选择自定义服务器，填写同一个 HTTPS 地址并保存。公共服务器目前仅为占位，没有默认接入点。使用正规 HTTPS 证书时，证书指纹留空。
3. 任一端打开“创建网络”，点击创建，取得 **6 位配对码**，有效期 **5 分钟**。另一端在“加入网络”输入短码，明确点击“加入网络”；输入或粘贴本身不会提交。
4. 两端会显示另一个 **6 位校验码**。通过已信任的聊天、电话等方式核对；一致后，由创建端点击“校验码一致，允许加入”。不一致或不是自己的设备时，拒绝并换码。
5. 软件自动选择公网入口。实际握手完成才显示“已直连”。创建端虚拟 IP 为 **10.129.129.1**，加入端为 **10.129.129.2**，两端都能收发数据，创建端不一定承担公网入口。
6. 配对自动保存，下次直接启动。需要验证带宽时，点击“测试连接质量”：测量对端向本机发送的 20 秒、50 Mbps 数据。测试占用带宽，空闲时运行。

配对码只定位临时房间，不作为长期密钥。双方临时 P-256 ECDH 公钥先承诺再揭示，通过校验码确认，并用 AES-GCM 传递随机长期配对秘密。创建端批准后短码立即作废；未批准的房间到期删除。当前协议仍需进一步独立安全审计，不应省略校验码核对。

每台电脑目前只管理一组双端网络；创建或加入新网络会替换原配对，程序会先提示。不是多节点 Mesh。邀请房间只存在于本次界面会话，退出或换码会撤销；已保存的网络不受配对码过期影响。

## 前台、托盘与可选服务

首次运行不会自动安装服务。无服务时，连接由程序维护；默认关闭窗口后留在右下角托盘，双击图标恢复。托盘菜单“退出界面”在前台模式下会断开连接。可在设置关闭托盘常驻，此时关窗即停止前台连接。

需要无人登录自动组网时，在“设置 → 后台与托盘”点击“安装后台服务”。安装或更新会切换当前连接；服务保存上次的启动/停止状态。服务模式下关闭界面继续组网，要断开请点击“停止网络”。安装、更新、卸载仅由这些明确操作触发。

点击“卸载后台服务”会停止网络、取消服务注册，保留配对和日志，界面转为前台模式。它不删除所有安装文件，也不卸载可能被其他软件使用的驱动。

安装目录为 `C:\Program Files\StreamLink\0.3.0-<包标识>`。持久配置位于 `C:\ProgramData\StreamLink`，使用机器级 DPAPI 加密并限制管理员/SYSTEM 访问。桌面偏好在 `%LOCALAPPDATA%\StreamLink\desktop.json`，仅包含服务器地址、指纹和托盘偏好。当前 GUI 仍需管理员权限。

所有耗时操作都会显示“正在…”和进度提示，暂时禁用相互冲突的按钮；完成或失败后恢复，防止重复点击。

## 设置

- **打洞方式**：TCP 映射 + FakeTCP 为推荐模式；UDP 映射为实验模式。用于新建网络，加入端跟随创建端，改变选项不改现有配对协议。当前自动映射需要合适的 UPnP 网关与上游 NAT，UDP 选项不是完整的 EasyTier 多类 NAT 打洞移植。
- **组网传输**：当前只有 UDP2RAW；其他方式以后再加入。FakeTCP 保留明文 HTTP 特征，不是 HTTPS/TLS，不引入标准 TCP 有序重传。
- **STUN 与端口设置**：可增删 TCP/UDP 列表、导入导出、设置入口偏好、端口和已有 Lucky 公网端点。内置 pradt2/always-online-stun 的 TCP 列表快照，可点击“补充社区 TCP 列表”联网补充，检查后保存。公开可用不等于本地一定可达。
- **日志与设备**：设备名、关闭/错误/常规/详细日志及目录。主界面没有实时日志大框，点击“显示日志”打开当前日志快照。日志可能包含端点地址，分享前检查。
- **关于**：访问 GitHub、检查更新。当前仓库私有，未授权 API 查询可能返回 404；届时按提示登录 GitHub 查看 Release。软件不内置个人 GitHub 凭据，也不自动替换程序。

设置中的“协调服务器”就是交换配对信息、更新公网地址的服务器。它不转发业务数据，因此没有标为会中继流量的“中继服务器”。更换服务器地址仅用于之后的新配对，已保存网络仍使用原地址；两端要迁移时，在同一新地址重新配对。

## 从 0.2 升级及回退

保留旧包，并将原 `C:\ProgramData\StreamLink\profile.dpapi` 在同一受保护目录内备份后关闭旧界面，解压新包运行。已有 0.2 服务和 FakeTCP 配对可继续工作；如要使用新版 UDP/日志/STUN 配置，先在设置点击“更新后台服务”。该动作会短暂切换连接，新包验证和复制成功后才停止旧服务。

不要仅为升级重新创建网络。原配对会保留；但迁到新的协调域名时，需要双方填写新地址后重新配对。旧版长邀请仍在底层兼容，新界面不再要求用户操作它。

要回退，先停止网络并卸载新版服务，退出新版界面，恢复此前的 profile.dpapi 备份，再从保留的 0.2 包运行 `StreamLink.exe --install` 安装旧服务。0.2 不支持新的 UDP 配对和超过 64 项的 STUN 列表；不能假设任意新版配置均可直接降级。不要同时启动占用同一虚拟网段或映射端口的两套程序。

## 网络条件与边界

- 一端通常需要 UPnP 路由器直接转发及允许入站的上游 NAT，另一端可以处于严格 NAT。STUN 返回公网地址不代表已连通；以实际双端握手为准。
- 不保证双方严格对称 NAT 的连接，不进行业务中继或静默 TCP 回退。PCP/NAT-PMP、完整 UDP 打洞协商和多节点组网尚未实现。
- 固定使用 10.129.129.0/24，冲突时拒绝启动。不接管默认网关、全局 DNS、Lucky 或原有 EasyTier 配置。
- HTTP 特征对运营商 QoS 的效果取决于具体网络；历史纯 UDP 实验未绕过约 6 Mbps 限制，不能把 FakeTCP 实测效果推广到 UDP 模式。
- 当前版本保留已经验证的原生传输二进制。0.3 的验收主要覆盖界面、配对和控制生命周期；不能将 0.2 的 50 Mbps 零丢包记录写成 0.3 已重新完成公网性能测试。
- 全新 Windows 的首次驱动安装、冷启动未登录、休眠换网、长期运行及不同路由器仍需扩大测试。应用 EXE 尚未签名。
