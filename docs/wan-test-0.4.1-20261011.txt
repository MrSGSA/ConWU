StreamLink 0.4.1-preview 双端公网实测与使用说明
时间：2026-10-11 09:52–10:05，Asia/Shanghai

结论
两台真实 Windows 已通过自主 Wintun + MeshLink + 原生 udp2raw FakeTCP /
明文 HTTP 的公网直连验证；默认新版路径没有使用 EasyTier 组网后端。
两个方向分别 50 Mbps、20 秒，接收均接近目标速率，序号统计均零丢包。
本次不需要手工 Lucky 测试入口：Akane 自行 TCP STUN + UPnP 映射，
Thinkbook 从校园网主动连接。它验证的是至少一端入口可达的组合，不能
据此宣称双端随机对称 NAT 的 TCP 同时打开已实现。

二、测试隔离与路径确认
使用 MeshHarness 调用产品 MeshRunner，在两端分别加载独立成员凭据、
配置目录与原生网卡。测试源端口 42791，Akane UPnP 转发到 42780；
旧 Lucky / StreamLink 入口未修改。Thinkbook 的物理以太网协商为 1 Gbps。

独立协调实例只绑定旧虚拟 IP 的 HTTPS 42869，校验专用证书，只传递
控制公告。没有升级正式公网协调服务，没有新增 VPS 数据转发或中继。
测试控制面依赖现有虚拟网络，不能将本轮启动耗时直接等同正式域名部署。

已确认新测试 IP 的 /24 路由指向新 Wintun，udp2raw 使用物理接口与对端
公网 TCP 元组。正向三档测量期间，新网卡收到 179,064,857 字节，旧网卡
仅收到 20,972 字节、发出 82,792 字节。结合路由、进程与流量统计，业务
通过新版公网直连路径，没有绕回旧 EasyTier 网络承载。
另以新虚拟 IP 作为 SSH 源和目标，成功连接 Akane 并返回主机名。

三、吞吐与丢包
每包 UDP payload 为 1200 字节，两个方向依次测量，不是同时双向满载。
Quality 测量按包序号去重，接收结束报告后留 1 秒收尾，再计算丢包；
Mbps 为收到的 UDP payload 字节数除以设定发包时长，不含外层协议开销。
它不测每包截止时间，因此零丢包不等于没有迟到帧或已完成游戏长稳验收。

负载期间 24 次 ICMP ping：24 发 / 24 收，最小 13 ms、最大 15 ms、平均
14 ms。此为小样本 RTT，不是 UDP 抖动、单向延迟或 p95 的统计结论。

四、恢复和控制故障
1. 双端初次启动：Thinkbook 从测试进程开始到已直连为 19.500 秒；Akane
   为 17.391 秒。两端启动相差约 2.3 秒，不能当作同起点的竞速比较。
   Akane TCP STUN + UPnP 租约复核在 778 ms 完成，本机入口就绪 1372 ms；
   Thinkbook 网卡就绪 3998 ms。入口发现不是剩余全部耗时的解释。

2. 单个新版 udp2raw 子进程退出：只结束匹配测试路径与父进程的实例。
   自动生成新进程，Wintun 接口索引保持不变。结束旧进程后 5.271 秒
   首次 ping 成功，随后短暂仍有 3 次超时；整个 24 次探测窗口共 14 次
   超时。因此 5.271 秒是首次恢复回包，不是已证明完全稳定的恢复时刻。
   后续正常 ping 与吞吐再次成功；旧 0.3.2 进程未结束。

3. 协调不可达：临时规则仅阻断 Akane 访问本轮 HTTPS 42869，日志确认
   8 秒请求超时。已建业务路径仍完成 Akane → Thinkbook 的 50 Mbps / 20 秒：
   104103 发 / 104103 收，49.96944 Mbps，零丢包。随后规则已移除。
   这是单端控制访问故障，没有模拟双方控制面同时失联或服务器整体停机。

4. 完整停止并重启 Thinkbook 新版测试进程，Akane 新版保持在线：
   从新进程启动到已直连 18.891 秒，其中网卡就绪 8.414 秒。后续 6 次
   ping 全部成功，14–15 ms。这不是 Windows 重启或未登录服务启动。
   后续需补充网卡、防火墙、子进程和公告阶段计时，才可确定余下耗时。

额外观测：Akane 的 STUN 持续连接约每 62 秒断开重建，自动复核映射后
本轮业务继续运行。Thinkbook 未发现 UPnP，仍能使用对端入口；重复探测
期间出现过 DNS 查询取消及 AddressAlreadyInUse，后续候选重试恢复。
上述日志适合后续优化重试成本，不能单凭它们断言运营商或系统具体根因。

规则均为 0；临时 HTTPS 监听已停止，故障注入规则已移除。Akane 日志
10:02:37 确认删除本软件的测试路由器租约。两端原 StreamLink 服务仍为
Running，路径仍指向 0.3.2；原虚拟 IP ping 正常。
安装包、工具及实验结果保留在指定目录；实验凭据目录限制为本机管理员
和 SYSTEM。报告不含密钥或动态公网端点，配置原件不要作为报告分享。

六、后续优先级与部署要求
优先查清约 18.9 秒完整启动及传输退出后的恢复时延，再做多次重复测量；
随后验证长时间 50 Mbps、实际游戏、Windows 重启/未登录、休眠换网和
真实公网端点变化，最后增加第三台真实设备。八台上限未在本轮实机压测。
本轮没有纯 UDP 的同期对照，不能将结果归因为 HTTP 特征单独造成的改善，
也不能保证任意时段、任意运营商永久绕过 QoS。

正式升级还需要支持 meshProtocol:4 的协调服务，并在两端创建/加入
新版网络。0.3.x 配对不能直接用于新协议，不宜直接替换现用单端服务。
本轮仅传包及隔离测试，正式协调、系统设置和旧配置保持原状，无需回退。
未来迁移遵循 docs/native-mesh-0.4.txt，保留旧完整包及同机 DPAPI 备份。
