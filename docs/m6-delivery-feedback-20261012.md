# M6：认证路径送达反馈正式接入

开发基线 `d1d927f`。本次补齐实际承载上的认证接收计数，不使用协调服务或其他成员转发业务。**功能独立默认关闭；尚未启用AutoQuality或备用路径。已发布0.5.3与现用服务未改写。**

## 实现和授权

`QualityFeedback=1` 为独立成员能力，默认0字段从既有签名序列化中省略。需要本机设置、双方签名公告及协调服务独立支持；Attempt在创建时固定授权，正式Factory→Manager→Actor→Router接线。旧端/旧服务不分配反馈历史，也不发送新控制包。设置和IPC有独立版本，兼容模式会清掉不可见的实验选项。

每条实际保留路径使用现有MeshLink AEAD的kind7控制体，`SLD1`长度128B。范围绑定规范化的Network/成员/Boot/Attempt/候选上下文摘要、请求随机ID、数据发送AEAD epoch和实际起止序号。已有业务、HTTP/SEQ及MeshLink计数器不改；反馈与提名共享同一成员加密和重放状态，不创建另一套nonce分配器。

发送侧只统计该路径实际接受的数据报，记录完整内层IP包数/字节。接收侧只记录该路径经认证/重放/源目的检查、实际写入本机适配器的业务；不根据全局序号差推算数据量，因为全局序号还包含控制和其他路径。

约两秒一个有业务的范围，接收端等待至少一秒后取送达快照。报告带实际取样收尾时间；它测的是**接收截止时的缺口**，不是永久丢包、实时截止送达率或单向延迟。首次快照固定，重复请求回同一快照，不因重试提高已交付数或续期。

- 控制走全机维护账本；wire-aware原生在实际注入处计账，其他适配器用现有维护准入。每Router另有8次/秒、突发2的调度上限，只限制排程，不提供额外wire额度；原心跳先调度，peer按既有游标轮转。
- 每路径最多两个等待报告、四个未完成接收请求、总共八个接收缓存、最近三个报告；接收元数据环固定16384条（约256KiB），关闭功能不分配该环。只存序号/长度，不留业务内容。
- 请求/报告最多三次控制发送；报告只在首次和重复查询时发送，不定期制造无请求重发。控制入队计为QueuedControls，不能冒充物理线上发送。
- 超时八秒、历史不足、过长观察间隔、epoch/范围/摘要不符或计数越界均不给送达成功证据；反馈超时为Unknown，不记100%业务损失。
- 取消/退休/回退清掉pending与报告；保留旧序号水位，迟到范围不能复活比较历史。不同AEAD epoch重置对应方向历史；反馈只处理Active且已共同提名的实际路径。
- 不重传业务，不等待缺包后再交付，不因反馈不足中断健康路径或自动切换策略。

正式路径和成员状态增加`Delivery`，Runner日志把反馈范围与已有五秒本地窗口分开。原`Traffic.Qualification`仍为QualityUnknown；不把两个时间范围硬拼成一个质量结论。
