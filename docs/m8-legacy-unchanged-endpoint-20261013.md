# 对端地址不变时的兼容路径恢复

2026-10-13。继续 M8 兼容主线，保留 FakeTCP＋HTTP、单条有效路径及先认证后退役。未修改现用服务、驱动或网络配置。

原实现只在公开入口地址变化或传输报告进程退出时创建新客户端。已经选中过一个客户端后，如果进程继续存活但线路没有认证收包，地址不变就不会再创建替代。这不能覆盖 NAT 状态消失等“进程存活、路径失联”的状态。

本次复用 Router 原有健康判断与 12 秒窗口。已选中兼容传输失去健康、且仍有有效公告端点时，同一入口也能经过原尝试准入创建一个独立客户端；最多 Active＋Candidate。旧进程/适配器保持持有，替代必须返回本路径的认证挑战，随后才关闭旧传输。健康链路不额外申请尝试，失败替代仍按原超时/退避处理，不发布过期公告为新候选，不改成中继。

完整 TCP/兼容测试 81 项通过；独立恢复用例 10 项通过。该用例使用正式 Router/路径管理、真实回环 UDP 转发与内存 IP 适配器，旧传输故意静默但仍报告存活。其健康判断在静默后约 11.371 秒发生（最后认证包早于静默计时起点，原 12 秒窗口未缩短）。额外故意丢掉 1.3 秒挑战响应后，从准备替代到对端收到完整内层 IP 包约 **1725ms**。这个时间不是公网、真实 native 进程、Windows 休眠或稳定业务/目标吞吐恢复承诺。

原始产物：`artifacts/m8-legacy-alive-first-20261013.log`、`m8-legacy-alive-timed-20261013.json/log`。另有 222 项受管 Router、100 项 Windows/IPC 回归，以及服务/界面 Release 构建通过。默认兼容链路使用此健康触发；物理出口变化时本机监听/映射刷新、系统休眠和无人登录恢复仍需继续完善与实际验收。

第二轮准确来源 `41e5102` 的完整 Package 停在共享端点池负例：固定 180ms 取消可能仍处于新增事务准入等待，尚未产生部分查询。已把该负例改成先确认真实反射端收到一条请求，再取消；44 项端点池/七成员源共用/隔离检查通过。负例验证的是部分 I/O 后查询能力失效且旧 native 捕获仍可用；准入阶段取消不应污染字节流。首轮与第二轮完整 Package 失败分别保持在本地独立证据目录，未发布半成品。

打包流程把端点池、短窗口观察这类基础检查前置到长时间诊断之前，全部原检查与门槛保留；新准确来源仍须完整执行。相关代码、真实发布 Gate 与观测总账继续按 M0—M9 跟踪。
