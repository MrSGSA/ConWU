# M8：协调中断、反射查询失效与签名撤销

## 修复的行为

协调服务会在成员撤销后拒绝该成员的 watch，返回 403。原客户端把它作为普通 HTTP 故障重试，无法通过这个接口得到最新签名目录，被撤销的一端可能继续依赖旧的成员授权。

`MeshDiscoveryClient` 现在在 watch 403 后，把**下一次已经计入 Runner 请求预算的轮询**用于原有网络读取接口。先验证目录所属网络、管理员签名、版本不回退，再核对自己的完整成员身份；确认被移除后抛出 `MeshRevokedException`，由 Runner 正常停止和回收资源。

- 403 本身不是撤销证明，不直接拆除健康数据路径。
- 不在失败 watch 内偷偷增加 HTTP 请求，也不关闭长轮询/打洞能力或降级协议。
- 没有新增服务器接口，兼容当前提供网络读取接口的协调服务。
- 503、连接中断、伪造目录或旧的签名目录不能充当有效撤销。
- 保留“协调离线时按照已有合法授权继续”的边界；无法承诺离线时即时获知撤销。没有延长凭据有效期。

## 正式路径集成结果

新增 `--lifecycle-only` 入口，使用正式 `MeshCandidateFactory → MeshRunner → MeshLink`、实际 C++ 原生 worker、独占内核 TCP helper、真实回环 HTTPS。raw 包 I/O 和内层 IP 网卡使用内存适配器；未装驱动、未触碰现用网络。两端使用同一次提名的 Path/Lease/Attach，整个故障阶段没有重新 Gather 或替换握手。

协调故障通过独立测试服务中止实际 HTTPS 连接实现，包括已有长轮询。故障期间 TCP 反射和对等包路径仍可达；本实验**没有 UPnP/PCP/NAT-PMP 租约**，不能声称验证了 180 秒网关续租。通过 120 秒公告有效期后保持路径，只证明了当前保留授权及实际认证通信的组合。

这不是 50 Mbps 压测。每秒左右一组完整内层包用于生命周期断言；报告中的 `maximumDeliveryMs` 是本机测试投递耗时，不能解读为公网 RTT 或单向时延。只有一个开发设备、两个独立 Runner，不是两台 Wintun 真机，更不是八设备。
