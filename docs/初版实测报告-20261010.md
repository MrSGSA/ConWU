# Windows 初版与 UDP / FakeTCP 实测

本文记录 0.1.0 的公网测量。后续 0.1.1 调整通用组网定位、界面及双端测速，传输内核不变；其验证范围见发布包中独立的验证摘要，不把本文历史数据作为新版本再次实测的结果。

日期：2026-10-10。设备：Akane（Windows，山东移动 CGNAT）、Thinkbook（Windows，校园网）。方向：Akane 上行 → Thinkbook。测试与原生产 EasyTier/Lucky 隔离，使用临时端口及独立虚拟网段；控制命令通过原有 EasyTier SSH 执行。

## 结论

本轮已经交付原生 Windows 双端控制程序与中文界面，并在这两台电脑验证软件自行建立 TCP 映射、原生 udp2raw FakeTCP + HTTP 传输、内置 EasyTier 组网的完整链路。该链路 **50 Mbps / 180 秒，937435 个数据报全部收到，平均 49.996 Mbps**。不使用 WSL、Npcap、已有 Lucky 规则或业务中继。

UDP 直连已经建立成功，但两种 UDP 封装在当前路径都没有突破约 6 Mbps。因此首版采用自动 TCP 映射 + udp2raw FakeTCP；内层业务仍为独立 UDP 数据报，映射控制用的 TCP STUN 不承载串流数据。

## 自动 TCP 映射的实际实现

`TcpBinding.cs` / `TcpMapping.cs` 独立实现 STUN TCP Binding、完整流式读取、事务校验、保活及 UPnP。通过同一条 TCP STUN 连接每约 10 秒刷新，断开时重新连接；用短租约将来源端口转发到原生传输监听端口。规则每约 60 秒续期，180 秒过期，删除前核验规则所有权。规则冲突报错，不覆盖现有 Lucky 映射。

前一轮短连接探测 + HTTP 保活出现 Windows TIME_WAIT 和端点变化，导致旧端点连接失败；该次没有有效测速，不能计成“测速丢包 100%”。切换为持续 STUN 连接后建立稳定可用链路。程序并未实现任意双对称 NAT 的通用 TCP 同时打开，这里应称为 **自动 TCP 映射和直连**。

`StreamSession.cs` 将 EasyTier 只接到本地 udp2raw 的回环 UDP 端口，关闭其独立打洞、外部共享节点、UPnP 和 DNS 接管。检查对端身份、cost=1、next_hop=peer_id 和本地 UDP 连接后才显示“已直连”。公网业务由 udp2raw 直接发送。

## UDP 新实验与障碍

先尝试 UDP 探测源端口与 raw 传输端口分离。只读抓包证明数据仍到达探测端口，路由器的 UPnP 转发没有覆盖现存 UDP NAT 会话。修正为同一 UDP 端口共享绑定，并让 WinDivert 过滤器排除指定 STUN 服务器的回包，才让 .NET 保活和 raw 数据接收同时工作。

随后尝试加上 STUN/TURN Data Indication 报文形态（类型 0x0017、魔数 0x2112a442、XOR-PEER-ADDRESS、DATA 属性），内层仍保留 udp2raw 的认证/加密。抓包确认实际发出 IPv4 协议 17 和预期头部。此实验不接入 TURN 服务器，不是中继，也不构成完整 TURN 协议实现。[RFC 8656](https://www.rfc-editor.org/rfc/rfc8656.html)

两种封装均能连接但持续被限制在约 6 Mbps。与同期 FakeTCP 高速结果及之前普通 UDP 对照一起，这支持当前路径存在对 UDP 特别不利的分类/整形；尚不能仅凭端到端结果定位运营商设备，也不能证明所有可能的 UDP 协议特征均无效。

## 已验证与待验证

已验证：原生双端服务/客户端、独立映射和组网、50 Mbps 持续数据通道、程序内置授权测速、协议丢包后继续交付、Windows 子进程 Job 清理、过期会话清理与活跃会话保护、邀请校验。C++ 协议回归 9 项，.NET 校验 18 项。

发布前回归遇到一次测试代理线程因 Windows 启动期间的 UDP ICMP 不可达报错而退出；修复测试代理对该异步错误的处理后，9 项协议回归全部通过。保留协议就绪超时和进程健康检查，没有跳过失败用例。

发布程序还完成了停止后重新加入，虚拟地址 ping 4/4 成功，约 16 ms。中文界面在 250% DPI 下离屏渲染检查；跨机器业务验证通过 CLI 调用与界面共享的会话控制代码，没有声称自动点按完成所有 GUI 流程。

09:00 前的清理审计确认：两端没有本轮测试组件、`StreamLink-*` 防火墙规则或 10.129.129.x 地址/路由残留；41391、41392、42691、42791、42780、42880 的临时 TCP/UDP 路由器映射均为空。原 EasyTier 网络 10.126.126.2 可达，Akane 原有 Lucky、EasyTier、Sunshine 进程仍在。本轮没有修改生产配置、默认路由、DNS 或 WSL，也没有升级/卸载已有驱动。

本轮未自动启动 Moonlight 游戏，不将吞吐测试写成实际游戏体验。新软件的晚高峰、小时级游戏、视频峰值、断网休眠恢复以及从未安装过驱动的干净 Windows 尚待验证。HTTP Host 的因果作用尚未证实，也没有 TLS/HTTPS 隧道。最初成功 PoC 的用户实玩反馈属于旧包，应与本轮原生实现分开记录。

预览交付为完整便携 ZIP、中文界面、邀请配对、内置测速、日志和停止清理。尚没有短码发现服务、持久设备身份/DPAPI 密钥库、完整安装器、自动升级、多节点 Mesh 或无感换网恢复。

## 路线选择

当前推荐使用已经达到目标的自动 TCP 映射 + 原生 udp2raw FakeTCP，将 UDP 分类实验保留为研究入口。接下来优先做用户实际 40/50 Mbps 串流与长时恢复验证，再扩展 NAT 兼容、发现服务和安装体验。若当前网络不支持自动映射，可导入已有 Lucky 直达映射；仍失败时回到原可用 PoC 或真实 TCP P2P，不悄悄切换中继。

## 0.2.0 服务化与发现服务补充（2026-10-10 下午）

本节是新一轮测试，前文为 0.1.0 历史记录。新增 Windows 服务、持久配对、自动入口选择、STUN 列表管理，以及在用户授权服务器上的 HTTPS 发现服务；未修改 udp2raw 原生数据面代码。

Thinkbook 创建网络（槽位 1 / 10.129.129.1），Akane 加入（槽位 2 / 10.129.129.2）。Thinkbook 无可用 UPnP 网关，自动选择 Akane 的自研 TCP STUN + UPnP 映射作为入口。没有复用生产 Lucky 映射。两端服务以 LocalSystem / Session 0 运行，SSH 退出后继续组网，组件由服务 Job 管理。

开发版服务链路 50 Mbps、20 秒：49.98528 Mbps，104136/104136 包，0% 丢包。该测试是 Akane → Thinkbook，RTT 状态采样约 15–16 ms；不是新的 180 秒长测。停止独立发现服务后，对端虚拟 IP ping 20/20 成功，发现服务恢复无需重新配对。

把 Akane 的独立源端口 42691 改为 42791，再恢复为 42691：发现服务发布新候选，Thinkbook 自动停止旧传输并按新端点重建，虚拟地址保持 .1/.2。服务重启保留配对身份、启用意愿、最近成功入口和 STUN 项。Thinkbook 一些虚拟网卡初始化/重连约 30–55 秒，尚未优化至开机立即可用。

核心检查 35 项，另有公网发现检查 5 项（认证、过期、槽位占用、版本与证书），真实 SCM 服务检查 12 项（连续完整响应、服务 PID 验证路径、过大消息拒绝后仍可用）。本轮涉及的修改不改变 C++ 数据面，沿用此前 9 项传输回归结果。界面仍以离屏渲染和共享控制接口验证，没有宣称自动点按覆盖每一个设置操作。

初次部署的新公网 42860 在两端都超时；最终通过已有 HTTPS 域名的独立 /streamlink-discovery/ 路径发布。源站只绑定回环 42860，生产域名的其他 location 保留。元数据有应用层 AES-GCM 加密，服务器仅存认证散列、两个设备槽位和短期密文；不代理业务流量。

没有为测试重启整台电脑或注销用户；已验证 Session 0、服务重启及 SSH 退出独立运行，尚未做真实冷启动未登录桌面验收。生产 Lucky/EasyTier、应用配置、默认路由、DNS、WSL 保持原状。

最终候选程序再次测试：**49.97424 Mbps，104113/104113 包，0% 丢包，50 Mbps / 20 秒，Akane → Thinkbook**。两端 StreamLink、CLI、Service、udp2raw-native 二进制 SHA256 一致，详情随 0.2.0 包的验证摘要提供。

Akane 专属 StreamLink 服务强制结束后，SCM 约 **6.14 秒** 拉起新 PID；约 24 秒后日志确认完整直连恢复。恢复时清理旧会话的防火墙和临时密钥，凭持久设备所有者重新续用自身 UPnP 租约，没有等待 180 秒自然到期，也没有覆盖 Lucky 的规则。两端最终继续保留已配对的后台网络，创建端 .1、加入端 .2，服务自动启动。
