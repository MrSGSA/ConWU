# ConWU 1.4.5

这次更新主要处理“入口一直准备不好”和“原本连得上，重启后却迟迟连不回来”这两类问题。自主打洞补上了协调辅助，几种协议各自的握手、端口释放和复连问题也一起做了修复。首次加入仍然使用 16 位直连码和主机审批，不需要重新学习一套连接流程。

使用自建协调服务器的自主网络，现在可以让协调端帮助两台设备交换候选地址，并约定同时探测的时机。FakeTCP＋HTTP、Phantun、Mimic、TCPRAW、纯 TCP 和 HTTPS 都已接入。协调端只协助发现和打洞，不转发串流或其他业务数据；已经正常工作的直连也不会因为协调服务暂时不可用而被主动断开。

这项辅助需要协调端和参与设备都支持新版本，并直接访问 ConWU 的协调监听端口。同一个端口同时提供 HTTPS 和 TCP STUN，通常不需要另外开放观察端口；仅能转发 HTTP 的反向代理无法代替这个监听。

自主入口的准备过程也更清楚了：

- 生成直连码时，会显示正在查询地址、发现网关、申请映射，还是等待本机接收器准备，同时给出耗时和具体失败原因。整轮准备有时间预算，不再一直停在笼统的“准备中”。
- 入口暂时准备失败时，保留原网络、配置和已配对身份，后台继续重试，也可以再次生成直连码。取得 STUN 候选和真正建立双向连接会分别显示，避免把“查到了地址”误当成“已经打通”。
- STUN 观察连接与网关租约分别维护。观察服务短暂故障时，优先恢复观察或尝试备用服务，避免连带拆掉仍有效的映射和正常通道。
- Windows Mimic 增加了 PKARR 首次候选交换和双向探测；主机审批及身份校验仍然保留。PKARR 查询和发布直接联网，避免已失效的本机代理让发现服务一起失效，发布失败时也会提供更具体的原因。这个首次协同扩展目前只用于 Windows Mimic，没有扩大为其他协议都具备的能力。

已有入口继续按照保存的地址或订阅工作，不会额外启动自主打洞、STUN 或网关映射。它与第三方工具之间的职责保持清楚，也一并检查了首次配对、断开再连以及两端分别重启后的恢复。

本次修复还包括几处不太容易从界面看出原因的问题：

- FakeTCP＋HTTP 在对端重启、地址端口却没有变化时，可能重复使用旧握手，导致双方一直恢复不了连接。现在新的复连周期会重新准备握手。
- TCPRAW 在同一端口监听并主动连接时可能遇到端口占用；重复或迟到的连接回调也可能误删仍在使用的连接。现在受控端口可以正确复用，旧连接的回调不会再影响新连接。
- 纯 TCP／HTTPS 的协调探测区分了“谁先建立物理连接”和“谁是主机”。反向建连仍按获批的 HTTPS 身份验证证书，不会因为连接方向改变而放松校验。
- Windows 的 STUN 辅助连接关闭后，原端口可能短时间内无法再次使用，拖慢重试和重启恢复。现在辅助资源退役后可以及时重建。
- Windows 原生 FakeTCP 可能打不开较深目录中的配置文件，表现为刚发起配对就提示入口未回应。现在支持超过 260 字符的会话配置路径，文件打不开时也能记录正确的文件错误原因。

功能回归覆盖了六种协议在 Linux 下的协调辅助和已有入口，并检查了 Windows／Linux 分别作为主机时的审批、配置继承、双向收发、断开重连和重启恢复。Phantun、Mimic、TCPRAW 另外检查了多网络共用监听、网络隔离和连续重连。

这些改进不能让所有 NAT 都必然打通。本次校园网严格 NAT 的双端无显式入口试验仍未接通；短时合成发包也有待继续校准的收发计数缺口，因此本版不宣称提升了公网穿透率或实际串流码率。

升级保留现有设置、网络身份、虚拟 IP 和证书，无需为了升级先删除网络。GitHub 与 Gitee 继续提供同一份 MSI 和 Linux 安装包，Windows 完整 ZIP 由 GitHub 提供。Android／iOS 不包含在这次发布中，APK 保持原样。
