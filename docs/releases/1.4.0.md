# ConWU 1.4.0

本版修复 TCP／HTTPS 自主入口的端口对应问题：多层 NAT 下，STUN 观察到的公网端口不能直接作为内层路由器的转发端口。现在优先使用直接公网映射，其次保持独立探测源端口，并将本层端口转发到实际接收端口；网关不可用时保留接收端口的候选观察。仍需对端实际连接验证，不保证所有 NAT 都能打通。

## 修复与改进

- 创建多个网络后，可在对应网络选择、生成及复制各自的直连码；异步结果不会串到另一网络。全局设置的进度查询不再携带空网络编号，被动配对查询保持原网络范围。
- 网络和协调设置保存失败时，在发起操作的浮窗内显示错误，保留草稿并恢复输入与重试。入口测试的迟到结果不会覆盖修改后的来源；长设置页会滚动显示错误。
- Windows 监听防火墙规则规范化程序路径，兼容 `C:/…` 写法，同时保留程序与端口限制及所有权清理。
- Windows／Linux WebUI、Linux CLI 及 Android 测试客户端提供官方正式版更新检测，按平台选择附件，不自动安装或改动设置。
- 首次配对超时可区分 TCP 建连、TLS 握手、WebSocket 协商与配对交换阶段。

## 平台与验证范围

正式附件面向 Windows x64 和 Linux x86_64／glibc。保留现有网络、设置及证书，升级不要求删除网络或重新选择协议。

TCP／HTTPS 已在台式主机到笔记本的公网入口上对照验证映射修复、加密回声、重新连接及租约维护。回环检查覆盖多网络隔离、审批、证书绑定、端口占用与资源回收。随 Release 提供的 verification.json 记录实际检查和三机升级结果；测试吞吐不代替 Moonlight 串流验收。

Mimic 与 TCPRAW 继续作为实验选项。两机均可建立公网通道，但当前线路的独立 20 Mbps 测试丢包约六成，同条件 Phantun 也出现类似结果；HTTPS 对照完成约 20 Mbps 加密回声。Mimic 另有一次审批后的配对轮询超时，尚不能称为稳定的日用替代方案。丢包发生于两机间路径，具体执行点仍未确定。默认保持 FakeTCP＋HTTP，升级保留用户原有协议。

Android 从机源码、开发测试构建入口及使用说明一并维护，支持 TCP／HTTPS。当前 Android 仍使用独立的开发签名测试包，尚未完成手机串流和正式签名验收；本版不提供 Android 正式安装附件。iOS 待具备 Mac、Xcode 和签名条件后继续。
