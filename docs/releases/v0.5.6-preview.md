# StreamLink 0.5.6 开发预发行

保持原生Windows、Wintun→MeshLink→udp2raw FakeTCP＋HTTP、八成员直连与禁止业务中继。此版本是后续开发候选，完整M0—M9发布Gate仍未通过。

本版变化：

- 兼容原生SYN、HTTP、确认与维护在实际注入前领取全机控制额度；随机授权及实际PID绑定管道，限制等待队列、过期与旧捕获代次。业务数据独立发送，HTTP/SEQ和无业务重传语义保持。
- 注入、真实源端点、排队、预算许可及失败分别进入诊断账本，未知物理/内核开销继续标记未知。
- 网络事件和Windows服务唤醒接入Mesh及历史双机流程。HTTPS变慢不阻塞历史双机的本地准备，候选更新/helper失效保留健康会话的资源。
- 受管pacing按实际出口分组，再按成员公平调度，速率仍是全机合计；继续默认关闭。

测试已包含30轮原生协议/管道/Router集成，以及一次两Windows真实WinDivert/Wintun公网业务验证：双向各10个完整1280B/DF包全部返回。真机控制许可与拒绝统计可核对；这次协调依赖旧网络，不是独立冷启动。Thinkbook首次连接20.921秒，尚未满足15秒目标。

默认保留PreferFakeTcp和已验证的显式TCP入口。SO、UDP_DIRECT降级、观察/预测/来源学习/概率探索、PCP/NAT-PMP、原生IPv6、pacing、反馈、备用、主动诊断及AutoQuality继续独立许可，默认关闭。轻量包不包含EasyTier。

尚需完成兼容业务pacing/过载反馈、完整路由与迟到探测处理、私网UDP peer-port证据，以及所需公网SO/NAT组合、八台真实Windows、50Mbps与60分钟、系统冷启动/休眠、正式安装升级及回滚。不得把本包当作这些项目已验收。

候选应先放入独立目录并执行自带bundle检查；启用新协调能力需要匹配的协调服务，旧网络配置应备份。当前生产0.3.2与协调0.3.0保持运行。

回退时停止新尝试并等待本版本的worker、捕获及所有者资源退出，恢复上一完整包及兼容配置。只清理本版本拥有的规则/映射/网卡，保留较新成员撤销状态和其他软件正在使用的驱动。测试候选未安装时，无需回退生产服务。
