# ConWU 1.5.1 候选版

## 串流与连接恢复

- FakeTCP、Phantun、Mimic、TCPRAW 共用的本地收包队列发生短时积压时，保留直连并继续收发。队列满时跳过来不及处理的数据报。增大本地回环套接字收包缓冲，给游戏串流集中发出的一帧数据留出空间。
- 每个对端直接向自己的本地承载套接字回包，省去共享发送队列。承载进程退出后及时释放连接和监听状态，准备重建。
- Mimic 在原端口重连时会更新已没有有效载荷的旧传输状态，并为在线协调服务预留一段同步建连时间。仍在收发的链路可以继续使用，旧状态中滞留的数据报会被丢弃。
- 直连中断后立即检查入口，优先尝试仍然有效的上次直连地址，并轮换过往失败的候选。协调服务器在双方均等待时采用约 2 秒的准备时间，后续尝试可用常规轮次。STUN 请求失败后轮换配置中的服务，独立网关映射可尝试备用外部端口。
- 纯 TCP 和 HTTPS 在接收队列积压时保留报文顺序，同时维持反向收发。

## Windows 日用修复

- UU 远程识别不同目录中的官方进程，以套接字归属关联当前会话和已批准的直连网络。规则就绪与检测到会话流量分别显示，连接或进程变化后重新评估。
- 托盘先占用本会话和数据目录的实例身份，再创建窗口。开机启动设置同时控制后台与托盘，隔离验收实例采用手动启动。
- 整合已有的加入申请收尾、失败申请移除、更新结果收起和 Mimic 的 WinDivert 日用承载修复。

ConWU 继续采用主从授权及两端数据直连。协调服务负责候选交换和安排建连。在双端随机严格 NAT、链路受到限速或端点不可达时，仍可能建连失败。Android 与 iOS 暂缓。
