StreamLink 0.4.1-preview：TCP 入口与连接恢复
日期：2026-10-11

定位
本轮把 TCP / FakeTCP 放回实际产品主线，优化已验证可用的
TCP STUN + 路由器映射 / 手工 Lucky 入口 + udp2raw FakeTCP + HTTP。
这些改动已接入 MeshRunner 和后台服务，不是独立的打洞演示模块。
维持每网络 8 台、原生 Wintun 与自主组网、业务只直连的范围。

具体改动
1. TCP STUN：首先用实际固定源端口连接首选服务。350 ms 后仍未完成，
   最多并发 3 个临时端口检查备用服务；每个检查 2 秒，检查之间间隔
   150 ms，候选队列上限 3。首选正常时不产生备用探测。
   临时端口的公网观测值一律丢弃。切换前完整关闭旧固定端口连接，再从
   实际源端口重新连接、查询和保活。始终最多一个实际源端口连接。
   整轮最多 12 秒，不再把整个服务器列表的四秒超时逐项累加；长列表的
   备用起点随轮次变化，避免一直卡在坏前缀。实际单连接仍为四秒预算。
   成功建立映射后的 STUN 服务会写入设备配置，下次启动和保活重建优先。

2. 主调度：100 ms 本地检查节拍，协调 GET、公告 PUT、成员目录保存分别
   在后台执行。创建网卡、等待本机映射、慢 HTTP 都不会阻止读取对端入口。
   本机没有入口时，仍能主动连接有入口的成员。
   未全部连接时 GET 间隔 2.5 秒，全连接后 5 秒；公告无变化每 15 秒续期，
   地址变化时至少间隔 2.5 秒，目录写入至少间隔 5 秒。按 8 台持续尝试的
   正常调度上限约 396 请求/分钟，保留现有协调服务 512/分钟配额的余量。
   请求失败和子进程连续退出均退避，避免频繁创建进程或请求风暴。
   稳定链路仍使用原 12 秒存活窗口；不会把调度节拍宣称为实际断线检测时间。

3. 地址切换：每个成员最多保留一条已验证传输和一条待验证替代传输。
   新地址需通过 MeshLink 加密认证，并在同一路径返回随机挑战，才能切换；
   对端有密钥、能够返回握手，或者挑战从旧路径返回，都不能代替此验证。
   旧路径在新路径确认前继续发送业务。替代路径 15 秒未通过则释放并退避。
   迟到的旧路径报文不会立即把发送路径切回；仍允许认证后乱序交付业务。
   这是链路存活验证，不是吞吐评估，也不保证切换过程绝对零丢包。

4. 恢复与清理：单个 udp2raw 进程退出只恢复相应传输，保留虚拟网卡和其他
   成员。映射失效后，旧租约异步清理，不堵住其他成员的恢复；新映射必须
   等旧租约清理完成，防止旧删除请求误删新规则。关闭时取消并回收 HTTP、
   STUN 探测、传输进程、映射和自有规则。

验证
新增 tests/StreamLink.MeshConnectionTests，43 项检查：
- Windows 实际 TCP socket 与回环 STUN 服务：固定源端口、持续连接保活、
  首选不阻塞备用、临时端点不外泄、事务 ID 校验、取消后端口重绑、12 秒
  总预算和所有失败连接回收。
- 实际 MeshLink AES-GCM 与回环 UDP：候选的双向挑战、从错误路径返回的
  挑战、无效报文、晚到旧路径报文、完整 1280 字节内层包、替代前继续传输。
- 实际 MeshRunner，注入内存网卡及隔离传输：网卡/映射慢启动、只有对端
  有入口、挂起协调 GET 时的进程重启及映射更新、慢租约删除、成员撤销与退出。
在本机故障模拟中，坏首选切换及清理约 0.4 秒；调度恢复应以测试日志中的
实际计时为准。这些数字不是公网打洞时间或 p50/p95 指标。
此外运行打包脚本要求的核心、旧配对、Windows 生命周期、连接、三节点组网、
UDP 基础、C++ FakeTCP + HTTP 协议回环、HTTPS 协调和界面回归。

边界与后续 TCP 研发
本轮没有增加原生 udp2raw 的 TCP simultaneous-open 状态机，没有实现 TCP
端口预测、低 TTL SYN 或随机扫描，也没有新增中继。当前仍需要至少一端有
可用入口，最终以真实加密直连验证为准；STUN 有响应不等于映射可以入站。
本轮没有修改 udp2raw 的 FakeTCP 报文格式和 HTTP 特征，也没有给业务增加
可靠重传或按序等待。现有 UDP 打洞基础仍未接入默认数据面。

真正的下一阶段是独立验证 FakeTCP 双端主动发 SYN：角色协商、固定本地
端口与实际公网观测对应、Windows WinDivert 收包与内核端口占用、交叉 SYN
状态、重试、身份验证，最后验证同一路径的数据包。不能把普通内核 TCP
connect() 成功直接视为能够无缝改用 FakeTCP，更不能据此保证双 NAT4 可连。
这需要 NAT 模型及两端真实网络验证；本候选不在默认配置中加入未验策略。

部署与回退
本地候选包为 StreamLink-0.4.1-win-x64-preview.zip；协调 API 和组网格式
仍为 meshProtocol:4，与本地 0.4.0 协调候选配套。现有公网旧协调服务尚未
升级，现用 Windows 后台服务也未替换。0.3.x 配对不能直接用于 0.4 网络。
Akane 上次确认为离线，本轮没有新增两端 50 Mbps、冷启动或休眠恢复成绩。
待两端空闲上线后，使用独立 MeshHarness、独立端口和隔离网段做对照：
首次建连、进程退出、公告地址变化、网络恢复、50 Mbps 双向数据与丢包；
分别统计控制发现、入口就绪、认证完成及恢复耗时。
本轮未改生产配置，因此现用连接无需回退。若以后手动部署候选，迁移和
回退按“使用说明.txt”执行，保留原完整包及同机 DPAPI 配置备份。
