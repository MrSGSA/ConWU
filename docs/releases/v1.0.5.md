# StreamLink 1.0.5

这次主要解决设置丢失、界面短暂失去响应和需要手动刷新的问题。

- 已有入口模式只使用填写或订阅得到的入口，不执行 STUN、自动映射或自主打洞。入口不可用时给出提示，由用户决定是否切换模式。
- 修复删除、退出网络时，可选配对房间清理超时导致操作中止的问题；必需的成员撤销仍等待服务器确认。
- 设置不再随退出、删除、创建或重新加入网络而清空；升级继承原有设置。
- 慢速停止和资源回收不再堵住本机状态读取，界面区分网络正在停止、后台暂未响应与授权过期。
- 修复退出后配对码输入异常、后台轮询锁住设置输入区、下拉选项被刷新打断等问题。
- 保留未保存草稿和恢复历史；多个窗口保存发生冲突时保留草稿，面板会话变化可安全恢复。
- 补齐已有入口的实际连接信息，增加天、时、分、秒的已直连时间。

下载 `StreamLink-1.0.5-x64.msi`，结束串流后更新两端。已有网络和设置保留，无需重新创建网络；使用现有 1.0.3 协调服务的用户不必为本轮修复重新部署服务器。1.0.3 继续保留作为回退版本。

两端已实际升级至此安装包，设置继承、浏览器交互、隔离安装/修复/卸载和完整核心回归通过。发布前核对了两机主日志、原生会话日志及 Windows 应用错误事件；一次手动删除、重建和重新加入与日志相符，未发现服务异常重启、资源回收失败或持续重连。当前已有入口直连和双向探测正常。

日志仍有偶发 HTTPS 协调和地址订阅超时，已有健康路径继续保持；此处不宣称外网请求零失败。长期大码率 Moonlight 串流、完整多机和跨账户矩阵尚未验收。协议仍由用户选择，不自动回退 UDP；新抗 QoS 方法未加入本版。

安装包与应用源码冻结于 `525f583c`。后续 `7ca701a` 仅修正升级验证脚本对省略的默认布尔值的比较，发布说明的更新也不改变应用源码。首次验证失败及修正后的实际升级复跑结果随验证附件保留。应用尚未进行发布者签名，驱动继续使用官方组件。
