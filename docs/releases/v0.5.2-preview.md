# StreamLink 0.5.2-preview 开发候选

本版增加 TCP 来源端点学习的正式接入，保留 udp2raw FakeTCP＋HTTP、Wintun 和自主 MeshLink。最多八成员，业务只走成员间直接连接。**这是开发候选，M0—M9 发布验收尚未全部完成。**

## 相对 0.5.1

- 新增默认关闭的“TCP 来源端点学习”设置。IPv4 原生 SO 收到同一授权 IP 的变化源端口时，可以有界学习，再完成原有认证和共同提名。
- 本机 native、双方成员及协调服务独立协商能力；签名绑定候选权限，旧组件不会自动启用。IPv6、UDP 和预测端口窗口不混用该权限。
- 同公网 IP 的多个成员按身份持有独立真实源端点，仍服从全机八端点配额。失败或闲置来源可安全退役，正在使用的路径不被回收。
- 来源机制各协议角色 30 轮受控验证，正式 Runner/签名/长轮询/设置/源池与预测回归通过；两台 Windows 各角色一轮，完成来源学习及真实 Wintun 完整回显，接收观察窗口无 RST。

真机测试通过已有 P2P 链路，使用受控偏移公告、本机 helper 和 SSH 控制；没有证明公网 NAT 新覆盖或独立启动。初次直接控制访问超时的失败仍保留。没有重测满带宽，不把此次功能结果当成 50Mbps 质量保证。

## 默认与实验能力

默认仍是兼容显式 TCP 入口、FakeTCP 优先、原生组网和有界恢复；可继续使用已有 Lucky 地址。升级不自动开启 SO、UDP 降级、来源学习、TCP 观察/校准/预测、PCP/NAT-PMP、外层 IPv6 或出口 pacing。

来源学习需双方新版、明确启用实验 TCP 打洞，并且协调服务声明支持。只更新安装包不代表服务器已经更新。健康 FakeTCP 不会因 UDP 更早连通被抢占。未找到路径时显示未连通或部分连通，不经过服务器或第三个成员代转业务。

UDP 多源概率探索仍仅内部机制；正式稳定端证据、签名协商与 Runner 接入未完成。AutoQuality、完整兼容/内核控制账本和多出口调度仍待完成。真实公网正例、八台 Windows、60 分钟质量、系统冷启动/恢复、正式安装及回滚 Gate 尚未全部通过，详见包内 `开发验收状态.md` 和 `验证摘要.json`。

## 使用与回退

完整解压后运行 `StreamLink.exe`；软件自带 Windows x64 运行时和配套组件，不要求 EasyTier、WSL、Python 或开发环境。不要只覆盖单个 exe。打开界面不会替换已安装后台，服务安装/升级仍由设置中的操作触发。

单项回退可关闭对应实验设置，pacing 填 0。整包回退先停止候选网络、等待资源退出，再使用已保留的旧完整包安装后台与配置备份；保留旧服务目录。不要删除共享驱动、全局路由或无关规则，不用旧成员目录恢复已撤销设备。

0.5.1 与此前包独立保留，现用服务尚未替换。产品 EXE 未代码签名；包内清单用于完整性核对，不能代替可信发布渠道。源码和依赖许可证随包提供。
