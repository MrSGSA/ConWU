# ConWU：入口、配对和网络设置

每个网络连接一台主机和一台从机，通道双向。同一设备可同时创建、加入多个网络，概况合并显示；不同网络之间不转发业务。

## 创建和加入

主机在“创建网络”填写名称，通过“网络设置”选择连接策略和虚拟 IP，然后创建网络、生成 16 位直连码。从机在“加入网络”输入直连码，核对双方校验码，由主机在“加入申请”批准。批准后自动获取主机的网络设置与入口来源，从机无需预先配置。

直连码按 `XXXX-XXXX-XXXX-XXXX` 分组，含 IPv4 入口、端口、配对房间及校验信息，有效五分钟。不区分大小写，粘贴时可包含空格或横线；复制、删除自动处理分组。它不包含完整网络凭据，业务权限和配置在批准后通过加密交换获得。旧六位配对码及 SL6 接口仅为旧脚本兼容保留，不再作为 WebUI 加入方式。

生成前必须取得可分享的 IPv4 入口。创建网络成功只代表身份与配置已保存，不代表 NAT 已打通。入口准备或订阅解析失败时保留网络和已有有效配对会话，待入口恢复后重试。直连码可以绕过离线的协调服务完成首次配对；实际通道仍需可达。

## 独立设置

每个网络分别保存设置。新网络默认采用 FakeTCP＋HTTP、自主打洞和 PKARR；不会继承上一网络的入口。创建前保存的设置草稿可以在刷新后继续使用。旧版共用设置在 WebUI 修改时仅分离当前网络，其余网络保留；后端也检查并发新增的引用。

网络设置浮窗内可调整连接方式、发现方式或已有入口、端口、STUN 及创建前的虚拟 IP。主机设置可改，从机继承的设置只读。网络删除后回收其专属设置，未创建的草稿和显式 CLI 模板不随其他网络删除。

全局“设置”只管理启动与服务、本机设备名、日志与终端外观。高级监听与证书属于本机服务，和每个网络选用的发现地址分开。保存设备名称或日志不会改动已有网络、反向代理、证书或信任参数。

## 连接策略

**自主打洞**：首次均使用直连码；后续入口发现三选一，互不同时运行：

- **PKARR 自动发现（默认）**：两端发布和查询签名入口，无需注册域名。
- **自建协调服务器（高级）**：填写指定设备的 HTTPS 地址，可附证书 SHA-256 指纹。协调服务帮助更新入口、交换候选，业务仍在两端直连。暂时离线不阻止本地创建、直连码配对或双机网络退出／删除。
- **仅直连码**：不使用外部发现；地址变化后重新生成并输入直连码。

**只使用已有入口**：填写主机的公网 IP:端口、路由器转发、第三方已打通的地址，或 HTTPS/TXT 等订阅链接。入口必须通向 ConWU 接收端口（默认 44680），不是 Lucky 等工具的管理网页。此模式不启动自主打洞、PKARR 或备用协调。若不是可更新的订阅链接，入口变化后需重新填写新地址。

多主机共用来源时可按标签筛选，例如内容为 `streamlink1=203.0.113.1:8436`、`streamlink2=203.0.113.2:9123`，分别填写 `txt://entry.example.com#streamlink1` 或 `https://entry.example.com/current#streamlink2`。标签只用于筛选，连接仍验证网络和设备身份。订阅检查间隔可设为 1 秒至 24 小时；成功配对后保留来源，重启仍重新解析。

现有直接 UDP 网络保留原协议，不静默转换。新网络默认 FakeTCP＋HTTP，纯 TCP 为后续预留，当前不可选。FakeTCP 外层不是 TLS；内层业务有认证加密。本版没有中继或自动降级到 UDP。

## PKARR 发现

主机与从机分别拥有发布身份和持久递增序列号，不共用记录。首次通过直连码配对、批准后保存网络、设备和发现公钥的绑定。从机获得自己的发布身份，不获得主机私钥。两端在已认证的通道内协商双向发现，再分别发布入口、查询对方并确认当前入口版本；旧端不支持时保留单向查询。

只发布自主准备的入口。地址变化时及时更新，配对前通常每五分钟发布，配对后通常每分钟发布，建立联系时更频繁。地址公告有效一小时，加密发现状态有效三分钟。网关请求有独立时间预算，单个网关卡住不会拖满整轮；定期比较其他网关，避免快速返回的旧缓存挡住最新地址。失败后退避重试，健康直连继续保持。

签名入口公告公开可见；设备名、启动轮次和入口确认信息仅配对双方可解密。网络私钥、入网凭据、管理密码不上传。查询校验签名、协议、时效与最高已接受序列，拒绝回退及同序列冲突；检查点写入受保护存储，重启和恢复设置后仍保留，保存失败时不将公告交给连接层。

在网络设置的“配对与发现方式”中可填写 1–4 个 HTTPS 网关，主从机配置随批准交换。更换网关后用于后续发布与查询，不改变发现身份、序列检查或健康业务通道。状态显示发布入口、成功时间、网关接受数、对端确认与查询错误；“立即刷新发现信息”不保存设置或重建连接。

当前通过公共 HTTPS 网关使用 PKARR，不包含原生 UDP DHT 客户端，不保证严格 NAT 可达，也不替代完整的双方同步打洞调度。PKARR 网络主从两端应同时升级。隔离回环与公共网关验证不能替代真实 NAT 或 Moonlight 串流验收。

## 本机协调能力与管理

安装后的设备默认提供独立协调能力，不自动成为其他网络成员，不扫描局域网，不承载串流。真正使用哪台协调设备由各网络的高级发现设置决定。自身提供与选用其他协调设备可同时存在。

新设备默认生成本机 HTTPS 证书并监听 `https://0.0.0.0:47822`；客户端使用可访问的地址并配置相应指纹，或使用自行维护的 HTTPS 反向代理。已有监听、证书、反代和来源信任保留。监听失败只影响协调能力，不阻断本机组网与管理。`0.0.0.0` 不是访问地址；HTTP 仅允许回环监听，公开访问需 TLS、转发和防火墙可达。

本机 WebUI 默认 `http://127.0.0.1:47821/`。Linux 可运行 `conwu web` 获取登录链接，或通过 SSH 转发访问。按 [Linux 文档](../packaging/linux/README.md) 显式启用密码保护的远程 `/admin/` 后才能域名管理；公开协调接口不会获得管理权限。

## 退出、升级与回退

从机“退出网络”移除本机关系；主机“删除网络”结束该网络。协调不可用时仍可完成双机网络本地退出／删除，远端撤销未确认时不会伪称已确认。需要时界面允许只从本机移除。邀请过期不影响已经获批的成员授权。

更新保留现有同语义设置、网络身份与虚拟 IP，新功能补入默认值。更改连接策略或协议可能重连，保存前显示受影响的网络。回退前停止服务，使用原程序及对应受保护备份，不手工覆盖运行中的数据。
