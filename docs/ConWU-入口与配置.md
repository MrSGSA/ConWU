# ConWU：入口、配对和网络设置

每个网络连接一台主机和一台从机，通道可以双向使用。一台设备可以同时创建、加入多个网络；概况合并显示，不在不同网络之间转发业务。

## 创建和加入

主机在“创建网络”填写名称，通过“网络设置”浮窗设置协议、入口、协调与虚拟 IP，然后创建网络、生成配对信息。右侧列出本机创建的网络，可查看配对信息、修改设置或删除。

网络设置决定数据怎样连接，配对信息决定首次怎样申请加入。使用协调发现的网络，以及已填写配对协调地址的已有入口网络，均可在创建页选择生成配对码或直连邀请。没有可用的配对协调地址时，只提供直连邀请；新建无协调配置不再自动创建隐藏的数字配对房间。

从机在“加入网络”输入主机配对码，或粘贴主机生成的完整直连邀请。主机在独立的“加入申请”页面核对设备、虚拟 IP 和双方校验码，再同意或拒绝。

批准后，从机通过加密配对通道自动获取该网络的设置。主机的“本机入口”转换为从机的“目标主机入口”，虚拟 IP 单独分配，本机监听与源端口按本机资源处理。本机名称、启动、日志、协调监听角色和管理凭据不会照抄主机。从机可查看这份设置，不能直接编辑或改用本机连接配置。

主机和需要进行自主配对的协调设备应先更新至本候选。旧设备未下发所需设置时会明确报错，不假称已经自动配置。

## 短配对码和直连邀请

从机在“加入网络”直接选择“配对码”或“直连邀请”，不由“协调服务器”页面决定。配对码模式下，通过“设置本次加入网络所使用的协调服务器”填写地址；双方需使用同一协调服务，主机先向它登记配对码。六位数字本身不包含地址，也不能查找任意主机。

尚未填写协调地址时，配对码模式仍可选择，但数字输入和“请求加入”不可用，指针显示禁止符号。填写后恢复使用；清空地址不会自动切换模式或清空已输入的配对码。协调设置按钮和请求按钮并列显示。

直连邀请模式不显示协调地址按钮或协调状态。已有入口和无协调自主入口都在创建网络页生成完整邀请，从机粘贴后申请加入，无需再填写一份主机配置。邀请携带初次联系所需的入口、协议和主机身份，仍须主机核对、批准。软件不通过业务协议回退猜测连接，旧版入口加短码接口保留兼容。

加入页记住本浏览器上次确认的协调地址，刷新及切换页面后仍可使用；明确清空后不会从旧默认值自动补回。首次更新时沿用此前已启用的协调地址；开启本机提供协调服务不会自动设置加入地址。此地址只用于发起新的加入申请，不改变已有网络或主机网络设置。

主机修改配对协调地址后，应重新生成配对码。界面不会继续显示或复制登记在旧服务器上的数字码；已经发出的旧码在其会话有效期内仍绑定原服务身份，审批不会被新偏好偷偷改写。直连邀请包含主机身份；协调网络的邀请也签名绑定该网络的协调身份，选择邀请不会把网络变成另一种发现策略。

生成直连邀请需要一个可分享的主机入口。自主打洞网络在需要时准备入口；取得候选仍不等于对端必然可达。暂无入口时会提示改用配对码或稍后重试，不创建虚假的成功邀请。已有入口网络不会因生成配对信息而启动自主打洞。

协调服务使用自签名证书时，主机填写相应的证书 SHA-256 指纹；从机在本次协调服务器弹窗的“自签名证书（可选）”中填写同一指纹。留空使用系统证书信任。此信任仅用于所选配对服务，不修改系统证书库、本机提供服务或已有网络。

## 已保存的设置

网络设置浮窗默认编辑本网络的独立设置，不自动选中第一份已保存配置。“复制已有设置（可选）”只复制内容，不建立共用引用，不修改来源网络。连续创建新网络、刷新页面或删除未使用设置，也不会自动回到第一条网络的配置。虚拟 IP 属于单条网络，单独分配。

加入的新网络使用主机提供的设置，不引用本机配置库。旧版本已有的共用引用不会因更新而重启；在 WebUI 编辑其中一条网络时，保存会先写入独立副本，只把目标网络改用副本，其它网络保留原值。保存前再次检查引用，防止编辑期间新增的引用被误改；目标网络已被另一窗口删除时拒绝保存。CLI 的旧配置管理接口保留兼容，WebUI 不再提供共用联动。退出、删除网络保留本机设备设置和配置库；未使用的设置可在浮窗内删除。

“设置”只管理启动与服务、本机设备名和日志。“协调服务器”页面只管理本机提供协调服务；创建网络所用的协调地址在该网络设置中填写，加入网络所用的地址在加入页填写。各网络保留自己的协调身份，不会因新的加入申请而改变。

本机提供协调服务与使用其他设备的协调服务可同时进行，不自动默认使用自身。使用本机 HTTP＋HTTPS 反代时，其他设备填写反代的 HTTPS 地址；`127.0.0.1` 仅供本机访问，`0.0.0.0` 是监听范围，不能作为访问地址。

提供服务侧只需填写监听地址，不再重复要求外部 HTTPS 地址；旧值保留用于兼容及诊断。证书、私钥和反向代理设置仍按需要配置。其他设备须能访问所选协调地址；开启提供服务并不使本机成为每条网络的成员，也不转发串流。

## 连接策略

**自主打洞**的配对与发现三选一：使用 HTTPS 协调服务器、直连邀请、PKARR。只有选择协调服务器时才使用其短码发现和候选同步。直连邀请、PKARR 均不同时向协调服务器发起另一套连接。取得 STUN 候选不等于入站一定可达；严格 NAT 是否能通取决于实际网络。

**只使用已有入口**：填写主机公网 IP:端口、路由器转发、第三方打通的地址，或 HTTPS/TXT 订阅。主机入口须实际通向 ConWU 接收端口，默认 44680；不是 Lucky 等工具的管理网页。此策略不同时启动自主打洞。

已有入口网络的“协调服务器”是可选项，仅用于短配对码配对。它不承担串流、不提供备用地址发现，也不启动 STUN 或 PKARR；未填写时使用直连邀请。协调服务离线后，仍可生成、使用已有入口的直连邀请。旧配置在用户保存新策略前保留既有行为，更新不静默修改在用设置。切换策略会记忆暂未使用的输入；隐藏的配对地址不会在 PKARR 或无协调自主模式下继续运行。

多主机共用来源时，用标签区分，例如内容为 `streamlink1=203.0.113.1:8436`、`streamlink2=203.0.113.2:9123`，分别填写 `txt://entry.example.com#streamlink1` 或 `https://entry.example.com/current#streamlink2`。标签用于筛选地址，不能代替身份认证。

## PKARR 入口发现

在“自主打洞”的“配对与发现方式”中选择 PKARR。不需要注册域名，使用 PKARR HTTPS 网关提交、查询签名 DNS 公告。此模式下 PKARR 始终启用；更换发现方式后停止发布。默认仍使用原有发现方式，更新不会自行开启 PKARR。

每条主机网络保留独立发布密钥和持久递增序列号，重启后更新同一个 `pkarr://公钥` 地址。只发布自主准备的候选，不发布隐藏的第三方入口。映射变化后更新公告，内容不变时每五分钟重发，公告有效一小时。界面显示发布状态、当前公告入口和最近成功时间。

首次仍须通过直连邀请交付发现公钥与主机身份。批准后，从机保存自己的网络身份和公开发现线索，不获得主机的发布私钥，也不会发布竞争公告。之后按入口检查间隔查询，最长一分钟一次，以免长间隔超过签名公告的有效期。

地址公告公开可见；网络私钥、入网凭据和管理密码不会发布。每次查询校验签名、协议、时效和当前进程已见的最高序列号，拒绝相同序列号的冲突公告。主机发布序列号持久保存；接收端最高序列号目前不跨进程保存。网关错误时不会以过期缓存启动新连接，已通过独立认证的健康通道继续保持。

当前不包含原生 UDP DHT 客户端，也未实现经 PKARR 的双方候选交换与同步打洞。它解决有可达候选时的地址重新发现，不能保证严格 NAT 连通。公开网关发布、更新和验签查询已实测；该结果不能替代真实双机 NAT 或 Moonlight 串流验证。PKARR 网络的主从两端均应更新到本候选。

本轮另外试验了仅凭六位数字在 PKARR 中查找入口：完整公钥无法由六位数字直接查回；若从六位数字派生发布密钥，则同码设备会共用记录，知道该码的人也能签名覆盖入口。隔离网关已复现这一点，因此未接入产品。首次短码发现仍需额外索引服务，或事先共享完整发现公钥；当前 PKARR 网络首次继续使用直连邀请。

## 重启、退出和回退

成功加入后会持久保存入口来源和网络身份。固定入口不变时继续使用；订阅与 PKARR 会重新查询地址；协调网络重新交换候选。只保存一次性裸 IP:端口且地址已改变时，仍需更新入口。邀请的申请有效期结束，不会使已批准成员的网络授权同时失效。

从机删除网络只移除本机记录，不删除主机网络。远端清理未确认时可选择只从本机移除，界面不会把远端撤销标成成功。

更新保留原有同语义设置及旧程序回退。当前候选的回归范围见随包记录，实际公网 Moonlight 串流由使用者验证。
