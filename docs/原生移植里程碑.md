## 本轮完成

独立创建 `product` 工程。研究用的上游仓库和当前成功 PoC 未修改；没有远程部署，没有运行 WinDivertOpen，没有安装驱动，没有调整现有 Lucky、EasyTier、Sunshine、WSL 或防火墙。

保留 HTTP 分支 `c4995eaad3576bd7bca872fe25bc93b519acdfdd` 的报文编码、加密、握手和数据报转发主体，新增 Windows 服务端事件循环与 WinDivert I/O 边界。

| 文件 | 变化 |
|---|---|
| `native_backend.cpp/.h` | 动态加载官方 WinDivert API；限定 FakeTCP 端口的入站截获；出站 IP 包注入；接收线程及有界队列；关闭/重建捕获句柄 |
| `native_server.cpp` | 用 libev/Winsock 管理服务端 UDP 会话与统一定时器，替代 Linux epoll/timerfd |
| `server.cpp`、`main.cpp` | 允许原生构建进入服务端协议，隔离 Linux 事件循环；新增不触网的 `--native-info` |
| `client.cpp`、`network.cpp` | 原生路径跳过 Npcap 设备发现及链路层探测，使用 WinDivert；处理源端口占用；修正 socket 关闭；校验 IP 头长度 |
| `connection.cpp/.h`、`fd_manager.cpp` | 原生定时器适配；会话关闭时注销 watcher；初始化清理计时和迭代器 |
| `common.cpp/.h`、`misc.cpp` | Windows 原生随机数使用系统 CSPRNG；不输出命令行及密钥；限制密钥读入长度 |
| `libev/ev_win32.c` | 将 SOCKET 的 `-1` 初始化改为 `INVALID_SOCKET`，兼容当前 x64 MinGW |
| `CMakeLists.txt`、`scripts/Build.ps1` | 独立、可重复执行的编译入口；将真实后端和测试后端编译成不同 EXE |
| `tests/protocol_loopback.py` | 实际启动 C++ 客户端/服务端，注入丢包、乱序、重复及篡改，核实 UDP 转发行为 |

原生后端在入站包交给 Windows TCP 栈之前截获它，避免系统栈对 FakeTCP 状态作出干扰性响应。发送端按 udp2raw 格式构造数据，不改为普通 TCP 字节流。WinDivert 的具体部署、校验和卸载标志语义以官方 API 为准。[WinDivert 文档](https://reqrypt.org/windivert-doc.html)

## 实际验证

使用 MinGW-w64 GCC 15.2.0 / CMake / Ninja，在 Thinkbook 构建 x64：

```powershell
.\scripts\Build.ps1 -Test
```

最后一次结果：**7 个测试，0 失败、0 错误，约 5.02 秒**。

| 测试 | 结果 |
|---|---|
| HTTP 开/关及 0、1、31、1200、1300、1500 字节 UDP 边界 | 通过；检测到开启时的 HTTP Host 字节 |
| 丢掉前一个数据包，后一个继续交付 | 通过；不等待被丢包补齐 |
| 把两个加密数据包倒序送达 | 通过；按到达顺序交付，不做 TCP 有序重组 |
| 同一加密数据包重复注入 | 通过；只向业务交付一次 |
| 篡改密文但重新计算合法 TCP 校验和 | 通过；篡改包被拒绝，后续包正常 |
| 两端配置不同密钥 | 通过；不能完成业务数据交换 |
| 注入不合法 IP 头和截断数据 | 通过；服务端存活，后续业务继续 |

这些测试使用单独 EXE 中的**回环 UDP 原始包载体**，运行真实 udp2raw 加密、FakeTCP 报文和事件循环，完全不打开驱动。它们验证协议和程序行为，**不验证公网抓包/注入、运营商 QoS、吞吐或真实丢包率**。

最后测试完成后未遗留本工程的客户端/服务端进程。检查 PE 依赖，未发现 Npcap、Python 或 WSL 依赖；WinDivert DLL 在真实会话启动时动态加载，故不能仅以静态依赖表声称“不需要驱动”。

## 未完成及风险

- 尚未证明 WinDivert 实际收发、校验和卸载、大包、RST 隔离及与其他驱动共存都正确。
- 本原生客户端使用自构造 FakeTCP 握手。当前成功 PoC 客户端使用 `easy-faketcp` 的 Winsock 辅助握手；这是必须单独 A/B 的变化。若该差异影响穿透/QoS，需要实现兼容握手后端，不能只改 UI 就上线。
- 没有双端实网跨实现互通测试，没有 50 Mbps 压测，没有这套原生后端的 Moonlight 实玩证据。
- WinDivert 真实路径只支持 IPv4 FakeTCP；IPv6、其他 raw 模式、跨平台后端未实现。
- 内核继承若干上游以 `int` 表示 socket 的接口与 libev 约束，需要在长期会话/多连接测试中审查，不将此开发版视为通用高并发服务。
- 自动 STUN/路由器映射、发现服务、邀请配对、Windows 服务、EasyTier 配套包、安装器和用户界面仍待实现。

下一步先完成 M1 的局域网和 Lucky 公网 A/B，再进入全自动打洞。具体步骤见 [开发顺序与验收](开发顺序与验收.md)。现有成功 PoC 是回退基线，不能被开发版覆盖。
