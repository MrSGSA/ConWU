# M6：把本机选路策略接入实际组网

本次从 `0da0e86` 继续，完成两种可配置策略和 UDP 降级状态的产品接线，未宣称整个 M6 完成。FakeTCP/HTTP 的原生报文、加密、序号、队列及业务数据报语义均未改；没有部署到现用服务或操作物理网络。

## 用户可配置的行为

连接设置新增“优先 FakeTCP”和“仅 FakeTCP”，以及独立的“允许 UDP 降级直连”。

| 配置 | 实际行为 |
|---|---|
| 默认 `prefer-faketcp`，`AllowUdpFallback=false` | 保留既有 FakeTCP 路径；不因打开实验打洞总开关就自动允许 UDP_DIRECT |
| `prefer-faketcp`，明确允许 UDP 降级，且打洞模式为 `tcp-udp` | TCP 不能提供路径时允许经过认证及包长验证的 UDP_DIRECT；健康 FakeTCP 不被 UDP 替换 |
| `faketcp-only` | 不公告、不收集、不接受 UDP_DIRECT，即使保留了以前勾选的 UDP 降级配置 |
| `auto-quality` | 当前明确拒绝启用；不再允许一个尚无质量证据检查的枚举绕过健康 FakeTCP 保护 |

旧配置缺少字段时默认优先 FakeTCP、UDP 降级关闭。既有 `legacy` 模式仍是默认；创建者明确选用的旧 UDP 网络属于另一种网络配置，不被当成已验证的 FakeTCP。仅 FakeTCP 与 UDP 网络组合会被拒绝，控制接口在停止旧网络、替换身份或保存前执行这项检查。

本次没有实现 UDP 已选中后在后台主动提升回 FakeTCP 的完整调度，也没有实现 AutoQuality。它们仍属于后续受管迁移/质量接线范围，不能把这里的保护检查当成完整自动质量选路。

后续进展：从 `f809e05` 继续的 [UDP 后台升级接线](m6-udp-upgrade-20261011.md) 已补上正式调度与失败回退；本页其余证据仍属于最初策略提交，不把后续结果追记成当时已通过。

## 执行边界

`DeviceProfile → MeshRunner → MeshRouter` 持有同一组不可变策略值。策略同时用于正式候选收集器和签名能力公告；已认证的远端请求不能重新启用本机禁止的协议。若没有允许的能力，Runner 保留兼容路径流程，不发布空能力公告。

Router 在接收路径所有权前检查策略及 `MtuQualified`。不合格路径仍由调用者负责释放，不能被误接入 Active。原来每次 `RegisterPath` 可以传入不同策略的入口已移除，避免单个候选覆盖设备设置。

还增加了实际切换前的复核：FakeTCP 在 UDP 提名期间恢复双向健康时，取消候选并保留原链路。由这项复核触发取消后，不再发送之前已生成的 Commit；原本就已生成的取消通知仍按原重试时序发送。

UDP 连接通过认证和 MTU 检查，只证明可达及可承载该包长。状态中的 `Degraded` 和界面的“UDP 降级直连、未验证目标负载质量”不会从低 RTT 或少量回显推导 50 Mbps 容量。成员列表、总状态和托盘提供一致提示。

后台控制回复新增 `PathSelectionVersion=1`。旧后台即使版本号同为某个开发版，缺少此能力字段时仍视为不支持；界面禁用新增策略控件并说明需要更新后台，避免旧服务忽略配置后界面却显示保存成功。本次未执行服务更新。

## 后续工作与回滚

AutoQuality 仍需正式、双向、绑定实际资源的负载窗口、证据新鲜度、至少三个五秒窗口、驻留/冷却以及共同备用提名。它不能挤进现有八秒 SO 整轮期限后再偷偷延长；下一步需明确备用资源的持有与测量阶段，再接入选择。出口 pacing、完整物理字节计账和长期质量 Gate 也未完成。

本轮不重复公网性能测试，前一轮反向质量失败仍有效。严格 NAT 覆盖、八真实 Windows、未登录冷启动、协调中断和正式安装包验收也没有因此完成。

回滚：现用部署未更新，无配置需要恢复。开发构建可退回 `0da0e86`；回退到旧构建时新增策略字段可能被忽略，因此不能把旧版本当作继续执行“仅 FakeTCP”设置的证明。实际发布时须连同配置备份和版本能力一起验证升级/回滚。
