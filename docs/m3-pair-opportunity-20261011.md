# M3/M6：前台机会窗与方法切换

从 `da81646` 继续。旧调度器每次方法失败都插入至少 30 秒退避，下一次方法又重新获得 60 秒。本次将这个等待改为“机会窗结束后的后台退避”，并把正式受管收集、排队、准备、握手和兼容主动入口计入同一设备对的本地期限。

## 接入与行为

- `MeshPairOpportunity` 记录本地机会窗 ID、对端启动代次、起点、共同期限、各方法次数和后台失败历史。合法能力公告使该设备对成为可调度对象时就开始计时，不等获得全机并发槽位才计时。
- 同一窗口最多 60 秒，每种普通方法最多两轮。一次失败先完成原资源清理，再选尚未耗尽的方法；同协议第二轮也不插入 30 秒后台等待。窗口内刷新端点不重置次数或期限。
- 开始新轮次前须留够完整协议预算：UDP 6 秒、SO 8 秒、现有兼容客户端验证 15 秒。准备完成和正式 Start 前再次检查。所有原生/UDP 内部期限保持原值，不通过放宽超时换取通过。
- 方法用尽、期限结束或余量不足以开始任何完整轮次，输出 `NoDirectPathWithinBudget`。之后以 30 秒起、最多 300 秒加小幅抖动重开一个可见的后台机会窗。已选中路径完成前台操作；后续硬故障可以开始新的恢复机会窗。
- 显式入口优先时间固定在机会窗起点。兼容主动进程在创建前扣除轮次，改变端点不能获得第三轮。两个明确失败的兼容尝试不再空等完整优先时间。若第二个兼容尝试尚在运行，不会因其次数已耗尽而提前取消；窗口到期只取消未验证的 pending，保留已验证 active。
- 已认证发起端的新 Offer 可以取代尚未成功的旧 Attempt，即使旧 Cancel 在协调合并时没被对端看到。新 Offer 等旧收集/准备资源完成清理后再接入；旧序列重放不能复活旧资源。健康路径的后台升级仍受上一阶段的能力、驻留、冷却和策略约束。
- 日志关联 opportunity/attempt、剩余时间、已用方法次数与停止结果；成员详情显示后台重试倒计时。

机会窗使用每端自己的单调时钟，从本端看到合法能力公告起算，不要求两端 UTC 一致；这不是从用户点启动开始的总时延，也没有新增跨版本窗口同步消息。旧协调服务或不公告共同能力的旧成员继续兼容流程；默认 `legacy` 模式没有因此改为实验模式。被动监听已有入口可继续接受经过认证的连接，不被算成新发起的主动探测。旧兼容资源和线上全部原生控制报文的统一总账仍是 M3 未完成项。

## 本次验证

| 产物（`artifacts/`） | 证据与范围 |
|---|---|
| `m3-window-tcp-retry-20261011.json` | 4 检查通过。仅 FakeTCP 的正式双 Runner：发起端首轮收集被注入故障，第二轮原生协议后端成功，8.647 秒报告连接；双向完整内层包通过。两端各只建立一个前台机会窗，无 UDP、无业务中继 |
| `m3-window-upgrade-20261011.json` | 16 检查通过。正式双 Runner 在首个 TCP 收集故障后 8.314 秒进入 UDP；此前同一受控用例记录为 36.513 秒。保留旧能力拒绝、升级失败回退、60 秒冷却、原生成功切换；双向各 1169 个合成包最终恰好交付一次 |
| `m3-window-opportunity-final-20261011.json` | 32 检查通过。模型覆盖每方法两轮、窗口不续期、余量门槛、退避上限；真实生产调度器覆盖快速故障、旧 Cancel 缺失、新 Offer 等延迟清理、重放、兼容轮次。真实计时中七个设备对只有两个获得准备槽位，其余五个一直排队 |
| `m3-window-baseline-final-20261011.json` | 55 检查通过。正式候选准入、显式入口优先、全机并发、三 Runner 共享源、实际 HTTPS、原生协议后端、同 socket UDP、控制中断与退出 |
| `m3-window-legacy-20261011.log` | 44 检查通过。兼容 TCP STUN、双向路径验证、旧路径保留、协调阻塞期间恢复和资源回收 |

七设备对计时：排队的五个在约 54.016 秒因余量不足 6 秒而结束；两个正在等待的准备在约 60.016 秒被取消，约 60.549 秒确认清理。这里测试的是一台进程内的正式调度器与受控资源工厂，不能当作八台真实终端验收。

8.314/36.513 秒是前后两次受控故障用例的单轮记录，不是公网 p50/p95，也不是严格 NAT 的成功率。TCP/UDP 正式 Runner 用真实 HTTPS、回环 socket、C++ 协议测试后端和内存 IP adapter；没有 WinDivert/Wintun 或物理 NAT。合成包最终全到不代表达到应用时限或 50 Mbps。

回归曾失败：`m3-window-baseline-20261011.json` 保留首次显式入口测试失败。当时优先时间从首次检查才起算，排队后可能额外等待 15 秒。已改为机会窗起点，最终基线通过。最初机会窗记录 `m3-window-opportunity-20261011.json` 的顶层通用 scope 文字过宽；最终文件改为准确的调度器/计时范围，历史文件不作为真实 Runner I/O 证明。

分组命令示例：

```powershell
dotnet run --project tests/StreamLink.MeshRunnerTraversalTests -c Release -- --native out/native/udp2raw-protocol-test.exe --rounds 1 --output artifacts/pair-window.json --opportunity-only
```

`--tcp-retry-only` 验证原生第二轮恢复，`--upgrade-only` 验证 UDP 降级与升级，`--baseline-only` 跑原有正式集成回归。不带分组选项时包含所有组。不要并发重建仍在运行的同一个 Windows exe。
