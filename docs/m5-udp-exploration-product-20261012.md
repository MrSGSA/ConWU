# M5：UDP 多源探索接入正式产品

基于 `d40e66e` 继续实现执行计划 §8.4。独立 capability、签名候选、正式工厂、Runner、同 socket 接管、全机增强准入和设置已经接入。**功能默认关闭；本次不升级公网 NAT 覆盖、Wintun 或八真机发布 Gate，也没有替换现用服务。** 已发布的 0.5.2 包不包含这些后续修改。

## 正式流程和资格

普通打洞优先。UDP 的第二轮才可以进入探索，且需要本机显式开启、UDP 备用许可、双方及协调服务独立声明版本 1、足够的共同剩余期限。旧端或旧服务继续普通 UDP；不把 TCP 预测或来源学习能力当成 UDP 探索授权。探索期间发现目标已有健康路径，会取消候选；高成本名额出队时再次核查。

签名候选声明稳定/严格角色、随机证据编号、观察时间、授权目标端口集合及证据范围。双方必须恰有一个合格稳定端。后续消息不能扩大最初协商的授权。探索上下文使用独立的认证域；普通候选省略新增字段，保留既有签名字节及普通提名上下文。

生产自动资格目前只包括：实际物理网卡的原生公网 IPv4，同一个持续持有的源访问至少两个不同 STUN IP，观察映射都等于实际本地端点。生产在分配源之前拒绝回环、私网、CGN、文档等非公网对端地址。反射结果和正式准备阶段也复核公网地址及物理出口。

`PeerPorts` 证据接口绑定同一实际资源、UDP、出口代次、对端 IP 和每个授权端口，但**尚无生产侧 peer-port 观察提供者**。本轮使用它的确定性正例是显式注入夹具。Akane 的多个 STUN 返回同端点，不能据此批准对某个对端全部猜测端口的稳定性；没有资格的私网源明确退出，不偷偷扩大扫描范围。

## 源资源、期限和成本

`UdpExplorationSeed` 在公告前持有一个真实 `UdpTraversal`，它的首次 STUN 准入开始同一个 12 秒单调时钟和 512 包/256KiB 轮次账本。排队、后续观察、扩池、检查、选择及提名只能使用剩余时间，不能重新起算。全机 60pps、突发、维护保留和 TCP/UDP 共用高成本名额保持有效；失败按 pair/出口代次进入五分钟冷却。

稳定端保留一个源；严格端请求总共至多 32 个源，**已观察的 seed 包含在 32 个内**。实际配额不足时减少新增源数。显式实验扩池上限 40，正常配置仍为全机八资源，Active/Candidate/退役引用均占额度。日志区分实际打开的源、准入包和不同试探端口；实际外部存活映射数保持 `Unknown`。

接管不重绑端口、不增加第二个接收者。原 socket、SocketResourceId、DF 和接收循环延续到正式业务。接管密钥与新探索源保持相同的两级 HKDF；本次首轮发现 seed 少一级派生，保留失败产物，修复后复测。未获胜源关闭，获胜源通过 Select/Ack、MeshLink 双向验证和路径内共同提名后交给 Router。准备对象结束不能关闭仍被 Active 引用的源；最终路径结束才归还名额。

健康 FakeTCP 仍受 `PreferFakeTcp` 保护。已认证、MTU 合格的 UDP 探索路径仍标记为降级直连，没有从连通性推断 50Mbps 串流质量。没有服务器或其他成员代转业务。
