# M3：兼容组网控制报文准入与错峰调度

基线 `9f09e69`。本次将兼容路径上 MeshLink 的 Hello、握手回复、候选挑战纳入既有全机搜索预算，并保留 Active ping/pong 与恢复探测的维护分类。内层业务帧不进入这些低速控制桶。

## 修复的行为

此前兼容 Router 的握手包直接发送。健康路径的普通保活和恢复探测已经受维护桶约束，但并不意味着兼容建链阶段也全部受限。

接入准入后，七邻居回归首先发现了集中调度问题：全体成员在同一个周期内发送，未健康成员还可能在两个分支重复发 Hello，瞬间耗尽突发令牌，握手回复无法及时发出。保留失败产物 `artifacts/m3-legacy-control-seven-20261012.json/.log`；这不是严格 NAT 不可达，也不能靠扩大预算掩盖。

修复采用已有 100ms 调度周期，每次最多处理一个到期的兼容成员，公平轮转，每成员保留约 1.5 秒普通检查周期；没有端点的成员不占这个机会。候选变化只安排一次尽快检查，不再从多个调用点直接突发；消除不健康候选的重复 Hello。认证回复仍可立即领取预算，不需要等待自己的定时轮次。失败的挑战发送不建立虚假的“已发出 nonce”记录。

这项改动不更改 native SYN/HTTP/bare、FakeTCP 数据报或约十二秒健康窗口，也不增加 NAT 覆盖承诺。新候选最多增加一次本地调度等待；不能仅凭本地调度变化宣称公网建链更快。

## 诊断的边界

`TraversalResources.Usage()` 和 `SessionStatus.ControlAdmission` 暴露同一账本进程生命周期内的搜索/维护准入数、延后数、准入字节，以及通过该账本取得的 UDP 资源当前值与峰值。切换成员或一次 Attempt 结束不会重置这些累计值。

**准入不等于实际发出。** 取得额度后仍可能发生发送失败或取消；不同调用点提交的是各自已计量的帧长度，不能把累计准入字节当作物理出口计数。没有通过此账本取得的 socket、TCP 独占资源、内核 helper ACK/SYN/重传和旧独立 native 实例的全部开销也不能由这些值推出。剩余线上统计及兼容原生调度继续作为未完成项。

## 验证

本地用例覆盖以下实际行为，最终数据与源码哈希见 `artifacts/m3-legacy-control-*20261012.*`：

- 一个真实兼容 Router 与七个认证回环端点，从建链到同路径恢复，存在实际维护额度竞争。
- 一名有效成员突发发送 300 个 Hello，核对真实回复、准入与延后计数；同一连接仍可交付 24 个完整认证内层 IP 包。
- 独立账本的共享突发、搜索/维护分类、字节累计、资源峰值和最后释放；正式 Runner 状态携带准入诊断。
- 原有 Router 的共同提名、旧路径保留、迁移、业务恢复、健康与退出；正式服务映射/协调生命周期；UDP 同 socket 和 NAT 模型回归。

最终 `m3-legacy-control-final-20261012.json/.log` 通过 **206** 检查：300 个已认证 Hello 实际产生 8 个回复，对应 8 次搜索准入、292 次延后，随后 24 个完整业务包全部交付。七邻居均完成恢复，成员注册起算确认约 3.98–7.13 秒；有效观测约 6.33 秒内 158 个维护帧，最大滑动一秒 31 帧。这里存在令牌竞争，不能把本机受控观察外推成公网建链上界。

`m3-legacy-control-runner-final-20261012.log` 通过 **70** 项服务检查，`m3-legacy-control-traversal-final-20261012.log` 通过 **87** 项 UDP/预算检查；`m3-legacy-control-app-build-20261012.log` 的 Release 构建零警告、零错误。新诊断与协议没有增加密钥/配对信息输出。

回环 UDP 为真实 I/O，IP 适配器和远端响应器为受控夹具；没有 WinDivert、Wintun、真实 NAT、八台 Windows 或生产配置修改。候选包仍保持 c10af12 的独立归档；本次代码需后续整包构建。源码回退基线为 9f09e69，不对现用安装服务执行回退。
