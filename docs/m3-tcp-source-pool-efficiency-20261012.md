# M1/M3：TCP 源端点池的独立等待与观察复用

基线 `43c4b29`。正式受管 TCP 候选池此前用一把锁覆盖所有反射连接的建立、查询和维护；一个 STUN 回复超时会挡住其他源端点。七个成员同时借用同一资源时，也会依次重复查询。

## 实现与边界

- 注册表只负责有界的端点登记；每个实际本地源地址与反射目标组合分别串行收发。不同组合能够独立建立、观察和维护，同一组合仍只有一个独占 helper 和捕获所有者。
- 同一仍被持有、查询和捕获均未失效的资源，普通候选可复用两秒以内的观察值。两秒是新增工程初值 `TraversalLimits.TcpCandidateReuseMs`，不是 RFC 参数，不改变独立的预测新鲜度约束。
- 每个成员仍有独立候选 ID、Attempt 和认证流程。正式候选保留原查询的 `ObservedAt` 与到期时间，不因借用缓存延长公告寿命。复用映射观察不证明 EIM、入站可达、双主动成功或业务质量。
- 等待中的取消不触碰 helper；实际查询被取消后，只退役该查询流，现有原生会话继续持有其源与捕获。捕获已失效时，近期缓存也不能再发候选；替代源与仍被 Active 使用的旧源并存计入真实 TCP 额度。
- 普通 TCP 资源上限仍为八个，注册槽也有同样上限。失败且没有使用者的空槽回收，多个关闭请求共享同一清理任务；关闭等待在途查询、捕获退出和既有工作者引用释放。
- 维护仍按原约十五秒周期及全机控制预算进行；取消和失败不为其他源重置预算。HTTP/SEQ、握手及业务数据 profile 未修改。

改动已接正式 `MeshCandidateFactory` 的普通 TCP/IPv6 收集路径。默认 `legacy` 仍沿用现有入口，不自动启用 SO 或其他实验开关。校准与预测的专用独立源不读取此普通缓存。

Runner 本次两机夹具的选中时间分别为 UDP 6.467 秒、FakeTCP 7.420 秒。这不是与旧版本同条件的性能对照，也不是公网、八台真实 Windows、物理 WinDivert/Wintun 或严格 NAT 成功率证据。查询隔离用例要求另一个目标在一秒内完成，且被阻塞目标仍未完成，而不是等其超时后误判为并行。
