# M6：复用普通保活的空闲路径观测

基线 `c10af12`。正式 Router 和服务增加 `StablePath`，补充没有业务流量时的恢复诊断。它与 `FirstBusiness / StableBusiness` 分开：只有认证往返而没有内层 IP 包时，业务字段继续为空，不提升负载质量等级，也不改变 PreferFakeTcp 策略。

## 接线和口径

- 复用原有约 1.5 秒一次的所选路径保活，不增加空闲快速探测、socket、接收者或线程。兼容路径的普通 ping 发送也纳入已有全机维护桶；回复原已计入。受管 native 仍在实际注入时计账。
- 保留实际发送成功的 nonce，只接受当前所选路径返回的认证响应；候选、退役路径、重复响应和过期响应不能增加样本。最多四个在途记录。
- 十次普通往返、至少三秒观测、当前健康且没有未决请求后，记 `StablePathStartMs / StablePathConfirmedMs`。默认节奏下通常需约 13.5 秒以上取得十个样本，**不是三秒内确认，也不是因此延迟业务开始**。
- 每个响应期限为一秒；超过 3.5 秒没有新的成功样本时，未完成的路径观测窗口重启。预算不足或调度延迟可以推迟确认，不会制造成功证据。高 RTT 环境可能只有连接而得不到此低延迟观测。
- 已确认结果属于历史区间，不是未来稳定承诺。实际健康丢失、路径改变或业务发送拒绝后，新 episode 重置两类证据；保持原约十二秒健康判定，不因一秒的观测阈值直接断开网络。
- `MeshPeerStatus.Recovery` 增加路径字段，服务按 episode 输出一次 `StablePath`，明确提示不代表业务恢复或负载质量。

仅同路径往返证明可达性，不等于 50Mbps、零丢包、TCP NAT 类型或公网打洞成功。业务稳定仍需要真实内层包通过本机 IP 适配器，以及独立的业务恢复探测。

## 验证与发布

`RecoveryTests` 增加空闲、过期与重复回复、路径改变、健康丢失和预算/调度间隙的负例；兼容与受管 Router 使用真实回环 UDP 和内存 IP 适配器，先完成空闲往返，再提供真实认证业务，分别确认两类统计。服务测试在协调查询阻塞时检查状态字段与一次性日志。

`RecoveryBudgetTests` 使用一个正式兼容 Router 和七个认证的回环响应端点，验证维护流量竞争下的延迟与计账。七个端点只是模拟不同远端设备，不能代替八台真实 Windows、原生封装开销或真实 NAT。结果与精确源码收据保存在 `artifacts/m6-idle-recovery-*20261012.*`；未执行的系统或公网 Gate 不标通过。
