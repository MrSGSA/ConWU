# M6：负载证据、共同选路与合格备用恢复

基于 a2bb38a，继续保留 Wintun/MeshLink/udp2raw FakeTCP＋HTTP、相同 HTTP/SEQ profile、无业务重传/跨包等待、无服务器或成员业务中继。本次完成实验 AutoQuality 正式 Factory/Actor/Router/Runner/设置/IPC 接入；准备 0.5.4 开发候选。未安装到现用服务，未更新公网协调服务；整体 M0—M9 发布 Gate 仍为 NotPassed。

## 实现与保守边界

- 本机需显式选择 auto-quality、开启备用与空闲诊断，并配置至少诊断目标 1.4 倍的共享出口额度。默认仍 prefer-faketcp，所有诊断/备用/自动切换默认关闭。
- AutoQuality 是独立版本能力；双方及协调服务都声明 1、诊断目标相同才授权。仅支持诊断的旧客户端/服务不会因此获得自动切换权限。
- 12 个有界窗口构成 Active/Candidate、双方向、各三次 5 秒观察。证据对应实际 PathId/LeaseId/网络代次/加密 epoch；窗口年龄分别检查，不通过空载 RTT 推断容量。
- 当前保守实验资格：有效接收载荷速率达到配置目标、截止缺口不超过 0.1%、加载 RTT p95 不超过 50ms、相对到达变化 p95 不超过 20ms；发送窗约 4.9—5.5 秒，无本地诊断拒绝且入队数与最终准入数一致，至少两个加载 RTT 样本。这里的相对变化不是单向延迟；绝对 50ms RTT 门槛也不替代规格中相对空载增量的完整验收。
- 普通切换需至少一个方向三个窗口都持续改善，另一方向无明显退步；驻留至少 30 秒、普通冷却 60 秒。相近路径保持 Active。
- SQV1 批准绑定当前备用上下文、诊断 SessionId、目标和完整报告 SHA-256；排除各机不同的本地资源 ID/时钟以使双端摘要一致。批准最多 8 秒、17 条重发，仍通过已有维护额度及实际线上计账。双方批准后继续 SLN2 共同提名，批准本身不直接转发业务。
- 共同提名与实际切换再次验证资源、epoch、证据和策略。普通 AutoQuality 枚举不能解除健康 FakeTCP 的 UDP 保护；默认 prefer-faketcp 即使收到批准也保持保护。
- 硬故障可跳过驻留/冷却，但备用自身的双方向质量、MTU、同路径双向新鲜度和双方批准仍必需。Active 的旧窗口过期或本地测量失败会取消普通收益比较；不能因此抹掉备用自身仍新鲜的证据。
- 保留旧 Active 的所有权及提名失败回退机制；选择复用备用现有 tuple，不为同一 TCP 四元组新建另一套 ISS/ACK 状态。
- 桌面 IPC 保持 64KiB，显示成员质量与诊断摘要；完整窗口仍在 Runner 诊断记录和验证产物中，显示副本不修改用于选路的证据。质量结论变化才写简短日志，避免逐 tick 重复。

原生收益与 UDP 保留正例使用修正后的低速源信用上限；之后高码率信用改为按同一额度的有界抖动余量计算，1Mbps 正例仍为相同四帧上限。最新 Core 的普通 Router 和 Active 过期后的真实 worker 恢复已复跑。所有联调的目标为 1Mbps，不能据此宣布正式 50Mbps/WAN/播放时限 Gate 通过。

上述产物之后还补了共同提名完成前的最终批准检查、选中前业务准入及原 Active 资源的硬故障判断，避免把候选提交过程误判为原路径故障。完整 Package 将在准确候选提交上复跑三类正式流程；发布收据单独记录结果，不把前面的历史正例冒充最后一次构建的网络验证。

首个 c63ee5d 完整 Package 在最后的旧窗过期断言停止：固定 13 秒没有适应此次更快的窗口流程，尚未进入杀进程阶段。测试改为按双方实际 ObservedMs 等待首个 Active 窗口过期，并等待状态发布，保持原合格备用与过期断言；新准确提交重新构建验收。先前完整流程不会整体计为通过。

f2b3594 的第二轮完整 Package 在 UDP 质量保留用例停止：第 5 窗入队 508、最终准入/接收 507，存在一次本地诊断额度拒绝。质量规则正确返回 Unknown，不能将它当网络丢包或让测试跳过该证据。

进一步修复将诊断额度的可发送时间接入共享出口队列：不足时使用原精度计时器等待，不抢占业务预算、不增加缓冲、不重发已发送数据。额度仍只在最终注入点扣除；过期/取消仍走有界终态。原生 capture 与同 socket UDP 使用同一机制；普通业务包不加这一等待条件。一个诊断等待头不阻止其他成员及维护队列进入。

新增 m6-diagnostic-readiness-first-20261013.json 实际计时器/队列检查：12 个低速突发全部准入、零拒绝，其他成员继续、账本守恒、过期不注入。修复后的正式 UDP 保留 12、原生受控收益 14 项检查通过；memory raw/IP 与 1Mbps 范围保持。50Mbps 普通单/七成员持续队列回归满足既有 98% 本地吞吐门槛。最新准确源码的完整包结果另行记录，两个中止的整包结果不算通过。

## 保留失败与诊断发送修复

初轮原生测试误用生产后端，未完成 ABI 2 夹具接入；随后按测试要求使用 protocol-test。失败日志/JSON 保留，不能计为通过。

后续真实诊断发现：原生维护拒绝数混入诊断摘要，且发送线程会在延迟唤醒后补发全部欠账，使快出口上的低速诊断触发自身最终额度。现在分别采用诊断 Permit 的拒绝计账及按同一最终额度约束的有界发送信用；低速最多四帧，既有源预算、会话 90 秒/256MiB、共享 pacing/有限队列保持。

首个四帧固定信用试验的三段目标 50Mbps 接收约 47.325/48.808/48.828Mbps；保留为性能不足。改为额度约束的抖动余量后，三段接收约 48.996/49.340/49.998Mbps；第二段有 7 次本地拒绝，第一段有截止缺口，不能写成全程 50Mbps 无丢失。它只说明诊断数据面实际执行完成，完整性能 Gate 未通过；常规已有效业务承载没有改动。
