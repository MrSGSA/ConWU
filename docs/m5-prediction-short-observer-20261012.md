# M5：条件预测模型与 TCP 短窗口观察

在 `31f8ff7` 的原生控制包计账基础上继续开发。本次完成预测模型及准入、正式工厂的诊断报告，以及可在两秒内取回结果的 TCP 观察接口；**尚未把预测候选接入正式 MeshRunner 协商，M5 整体未完成。**

## 实现

`NatPortPrediction` 按协议、接口、源地址和网络代次分开建模。至少 20 个分离窗口，按时间前后拆分训练和留出，后者至少一半。端口保留、观察端点稳定、固定步长、已观察小端口块四种可解释规则只在训练部分选择；留出失败不换模型重新拟合。两部分覆盖均须达到 90%，且各自都有基线与已核实的背景分配干扰。

- 同窗口必须来自同一个实际资源、capture owner 和本地端点；观测 ID、窗口和本地/目标 tuple 不能重复。内核 TCP STUN 不能代替原生 TCP 证据。
- 最多预测 8 个合法端口；不会把本地临时端口范围当作 NAT 端口池，也不假定端口回绕。
- 取样、预测和真正领取预测时均检查资源；年龄从**本机首次发起探测的单调时钟**计算，不因服务器 UTC、重复回复或本机改时延长，初值小于两秒。单调时间戳仅用于本进程，不是跨机器时间或可持久化授权。
- 每条观察只能使用一次；两次已领取的实际尝试连续失败就停用模型，切换网络使旧模型失效。取消不冒充路径失败。一次认证成功可清除连续失败计数。
- 模型最多保留 128 个观察窗、64 次预测领取前的观察；调用者仍须持有实际资源、使用全机/Attempt 预算并协商候选。模型自身不分配 socket、不扫描端口、不认证对端。

TCP 正式工厂把现有原生 SYN 观察转为预测资格报告，保存在本地 `tcp-port-prediction-qualification.json`。同一票据四个目标只算一个窗口；它没有测量背景干扰，因此不能自行开启预测。原有每工厂生命周期最多八个观察资源、每成员两张保留票据等限制未放宽。

这种保守门槛对应共享分配器、并发分配和多层 NAT 可能破坏预测的限制；协议独立观察也继续保留。[RFC 5128](https://www.rfc-editor.org/rfc/rfc5128.html)、[RFC 7857](https://www.rfc-editor.org/rfc/rfc7857.html)。

## 短窗口协议

原先八秒窗口结束才读取结果，无法充当两秒预测的新鲜锚点。新增 `register-fresh` 操作，由既有成员签名覆盖，catalog 必须明确返回 750ms 能力。每张短票据最多两个固定登记目标，每个目标最多两个同 ISS SYN。

客户端使用原 `TcpCaptureOwner` 和持续持有的独占 helper；不重新 bind P，不另建捕获所有者。原生发送继续使用维护控制预算。客户端等完整捕获窗口结束后读取，必须获得服务端 `Final=true`，并再次检查本机年龄。旧服务、时长不匹配、未结束的结果、慢登记或慢读取均不能提供可用预测锚点。

服务端用单调时间关闭短窗口，但仍保留完整 60 秒的 ISS/目标冲突保护。重复登记不续期；窗口内不同来源返回 Ambiguous；关闭后迟到的 SYN 不能修改最终结果。短窗仍只有 `SynObserved` 级别，握手和完整 profile 均为 `NotTested`。没有新增业务转发或额外 SYN payload/option。

旧 `register` 保留八秒窗口。新增回复字段有兼容默认值，不改已有请求签名结构；旧客户端仍可使用旧操作。正式后台诊断仍调用旧窗口，短窗口目前供显式实验/未来预测收集器使用，未自动开启。

## Windows 物理出口到公网的短窗补测

`m5-observer-public-20261012-020256.json` 使用 Thinkbook 物理源地址、已有 WinDivert 和服务器限时 Linux 观察进程。一次两目标短窗，共提交四个原生 SYN：已知普通 TCP 可达的目标取得 `SynObserved`，原高位对照目标 `NotObserved`。

完整探测接口耗时约 1907ms（包括 catalog/登记/读取），返回时两条记录对应的首次本机发起年龄分别约 **1476ms、1310ms**。前者是实际观察到的来源，后者只有探测发起、没有观察结果。同一 kernel helper 前后查询成功且公网端点相同；结束时 owner 的 session 为零。

这证明短窗口在本次实际公网路径上能提供两秒内的原生来源观察。它**不证明预测命中、SO、HTTP/bare 或 MeshLink 业务通过**。只有一个服务器公网 IP，未完成完整映射/过滤分类；未取得线上 RST 抓包证据。控制 HTTPS 经临时 SSH 回环转发，探测 SYN 直接走公网，不转发业务。

复现脚本为 `scripts/Invoke-TcpObserverPublicFollowup.ps1 -Fresh`，需显式指定自有观察目标、独立目录和已有 WinDivert。限时服务在新隔离目录运行，保留原生产协调服务和 StreamLink。没有安装驱动或修改防火墙、路由、Lucky、网卡及 VMware。

补测后核实临时 43983 监听已关闭，生产 `streamlink-discovery.service` 仍为 `active`；Linux 回环测试进程也已正常退出。
