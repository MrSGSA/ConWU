# 匹配的个人协调服务

交付协调包包含全部 linux-x64 self-contained 文件，不能只上传 apphost。只准备/部署独立个人实例，不更换旧线上服务；实际服务器部署与公网 HTTPS 路由状态以本次交付的 server-deployment.json 为准。

2026-10-14 公网 `/health` 仅声明旧 protocol=3、metadataProtocol=2、shortPairing=true，没有 meshProtocol=4/meshTraversal=1。旧服务可继续供 0.3.2 使用；不能假设它已经支持新 Mesh/SO/来源学习。

需另建 `streamlink-personal-v3.service`，目录 `/opt/streamlink-personal-v3`，状态目录 `/var/lib/streamlink-personal-v3`，HTTP 入口 `127.0.0.1:42863`。部署脚本发现已有同名服务或安装目录会拒绝覆盖，不修改旧协调、STUN、SearXNG/Tunnel。审核后显式运行：

```sh
sudo sh /绝对路径/coordination-linux-x64/Deploy-PersonalCoordination.sh /绝对路径/coordination-linux-x64
curl --fail http://127.0.0.1:42863/health
```

在原 Cloudflare Tunnel 中增加独立域名，例如 `streamlink-personal.space4sgsa.com`，服务地址填写 **http://127.0.0.1:42863**。无需用 Tunnel 承载 STUN，也不添加任何业务转发。

客户端填写对应 HTTPS 域名。健康返回至少应包含 meshProtocol=4、meshTraversal=1、relay=false。校准/预测还需要独立 TCP SYN 观察设施和资格；普通 STUN 并不能替代观察器。未部署该设施会准确跳过预测。

恢复旧协调仅停止 `streamlink-personal-v3.service` 并撤回新域名路由；保留其状态目录，不覆盖旧服务及成员目录。用户自己填写服务器，不预置私钥或配对凭据。
