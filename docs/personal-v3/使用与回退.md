# StreamLink 个人功能先行版 v3

这是完整的个人候选文件包，不是已通过全部验收的版本，也不是公众 1.0。当前自研 TUN 已编译、产品接线并包含在包中，尚无签名/实验机/真实内核 Gate；不能在两台日用机实际启用。不会自动切换或加载它。

1. 两台机器各自保留原 0.3.2 完整安装、同机 DPAPI 配置和原协调服务。不要互拷加密配置或复制现用私钥。新版服务名、管道、ProgramData 与 ProgramFiles 均为 `StreamLink-PersonalFeature`；源端口默认 44691、监听默认 44680。
2. 先按《协调部署》准备匹配的独立 HTTPS 服务。运行新版 `StreamLink.exe` 管理入口，填写该服务；创建新的个人 Mesh 网络，在另一端输入 6 位配对码，双方核对校验码。不要导入旧日用配置冒充隔离。
3. 设置中“应用个人增强预设”启用现有 SO、来源学习与同 socket UDP 备用，保留已明确禁用和预测/概率/压测的独立许可。运行中的健康个人会话须先停止才能应用预设；不会影响另一个 0.3.2 服务。
4. “检查新方法准备状态”只验证配置及网卡准入，不等于打洞成功。启动后查看三项事实：实际虚拟网卡、实际建链方法、实际业务承载。UDP 可用只表示降级直连，不抢占健康 FakeTCP，也不证明能绕过 QoS。
5. 自研网卡选择必须有受保护完整包、适用签名、实际设备与本机批准的内核证据。当前选择它将明确拒绝并保留原连接；不把 Wintun 显示成自研 TUN。先在可恢复实验机完成《driver-gates》，再分别授权日用加载。
6. 可选安装个人后台服务并明确选择日常账号；普通窗口只读取非秘密 DTO。驱动首次加载、Verifier 或系统安全策略不在后台安装授权之内。

本轮保留的主要限制：官方 Wintun 关闭在真实并发测试中可超过原 3 秒门槛；源码/模型/旧 overlay 验证不证明校园网物理 NAT4 新覆盖。具体通过、失败和未测见交付报告及逐项证据。未通过项不可用“开关关闭”包装成全部完成。

第一次实际试用：先部署独立协调并查看 HTTPS `/health` 的 Mesh4/Traversal1/relay=false，再以官方 Wintun 创建新的个人网络。两端启动后须同时看到“已直连”及实际 IP/承载。将串流或其他应用的目标改为 **新版显示的对端 IP**，不要沿用 0.3.2 的地址。先低码率核对连接，再以 50Mbps 验证。个人准备检查现在会拒绝未创建/加入 Mesh 的配置，不再跳过协调核验。

如果停止超过正常时间，先保存日志，确认个人 worker/native PID 退出后再启动；资源退出未证实时后台会拒绝建立第二 owner。不能停止旧 0.3.2 来排查新包。没有完整当前双机/负载证据时，只作为隔离候选试用，不直接接管唯一远程管理通道。

回退：停止 **个人实例**，确认 worker 已退出，再卸载 `StreamLink-PersonalFeature` 后台服务；程序的 `--uninstall` 只指向该服务。保留个人配置与日志。原 0.3.2 未替换，可直接继续使用原 IP/配对。不要删除共享 Wintun/WinDivert、原 Lucky 映射或旧服务。自研内核故障需要独立本地/离线恢复，不能承诺应用热回退。

本人试用验收：在允许的配置上分别停止/重开 5 轮；看复制 IP、设置草稿跨 3 次轮询、取消、错误网卡准入反馈；按 50Mbps/20秒双向顺序记录零丢目标；再实际串流约 10 分钟记录卡顿、重连和应用统计。未经本人确认，实际串流项为 PendingUserTrial。C2 单端自研角色互换与 C3 双端自研必须等内核准入完成，不能用 C1 的 Wintun 成功代替。
