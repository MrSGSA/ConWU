# 第二轮：固定 5d1fb051 的产品与回归复审

本轮使用独立只读上下文检查完整用户路径、控制取消、停止/重启、失败隔离、设置保存、安装回滚、打包依赖与默认能力。与第一轮的原生/驱动安全检查分开，不以重复实现总结代替审查。

| 编号 | 分类/级别 | 结论与修复 |
|---|---|---|
| SA-11 | ConfirmedDefect / P1 | MeshRunner 关闭错误被控制层记录后，running 任务仍可正常结束；End 随后清引用、报告停止，Dispose 释放控制锁，可让第二 owner 进入。现在完成任务后仍核查资源失败标志，拒绝启动/保存新启动状态，保留失败的 runner 和具体 owner。Dispose 后将失败 worker 强引用隔离到进程结束，防止 FileStream finalizer 提前释放锁。UI 显式退出记录脱敏错误并结束自身，不触碰服务或旧版。 |
| SA-12 | TestContractDefect / P2 | 保护证据的祖先 ACL 检查把默认 ProgramData 上允许创建兄弟目录的规则当作替换已有保护文件的能力，并读取隐藏目录失败。现在区别叶文件写权限与祖先 DELETE_CHILD/删除/改 ACL 权限，忽略仅继承到子项的 ACE，使用 Force 只读隐藏目录。正例及两种真实 ACL 负例通过；不修改系统目录 ACL。 |

SA-11 的定向测试使用独立进程和真实 runtime.lock：停止失败与本地停止拒绝、Dispose/GC 后第二 owner 拒绝、原进程退出后可重新获得锁。关闭故障注入另检查独立清理继续执行、失败 owner 强引用保留。不是实际原生资源关闭成功的证明。

SA-12 的定向测试只修改本次创建的随机 ProgramData 子目录和文件，核验默认祖先、可写叶文件拒绝、可替换祖先拒绝；清理边界核验后删除自有测试目录。第一次隐藏目录读取失败保留，不回写通过。

修复后的 App 编译发现 ProfileStore 命名空间缺失，已补导入并再次编译；原编译错误保留为本轮开发证据。第一次完整核心回归在发现 SA-11 后主动中止，记录为 AbortedForConfirmedFix，不能算完整回归通过。新提交固定后再执行一次完整核心回归。
