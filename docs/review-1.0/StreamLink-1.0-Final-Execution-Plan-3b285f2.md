## 0. 给 Codex 的总执行指令

从当前真实工作树继续，不重做已实现模块。先读取仓库指令、交接报告、本规格、配套审查与任务清单。若HEAD已超过3b285f2，映射新增提交与对应任务；旧行号仅是审查定位，按当前函数核对。保留用户未提交改动，不自动reset或改写历史。

本轮目标同时包括：**修复明确缺陷、补交接代码余项、让更多网络获得合格FakeTCP直连、改善普通用户体验、完成网卡适配自主化，并实际启动有边界的自研驱动工作。** 不是只改版本号，也不是再写一份未接产品的框架。

优先级冲突时：安全/不破坏系统与已有Active > 核心FakeTCP建链和质量 > 用户工作流与交付 > 高成本探索 > 新内核后端替换。完成已授权代码、构建、隔离实验与打包后持续推进其他可做任务；不在每个小Gate重复要求审批。需要真实生产变更、重启、驱动测试机或签名凭据时，明确列出操作/环境/回滚，而不是擅自扩大权限。

### 0.1 不可变业务约束

- Windows原生、自包含发布；用户不需EasyTier、Lucky、WSL、Python、开发SDK。
- 最多八成员；每对独立直连。协调/观察服务只处理控制，不承载业务；成员不转发第三成员业务。
- 默认保留Wintun → MeshLink → udp2raw FakeTCP＋明文HTTP特征。HTTP Host只是报文特征，不是CDN中继或TLS。
- 外层不增加业务可靠重传和跨数据报按序等待；内层应用TCP由端系统处理。
- 保留当前HTTP/bare序号、seq-mode及有效报文兼容快照；解析安全修复与有效协议形状改变分开提交。
- 0.3.2稳定生产环境是体验参照，不是新版长期稳定性证明；不得未经授权替换运行服务或协调实例。
- 自研驱动不能通过关闭Secure Boot/HVCI、绕过签名、加载漏洞驱动或全局删除别的软件驱动交付。
- 缺原生IPv6时走IPv4；不得用VPS/第三方隧道“硬开IPv6”违反禁止业务中继。

### 0.2 文档优先顺序与结束条件

本规格在1.0范围、发现问题、执行顺序上替代此前宏观建议；原M0—M9中未冲突的协议不变量、资源限制和证据要求继续有效。最终交接报告优先于旧0.5.6早期preview说明；代码与原始产物优先于“已完成”文字。

同一失败无新假设/代码/环境变化，最多再做一次定界复现，然后转定位或记录阻塞；不无限重跑完整Package、小时负载或坏网络。每次长测试先检查环境与依赖；文档/清单元数据改变不自动触发全部网络复测，但必须更新来源关系。

## 2. 1.0 定义、默认能力与晋级

1.0应交付：普通用户能完成配对并判断连接状态；健康链路不因设置、探测或失败候选被破坏；至少一项新增TCP/FakeTCP策略证明救回原默认方法失败的场景；新增算法按资格自动使用，不依赖普通用户手动猜开关。

### 2.1 能力层级

| 层级 | 行为 |
|---|---|
| FormalAuto | 已通过安全、集成、指定真实覆盖与质量Gate；双方/服务兼容时自动尝试 |
| Conditional | 实现完成，有时效证据/网关/地址族要求；资格不足是Unavailable，不是实现不存在 |
| Experimental | 明示风险、预算与证据等级，独立许可，默认不运行 |
| Unsupported | 不建立接收者、不分配试探资源，不在界面虚报可启用 |

优先晋级：显式入口与角色反转、SO、TCP来源学习；其后有置信度的小窗口预测、基础UDP降级、已验证网关映射/原生IPv6、被动反馈与合格备用。高成本概率、多路径条带化、自动负载选路、新驱动替换不因为版本号自动晋级。

**REL-03默认晋级规则。** 每项运行资格为：`本地实现 ∩ 本地发布许可 ∩ 用户意图 ∩ 对端能力/许可 ∩ 控制版本 ∩ 本轮证据 ∩ 资源额度`。服务端只有能力声明，不能用未授权远程开关强行启用实验。用户曾明确禁用的值应保留；对旧版本“默认false”与“明确关闭”增加迁移语义，不能一律翻true。

### 2.2 三种用户策略

- **推荐**：PreferFakeTcp＋已正式晋级的低成本穿透；允许用户选择是否接受明确标识的UDP降级。
- **兼容**：已证明的传统入口、保守恢复，供定位和回退；不强制禁用已经可用的业务。
- **实验增强**：显式启用有限校准、预测/探索等；依然受签名、期限、额度和健康Active保护。

新能力不能永远停在“功能存在但所有人默认不使用”；晋级必须有逐功能结论和默认配置测试。若所有核心穿透证据仍不足，交付RC并清楚说明，不能宣传“严格NAT成功率大幅提高”。

## 3. 第一批：漏洞与可靠性修复

### SEC-01：原生TCP解析契约，发布阻断

定位：`network.cpp:2184–2215`、`client.cpp:387–411`、`connection.cpp:595–612`，详见F01。最小头长在访问字段之前判断，非法头长/选项返回负值，失败输出置空且接收状态不半更新。检查所有`recv_raw0`调用者，不只修一个分支。

新增真实解析函数单元/模糊测试：IP截断、TCP载荷0–19B、doff0–15、TCP选项越界、扩展/分片策略、合法HTTP/bare。保持现有SO630测试。先最小修复，再扩大原生接收源范围；不要把修解析的提交顺便变成HTTP序号规范化。

当前已经确认代码缺陷和隔离前缀复现，**尚未确认公网可利用性或崩溃方式**。Codex需要在旧native与broker两条路径测试实际可达性，分别记录，不给未证实漏洞编CVE或RCE结论。

### SEC-02：完整原生输入与依赖审计

覆盖`network.cpp`、`native_backend.cpp`、`native_so.cpp`、`NativeRawChannel`/`NativeAttachment`/`TcpCaptureOwner`，以及实际解密/长度/GRO解析。模糊测试使用离线帧语料，不向公共主机发异常包；可控Windows负例需精确过滤/隔离。

区分offload未完成校验与真实线上坏checksum。不能直接恢复一条`return -1`然后让有效出站offload包失效；也不能继续无条件信任坏入站。共享语料证明managed/native拒绝策略一致。

审查认证前内存、候选数、发送反射量、长度乘加、日志限速；解析失败不能退出整个broker。固定依赖版本、SBOM和许可证；依赖升级需同profile回归，不把“最新”作为默认安全结论。

### SEC-03：身份、会话、权限与日志

保留MeshLink每成员会话序号/重放共享、epoch轮换、成员源IP约束和迟到候选拒绝；没有证据就不要重构成新密码协议。新增功能必须绑定身份、方向、Boot/Attempt、候选版本、profile、提名revision和挑战路径。内层AEAD不能替代外层安全解析。[W9]

本机控制默认SYSTEM/管理员隔离已存在。GUI降权必须先做UI-04。审查日志快照、状态DTO、导出包、crash dump不泄漏私钥、网络共享秘密、邀请、ticket、完整ControlReply；保留脱敏关联ID即可。撤销状态单调，回退包不回退授权。

现有创建者生成成员私钥、长期ECDH无前向保密为明确的既有信任范围；1.0文档必须如实写明。可准备版本化本地密钥生成/PFS方案，但不能在本轮无迁移验证地替换认证协议。

### CTL-01：可取消控制操作和有界退出

给`ControlWorker.Handle/End`及下游传CancellationToken/OperationId；读状态使用不可变快照，不被长安装、停止、测速串行阻塞。区分取消UI等待、取消未获胜Candidate、停止Active网络，避免误释放。

停止顺序：停止新入场 → 取消候选/发送 → 请求worker退出 → 有界等待 → 必要时只终止本版本Job内进程 → 确认句柄/捕获退出 → 释放最后Lease。超时要报告哪个资源，不用全局驱动卸载消除它。

### CTL-02：统一旧Quality测速和新诊断权限

`Quality.Serve`既有peer授权保留，但接入同一全机诊断会话/出口预算、明确远端测量许可、有限冷却与取消；独立能力版本绑定完整消息语义。手动用户测量是一次有额度操作，不等于常驻允许成员无限请求。

诊断端口冲突、探针失败、反馈格式错误只能使诊断不可用，不得让`MeshRunner`重启网卡/所有peer。结果分实际业务与主动负载；本地Send成功不能当对端送达。

## 4. TCP/FakeTCP主线：把已有实现变成新增覆盖

### NET-01：真实端点所有权和物理收发

复用`TcpEndpointLease/NativeAttachment/TcpCaptureOwner/WinDivertEndpointIo`，不重新创建所有权框架。每源端点唯一捕获owner，授权native不二次bindP；辅助流完整双向tuple排除；源IP、路由代次、AttachId、初始序号及映射观察可追溯。

P→Q显式入口只是已证明入站候选；它不能代替“同P主动流保持公网映射”的SO证据。禁止内核已连TCP四元组与FakeTCP独立状态共用。native崩溃后的RST与正常Armed期间非预期RST分开统计；正常TIME_WAIT不是泄漏。

真实Windows与可控对端做30轮创建/抢占拒绝/捕获就绪/发送/取消/退出，另外检查helper延续。线上零RST需独立观察点和丢包计数，不能仅凭过滤器说“我丢掉了RST”。WinDivert NETWORK无PID、出站忽略接口字段等约束应通过源地址/路由证明落实，不能靠管道PID绑定代替网络tuple所有权。[W1]

### NET-02：SO与来源学习的正式晋级

保留`native_so_state.h`和`native_so.cpp`已有8秒共同期限。先回归交叉SYN、重复、丢包、启动偏差、错误ACK、旧RST和32位回绕，再验证完整legacy HTTP/bare、内层认证、共同提名和应用数据；三类角色分开：TCP外形主动角色、udp2raw client/server、提名控制方。[W2]

同一wire tuple只允许一个live/retiring状态。候选刷新复用该状态；独立握手用新受管端点或串行退役，不能仅换AttemptId保留两个SEQ机器。

来源学习是“允许有限候选端口进入检查”，不是认IP即认人。保留同公网IP多成员隔离、tentative来源、限额、时效与认证后冻结。源端口变化必须由实际原生tuple上报，不能由上层回环端口伪装。

### NET-03：共同提名、Active保护和业务接线

复用`PathNomination/MeshTraversalAttempt/MeshTraversalManager/MeshRouter`。Offer/Ready/Start重复幂等；Ready表示接收/捕获/预算均就绪；共享截止不在每次confirm重置。候选上的挑战响应只能证明该候选，旧Active回包不得替代。

新路径到Prepared时仍保留旧Active；双方提名收敛后切换，旧接收宽限按现有有界设计回收；丢Confirm/Commit时重新同步，不承诺网络分区中的原子切换。取消/超时不复活退役代次，不释放其他peer引用。该流程借鉴ICE检查与提名，不宣称实现完整ICE/TURN。[W3]

### NET-04：观测、校准与预测

按协议、源资源、目标、出口代次和观察时间独立记录。至少保存 `Unknown / EmpiricalEim / DestinationDependent / PredictableWindow` 与置信度/适用目标，而不是只给NAT1/NAT4标签。TCP与UDP默认分别维护，不把UDP打洞成功当成TCP孔洞。[W4]

自有观察服务只报告来源、挑战和时间，不转业务。现有`TcpSynObserver/LinuxSynCapture`可复用，明确SYN被观察、完整握手、legacy业务三层证据。一台机器若有两个公网IP可满足不同目标IP观察；一个IP两个端口不能完整区分地址相关与端点无关。

预测必须用同一持有源资源、独立留出样本、并发背景干扰、确定发送顺序和有效时间；**对端目标端口变动可能使自己的公网源端口也变动**，候选矩阵/顺序应按APDM而非固定端口假定。不同socket的观察不能拼成一个规律。[W5]

校准不阻塞已有直连或前台60秒机会；十分钟校准是独立有进度、有取消的实验，不得让新用户十分钟“正在连接”。基线失败两轮没有新证据后冷却，旧缓存网络切换失效。

### 必测算法增益

使用同一新二进制进行算法关闭/开启配对对照，控制映射冷热、顺序和背景连接；另外与保留的有效自主基线、0.3.2用户体验分别对照。记录旧失败→新成功与旧成功→新失败、成本、首包、稳定业务起点、截止失败。

默认核心晋级至少需要：受控正例30轮可重复完整链路；负例零错误认证/零Active破坏；代表性真实WAN新覆盖。人工改错公告后学习成功是功能证据，不等于真实NAT新覆盖。八设备28关系与一次对等连接的成功率不合并统计。

## 5. UDP与严格NAT增强：安全授权和可达性预测分开

### NET-05：同socket、PMTU及稳定端证据余项

保持`UdpTraversal`唯一收包者；STUN、检查、prflx、业务使用相同获胜SocketResourceId。提名完成先转移Active引用，再结束Attempt；不要跨进程复制两个相同端口socket冒充同资源。仅经实际合法来包学到来源；第一包被NAT丢掉时没有prflx可学。

IPv4内层1280B＋MeshLink64B＝1344B UDP payload＝1372B外层IPv4；IPv6外层约1392B。1400B payload只作余量，不应挡住稳定1344B路径。DF/真实长度/双方向/ICMP黑洞单独测试；原生FakeTCP实际开销另测。不因一个弱候选悄改全网MTU。[W6]

**关键设计评审：当前`UdpStableSourceEvidence.PeerPorts`要求覆盖所有授权目标端口，不能在尚未穿透的随机NAT后凭空获取这些观察。** 补provider前必须评估是否形成“先连通才允许打洞”的循环前提。

采用三层概念：

1. **探测授权**：成员身份、目标IP集合、候选端口集合、预算、有效期，必须强校验。
2. **稳定性置信证据**：PublicLocal / PeerPortWitness / EmpiricalEim，各自记录覆盖范围和有效期；观察不是未来永远稳定的证明。
3. **最终成功**：同一获胜资源上的双向认证与业务，不由证据标签替代。

能实际获得每个目标端口见证时实现PeerPortWitness；不能时返回原因，不伪造证据。另实现有版本、默认实验关闭的EmpiricalEim小预算路线，利用同源多目标、多时刻留出观察；它是可能误判后失败的机会性算法，不是安全授权放宽。证明覆盖增益及资源可控后再考虑晋级。**既不能无限保守到实用算法永远不可用，也不能把预测当密码保证。**

UDP多源探索保持已签候选集合、最多32源/256目标、共享12秒与全机额度；按实际剩余资源降级。真实外部映射数Unknown时不能把32个本地socket写成32个已确认公网映射。简化相交模型只用于一端稳定的概率成本估计，不适用于双端随机APDM＋APDF或TCP全部握手成功率。

### 策略选择矩阵

| 条件 | 先做什么 | 避免什么 |
|---|---|---|
| 任意一端有可达显式TCP入口 | 反转角色、原有单主动FakeTCP | 固定创建者为监听端 |
| TCP映射稳定且SO包序放行 | 原生SO | 要求必须先UDP成功 |
| 一侧可收到对方变化端口 | 有界来源学习＋认证 | 未收到包就宣称prflx能救 |
| 有可靠短期分配规律 | 受管小窗口预测 | 大范围扫描把源映射扰乱 |
| UDP一端稳定另一端随机 | 有限多源/多目标机会探索 | 将端口相交率写成串流成功率 |
| 双端随机严格映射过滤 | 有限普通尝试、模型研究、明确本轮未找到 | 无限重试或暗中成员中继 |
| UDP上行质量差 | 保持合格FakeTCP，UDP明确降级 | UDP先连上就抢占健康链路 |
| 无IPv6 | 原有IPv4策略 | 靠隧道服务器伪装原生IPv6直连 |

## 6. 组网效率、控制面和恢复

### NET-06：降低无效等待，不降低正确性

并行进行网卡准备、HTTPS发现与廉价候选，已验证候选立即尝试，不等待完整NAT分类。缓存最近成功入口/STUN必须绑定出口和原始观察寿命；临时端口筛服务的结果不得发布成正式源端点。

常规八成员仍维护需要的直接关系，高成本探索按实际peer需求/用户动作和公平队列进行。不要把完整网络从主动维护偷偷改为“永远等业务才连”而不改变UI语义。一个困难peer不得堵住其他成功peer。

当前`TraversalLimits`基线：2轻量peer、1重型任务、全机60控制pps/突发8；普通UDP6秒、SO8秒、前台机会60秒。先汇总到单一参数档案并检查旧兼容额度，不按peer复制预算。保活/确认有预留子账本，但不能账外无上限。

八设备×七邻居不允许每人同时独占8端点；TCP/UDP池分别记录Active、Candidate、retiring、observer及探索临时资源。共享broker故障影响多个peer，应整体恢复但公平调度，不制造同时重启风暴。

控制长轮询/事件已存在，复用设备级订阅和签名目录；核对请求总量、512/min网络配额、等待者数量、大小4096字符、客户端长轮询独立超时和代理空闲超时。不要为所有候选对各开永久连接。429退避有抖动，健康Active不因公告过期被销毁。

### QOS-02的一部分：出口、路由与迟到结果

`EgressRouteSnapshot/Cache`已经提供来源与LUID基础。补兼容路径：实际绑定源、下一跳/接口、地址状态和NetworkGeneration见证；路由变化后有界重测，旧观察/旧Start不能给新出口授权。出站WinDivert不能靠IfIdx强制选路，应核对实际物理观察。

路由未明时使用保守共享桶，不给每个目的IP造一份额度。多物理出口可以分组公平，但用户配置若是“全机50Mbps”，不能因为两接口就变100Mbps；若将来支持每出口独立额度，另行清楚命名和配置。

### 恢复指标与策略

区分进程退出事件、对端离线、单向黑洞、控制不可达、本地路由变化、设备休眠。先让进程退出事件快速触发，再研究保活缩短；不能把100ms调度误称100ms网络故障检测。

保留 `FirstBusiness / StableBusinessStart / StableBusinessConfirmed` 三个时间。无实际业务只记StablePath；成功一次ping后再次超时不叫恢复完成。备用必须新鲜、已认证、MTU合格且质量适合，才用于快速接替。

两机独立可比启动≤15秒仍是效率目标，不把跨机异步启动55秒/17秒相减。优化先分解网卡、候选、协调、Ready、握手和业务阶段；不要单纯缩所有超时。改动若不达15秒但安全和质量合格，列性能偏差等待发布决策，不伪报Pass、不无限重构。

### NET-07：已有网关映射与原生IPv6能力验收

复用`PortControlLease/PortControlProtocol/Ipv6Direct`与两个现有外层IPv6provider。PCP/NAT-PMP使用网关实际返回的外部地址、端口、租期与epoch；续租、网关重启、拒绝/无响应均有期限，不阻塞已有直连；只删自身拥有的映射。显式映射存在不等于多层NAT全路径可达，最终以同路径认证业务验证。

原生IPv6单独确认源地址/接口/路由、入站过滤、实际MTU和后端能力。ULA或虚拟网卡地址不能冒充物理公网IPv6候选；IPv4与IPv6各自失败不互相污染缓存。保持内层IPv4与外层IPv6解耦，不为外层新增IPv6就扩展未实现的内层广播/IPv6产品承诺。无对应网关/原生IPv6环境时交付已完成代码、明确不可用原因和待测步骤，不能空置provider接口冒充实现。

## 7. 网络质量与UDP QoS：补齐兼容路径，而非更换有效协议

### QOS-01：兼容业务pacing/过载反馈

交接明确未完成，必须编码。让legacy进程业务与broker业务使用同一全机调度预算接口，按实际注入字节记账。控制额度与业务速率分开；HTTP/SYN/维护也不能无限逃逸，但必要确认预留可用。

队列仅保留一层有界积压；统计enqueue、实际注入、拒绝、挤出、取消、在途与年龄，不能把后续native队列藏起来。背压/发送失败传回Router而非静默丢失后宣称成功。pacing＝0仍有内存硬上限，不是无限队列模式。

默认先不变限速，由同版本A/B决定是否正式启用。兼容profile至少达到同等测量与限额能力；不能用删掉兼容后端来“完成”补齐。

### QOS-03：反馈、备用、质量选路

被动送达反馈优先于主动压测；主动诊断须同意、同路径、同方向、同窗口、有总量上限。保持原共享session90秒/总256MiB/单window15秒等实际常量的统一档案；手动20秒旧测速如要迁入，需要显式有界的新profile，不能悄悄违反window限制。

FakeTCP健康时，UDP仅因握手快/空载RTT低不能替换。普通质量迁移须持续收益、双端相容策略、共同提名、驻留/冷却；来源不足不切。优先把“故障时用合格备用恢复”做到可靠，再晋级频繁择优。

方向性测量不可省：A上行受限不代表B上行相同。1.0可记录两个方向并按业务目标选一条完整路径；方向拆分为不同承载可以作为独立实验，但没有版本化路由/反馈/重放测试不默认开启。

### QoS方案取舍

本轮保留已经有效的udp2raw HTTP profile。Phantun/其他FakeTCP实现、真实TCP/TLS/WSS、ICMP、FEC/多流条带化等可列比较研究，但不加入默认交付范围，也不能用替换承载绕过SO主线失败。真实TCP带来的可靠按序语义与本业务现有约束不同；QUIC外层仍是UDP，不自动规避UDP限制。

优先改进：发送pacing、包长/MTU、接收与发送缓冲有界、公平调度、实际出口拥塞反馈和恢复。不要默认改网卡offload、全局DSCP、防火墙或路由来取好看的结果。无业务语义时不把所有IP流量当可丢视频帧；实时业务期限策略需明确流分类/用户许可。[W7]

用户界面报告“观测到UDP可用容量不足”“FakeTCP达到目标”等事实，不宣称证明了运营商具体QoS规则、HTTP域名白名单或永久绕过。

## 9. 自主虚拟网卡与驱动：明确做什么、怎么验证、何时替换

### NIC-01：先完成自有适配层，不把现成接口说成没实现

`IPacketAdapter`已存在于`NativeAdapter.cs:11–15`，`MeshRuntimeServices`已有adapter工厂，native桥接在`transport/tun/adapter.cpp`。在此基础上增加provider ID/ABI版本、能力、开始/停止/取消、最大包长、ring统计和错误分类；不新建两套同义接口。

正式provider第一种仍是官方Wintun。测试fake/memory provider只能用于夹具；UI要区分“自主组网＋官方驱动”“自研驱动实验”，不能把桥接DLL改名就称自研内核。

修复网段冲突检查：读实际地址前缀与路由，识别同/24、父/子前缀、VPN路由与自有旧网卡。默认路由不是自动冲突；但经默认或其他VPN实际会吞掉overlay/peer出口时要诊断。已入网不单机改身份派生网段，冲突给出新建网络或正式全网迁移建议。精确清理自有地址/路由，不接管系统默认网关/DNS。

### 驱动的两个不同目标

| 目标 | 替换什么 | 不解决什么 |
|---|---|---|
| StreamLink虚拟网卡驱动 | Wintun的本机虚拟NIC与用户态收发接口 | 不替代WinDivert，不自动穿过上游NAT |
| StreamLink WFP捕获/注入后端 | WinDivert对应的外层捕获/注入能力 | 不替代网卡，不自动提供端点无关映射或QoS豁免 |

驱动所有权不是性能结论。保持相同网络/承载/包长进行A/B，证明复制成本、CPU、队列与恢复收益后再切换。

### DRV-00：架构决策与独立工具链

输出 `docs/adr/driver-boundary-1.0.md`：内核最小职责、威胁模型、L3 raw-IP语义、NDIS/NetAdapterCx选择、目标Windows构建、用户API、PnP/电源、签名路线、许可证和回滚。

推荐先验证符合IP miniport语义的NDIS路线。Microsoft netvmini提供虚拟以太网样例，不直接满足L3接口；若用虚拟以太网作为实验底座，必须明确Ethernet/ARP与IP边界，不能把原始IP包当以太帧。NetAdapterCx是否适合该纯虚拟IP设备须以官方支持模型和PoC判定，而不是因为名字更新就替换。[W11]

驱动用独立MSVC/WDK构建项目，不把现有MinGW项目当成能直接生成生产内核驱动。保持原Package默认不依赖WDK；新增明确driver构建目标。新增路径建议 `drivers/StreamLink.Tun/`、`transport/tun-native/`、`tests/StreamLink.AdapterContractTests/`，均为拟新增而非本次已有。

### DRV-01：本轮必须真正推进的最小自研TUN实现

交付真实源代码：INF、设备/队列/PnP/电源逻辑、用户DLL、provider、ABI头和契约测试，而非空接口或写“未来研究”。第一版只覆盖当前IPv4单播与1280B约定，不做内核加密、内核NAT、路由协议或全机防火墙。

建议先用可证明正确的有界buffered I/O完成收发和取消，再将共享ring作为独立优化。若直接做ring，必须验证用户可写索引、包长、整数溢出、wrap和内存可见性，内核不得直接信任共享元数据；内核保留私有计数，映射与进程退出严格回收。

设备/IOCTL限定本机服务拥有者。禁止任意内核/物理内存映射、任意指针读取、全局任意接口注入。Service退出、句柄清理、IRP取消、NDIS pause/restart、surprise removal、低内存全部有确定结果；一个用户进程死掉不能让系统蓝屏或留无法删除网卡。

通过相同IPacketAdapter契约：真实双向Wintun等价IP包、边界包/满队列、源目标验证、停启100轮、移除/重装、挂起读取消、并发关闭、进程崩溃；测试期不连接生产默认网络。[W12]

### DRV-02：驱动质量与签名Gate

在专用VM/备用机器做WDK静态分析、CodeQL适用规则、Driver Verifier、HVCI兼容、HLK适用测试、Secure Boot下合法签名加载、休眠/电源/多CPU压力。Verifier可能触发bugcheck，不能在唯一远程管理机器上无恢复通道运行。

微软官方将HLK/WHCP作为推荐生产路线，attestation与preproduction有不同测试/分发限制；preproduction信任不等于零售系统普遍信任。具体账号、EV证书、签名和当前政策需在提交时复核，不能承诺纯软件自动免费解决。[W13][W14]

缺WDK可交代码与未构建状态，缺签名账号/硬件标明确BlockedExternal；不把没有Windows构建的驱动标Verified。驱动只有在完整Gate通过后才进入默认安装。**本轮完成驱动最小研发，不等于1.0发布必须强行替换官方Wintun；默认驱动替换是独立里程碑。**

### DRV-03：自研WFP捕获后端的有限研究

本轮最低交付ADR、与现有capture-owner对应的接口设计、可用环境中的最小授权tuple捕获/注入样机与回环防护测试。只有确认WinDivert带来可测的关键瓶颈或部署限制，才扩展成完整替代。

WFP注入报文可能重新进入分类，必须用注入状态识别防止循环；服务失联时撤销自己的过滤规则，不留下全局丢包规则；只对授权tuple抑制内核RST，不对全机TCP动手。[W15]

不能在同一批提交同时改变TUN、捕获驱动、HTTP序号、加密和打洞算法，否则回归不能归因。每层都有旧provider回退和同样的契约测试。

## 10. 版本、安全交付、安装和兼容

### REL-01：可信发布与版本通道

修复`SettingsPage.CheckUpdate`只过滤draft的问题：stable/preview通道独立、SemVer含rc语义排序、不从列表第一条猜最新版。当前只是提示下载，新增自动升级属于另一个显式权限动作。

保留现有manifest路径/大小/hash/reparse检查，补必需文件集合、目标架构、依赖版本、产品/驱动ABI和应用签名/签名清单来源验证。签名后再计算最终文件hash，元数据归档hash与安装二进制hash分别保留。测试自签不成为生产根；生产签名凭据缺失须单独标明，不发布含私钥的工具包。

发行清单必须说明自主与第三方来源、许可证、SBOM、支持系统和实验范围。未审查上游漏洞/许可证版本不声称全依赖已审计。若需隐私上传诊断，默认关闭并让用户预览脱敏内容。

### REL-02：安装事务与回退

安装在受管版本目录准备好、校验好再切换服务。验证本地ServiceReady（匹配BuildId/协议、配置读写、可用驱动或可解释等待），不把SCM Running当全部成功。对端离线/校园网不可达不是安装损坏，显示WaitingPeer即可。

区分首次安装失败清理、升级失败恢复旧ImagePath、回退再次失败和已恢复网络。回退错误不得吞没。不得删除其他程序共享驱动或关闭其他P2P软件以“成功”。同网络0.5.x→1.0RC→0.5.x/上一RC，以及0.3.2独立旧协议迁移分别测试，后者不支持直接混网。

升级保留用户实验意图；后台/GUI/协调不匹配给具体能力限制。身份目录保留最高撤销revision，旧代码不能通过回退恢复被移除成员。凭据备份在原机器DPAPI范围内，不能为了测试导出明文私钥。

### 协调服务及观察设施

使用匹配版本的独立测试协调实例。准备控制API兼容、长轮询上限、观察服务允许IP/端口、反射认证/限额和部署回滚。IPv4 raw SYN观察端点不能默认假设能放在仅HTTP代理后；HTTPS控制域名与直接可达的raw观察地址分别配置。

控制依赖无业务中继含义。A—B和A—C可达、B—C失败时，B到C不得经A成功，所有GUI与统计应如实显示局部连通。观察服务不得演化为任意目标流量放大/转发API。

## 11. 验收矩阵与质量口径

### VAL-01：三层协议能力与新增覆盖

| 层级 | 必须实际完成 | 不得替代 |
|---|---|---|
| 模型/可移植协议 | 状态、长度、预算、序号、取消/重放 | Windows驱动或WAN |
| Windows真实IO/受控NAT | 端点持有、tuple、SO包序、业务/PMTU；拓扑行为通过映射表与抓包确认 | 任意校园/CGN设备总体成功率 |
| 真实WAN | 固定路径、时间、包hash下的同资源认证业务 | 其他网络、长时间视频、八节点 |
| 实际安装包 | 安装后服务账户、真实UI配对、驱动/生命周期/回退 | 开发机源码测试或DPAPI预置profile |

受控SO正例初始30/30、错误身份/旧代次0次晋升；每种公网组合报告分子分母、超时和成本，不声称30轮＝30个独立校园网。至少新增一类旧默认失败而新方法成功的完整FakeTCP覆盖作为核心价值Gate。某算法没有条件即保持实验，不伪称覆盖提升。

### VAL-02：先固定规则，再测，不事后改历史失败

**历史短测零丢包Gate和安装Fail必须永久保留原状态。** 本规格不授权Codex把原0.023055%/0.069531%改为Pass。先确认原门槛究竟要求短测零丢包、长期零丢包还是业务质量；若需区分测试网络物理损失与软件回归，在执行前提出有版本的新Gate并说明依据。没有产品负责人认可新口径，沿用旧Gate，达不到则交RC和真实失败，不无限“刷一次零丢包”。

已商定/建议延续的质量指标：历史50Mbps/20秒双方向顺序回归；具备容量的路径60分钟有效吞吐≥49Mbps；加载RTT p95相对同条件空载增量目标≤20ms；pacing A/B吞吐不能下降超过2%且尾延迟/恢复不退化。全部按明确方向、载荷层、时窗和背景负载计量，不把最终到达量当期限内到达。[H1]

**新建议**：1.0加24小时低/间歇负载后台在线与其中至少60分钟实际串流；标为本规格新增任务，不假称原计划已执行。实际Moonlight/远程应用的冻结、重连与丢帧统计独立；无可信单向时钟时不宣称50ms单向期限。对连接总耗时和恢复记录分阶段。

安装测试编排先记录双向结果；非安全性的质量门槛失败可在预先批准且有自动回退保护的窗口内继续另一个方向，最后统一判Fail；驱动崩溃、身份问题、失去管理等安全事件仍立即回退。恢复后的重测是新RunId，不把不同时段的成功拼成一次双向通过。

### VAL-03：Windows、八设备与失效测试

- 实际两端未登录冷启动、休眠/唤醒、Wi-Fi/有线转换、地址变化、路由变化、helper失效、native崩溃、GUI退出、服务重启；每项至少若干确定性重复，记录实际次数，不把单一成功泛化。
- 双端仅协调断开至少6分钟；另测观察服务失败、DNS失败和路径黑洞，不混淆依赖。授权更新不可达与已知撤销分别遵守明确安全策略。
- 三设备的部分连通/禁止转发负例；八台真实Windows的相应发布等级，28对在可达受控正例中验证，各种难NAT拓扑不保证28对全通。并发加入/单困难peer/已有串流再加入均衡预算。
- 切换候选时保持唯一逻辑会话计数/重放；源资源/worker/ring/映射/规则基线和测试后对比，不能把正常TIME_WAIT当泄漏。
- 打包前无开发运行时机器验证自包含；无权改系统策略时不加ExecutionPolicy Bypass，仅使用现有获准宿主或重新实现不依赖脚本的产品操作。

八真机不足为BlockedExternal，不能由同机8进程换名通过。拥有两台机器的开发阶段仍可完成全部可执行代码、模拟负例和安装测试，不为等八台机器继续写计划外功能。

机器清单给出精确依赖和模块。建议按以下里程碑推进，阶段Gate不是重复审批点：

### 每个任务统一交付格式

`TaskId / BaselineCommit / ChangedFiles / BehaviorBeforeAfter / Tests / EvidenceLevel / RunId / BinaryHash / Environment / FailureAndRegression / DefaultFlag / Remaining / Status`。

代码发现问题先加最小失败测试，再修复。历史回馈不算本轮复跑。本轮新增驱动可独立产物与证据；即使默认未替换，任务也不能虚报“自研驱动已通过生产验证”。

### Goal防失控规则

1. 不执行计划外的新协议、无限端口扫描或驱动大重构；有发现写到有限的Post-1.0列表。
2. 同类失败的新尝试必须注明新假设/变更/观测；没有就停止重复。
3. BlockedExternal写明缺设备、缺拓扑、缺签名或缺授权，以及准备好的命令/夹具；Partial明确还缺哪段代码。
4. 每里程碑产出可审查状态，而不是一段“继续优化”叙述。
5. 达到开发结束条件就结束本轮并交RC；不得为了达成字符串“全部完成”删除失败测试或改Scope。
6. 1.0的正式标签只在发布Gate满足且发布操作获准时创建；RC可以带准确标注的实验能力源码/插件，默认不激活。
