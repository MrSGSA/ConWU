## 3. 问题分级

- **P0**：应在发布或扩大可达攻击面前修复的明确解析/权限/状态安全问题。
- **P1**：1.0 可靠性、可用性、功能契约或交付必修问题；不自动等价于远程漏洞。
- **P2**：需要专项验证或性能/界面完善的问题。
- **证据等级**：`ConfirmedStatic` 源码可确认；`PrefixProbe` 隔离前缀复现；`IntegrationInference` 调用链推断；`DesignGate` 修改方案的前置约束；`HandoffPartial` 交接明确余项；`NeedsWindows` 真实 Windows 行为待测。

### F01 — P0：原生 TCP 接收解析的错误返回与最小头长缺口

**位置：** `transport/udp2raw/network.cpp:2184–2215`；调用方 `client.cpp:387–411`、`connection.cpp:595–612`。

确认的问题：

1. 在验证 `ip_payloadlen >= sizeof(my_tcphdr)` 之前读取 `tcph->doff`。
2. 头长判断为 `>0 && <=60`，没有要求 TCP 最小头长20B，故 doff 1–4 可通过这一层。
3. doff无效、或头长超过IP载荷时返回0；正常解码的成功返回值同样是0。
4. 上述分支没有设置输出 `payload/payloadlen`。旧客户端调用前的 `data/data_len` 没有初始化，随后仅检查返回是否小于0，再使用 `data_len`；其他接收调用也按0成功处理。

本次隔离探针结果：

| doff | IP逻辑载荷长度 | 源前缀返回 | 解释 |
|---:|---:|---:|---|
| 0 | 20 | 0，输出未变 | 非法头长被报为成功 |
| 15 | 20 | 0，输出未变 | 60B头超过20B载荷仍返回成功 |
| 1、4 | 20 | 探针哨兵99 | 通过错误的最小头长检查；99是探针添加的“前缀结束”，不是完整函数返回 |
| 5 | 10 | 0，输出未变 | 逻辑载荷不足20B，没有在读取头字段前拒绝 |
| 5 | 20 | 探针哨兵99 | 正常头通过前缀，完整后续解析未在此探针执行 |

**范围限制：** `TcpCaptureOwner.cs:83–102` 对受管路径已经验证TCP最小头长、IP长度与分片；这是一道真实已有防线。旧 `native_backend.cpp:175–226` 直接接收路径与 WinDivert 的过滤/解析还需验证。因此这里确认的是函数与调用契约缺陷，**不声称已证明未经认证的公网 RCE、稳定崩溃或所有路径均可触发**。

**修复：** 输入长度先验；所有失败为负值；函数入口清空输出；只在解析完整成功时提交输出/接收状态。为旧native和broker两种入口共用语义测试。`network.cpp:2164–2175` 对未知TCP选项只校验len>1，没有先验证len在剩余选项内，纳入同次解析审计。避免在失败途中保留半更新 `recv_info`。

**验收：** 真正完整解析器单元/模糊测试，截断长度0–19、doff0–15、越界选项、IP长度/分片/IPv6扩展头；ASan/UBSan/MSVC工具可用性分别记录；真实Windows负例检查。已有630状态模型、HTTP/bare兼容和有效业务不能回退。跟踪任务：`SEC-01/SEC-02`。

### F02 — P1：旧测速路径与新诊断策略分离，并可能牵连主链路

**位置：** `Quality.cs:18–22,26–65`；`MeshRunner.cs:99–110`；`MeshRuntimeServices.cs:37`；对照 `PathDiagnosticBudget.cs`。

**ConfirmedStatic/IntegrationInference：** 正式Runner在网卡建立后启动 `Quality.Serve`，不以新主动诊断许可为前提。该接口按对端地址找密钥、验证HMAC，单次最多60Mbps/20秒且仅一个发送任务；这些防线应保留。但发送路径未使用新 `PathDiagnosticResources` 会话总额、主动测量许可与冷却。完成后可接受新ID反复请求。这里不是未认证互联网开放放大器，而是**已授权成员范围内的诊断资源滥用和策略不一致**。

另：`quality`任务退出/故障会被主Runner await并抛错，虚拟网卡上诊断端口冲突等可能导致整个网格重启。应隔离可选诊断服务失败。

MAC当前只覆盖id/mbps/seconds，不覆盖Op/Count。底层MeshLink已提供报文认证，所以不能将此直接称为网络任意篡改；升级诊断格式时应域分离并绑定消息种类、成员/会话/方向、结果字段和有效期，避免语义复用。

**验收：** 无诊断授权时拒绝负载；授权有有效期、总额及公平限制；连续新ID不绕过额度；端口被占/发送异常只使测速不可用，已认证业务仍通；结果与实际路径/窗口对应。跟踪：`CTL-02`。

### F03 — P1：控制请求超时没有贯穿执行与资源关闭

**位置：** `ControlWorker.cs:68–72,88–90,155–163`，`DesktopBackend.cs:17`。

修复为可取消操作、独立OperationId、只读状态快照与有界停止流程。不能因GUI超时就释放仍被native使用的Lease；到强制终止阶段只处置本版本受托管进程，核实退出后回收。

验收：挂起helper/HTTP/native收包/测量的确定性夹具；状态界面可响应；明确停止结果；无双重释放、无无限新轮次。跟踪：`CTL-01`。

### F05 — 降权UI的P0设计门槛：不能把现有完整控制回复开放给普通用户

验收：普通未授权用户/远程SMB/伪造server均失败；只读UI拿不到完整profile；用户允许的启停不等于允许更换服务EXE或签发成员。跟踪：`UI-04/SEC-03`。

## 4. 已存在且应保留的实现

不要把以下项目当成“尚未开发”再造一套：

- `TcpEndpointLease`、`NativeAttachment`、`TcpCaptureOwner`：持续端点、授权附件、唯一捕获owner及同tuple互斥。
- `native_so_state.h`、`native_so.cpp`：双主动状态机、共同截止与上层角色分离。630模型用例本次确实通过，但不等于WAN已过。
- `UdpTraversal*.cs`：未Connect的唯一socket、prflx与正式路径接口；保留引用和获胜资源。
- `PathNomination`、`MeshTraversalAttempt`：共同提名与代次，不用同一wire tuple承载两个独立握手状态。
- `MeshLink`：每成员会话锁分配序号，Active/Candidate不各造同密钥计数器；重放、退役epoch机制已有，不在本轮无依据指控nonce复用。
- `LocalControlPipe`：SYSTEM/管理员ACL及远程SMB拒绝已存在。
- `ServiceInstaller`：清单路径、reparse、文件hash验证已有。
- `IPacketAdapter`接口已存在；`transport/tun/adapter.cpp`是官方Wintun的用户态桥，不是自研内核网卡驱动。
- `EgressRouteSnapshot`/Cache已有OS选路和接口聚合基础，不重新建立一套靠目标IP制造多个带宽额度的调度。
- 默认只直连、不跨成员转发、FakeTCP优先和合法Active保护，应作为回归不变量。

## 5. 自研网卡/驱动的审查结论

当前自主部分：用户态组网、身份、路由选择、协议适配、服务、UI、Wintun桥接。内核网卡依赖官方Wintun，报文截取/注入依赖WinDivert。两类驱动是不同功能，不能用“重写虚拟网卡”代替WinDivert，也不能把改名fork称为从零自研。

建议本轮真正启动**最小StreamLink虚拟网卡驱动＋用户API＋契约测试**，在独立研发通道执行；1.0默认继续已验证官方驱动，直到自研实现完成签名、安全与功能Gate。自研WFP捕获驱动另立可行性/最小实验，不与网卡驱动合并成无限大内核项目。上游NAT/运营商QoS仍在本机之外，自研驱动本身不能创造原生IPv6出口或保证更高穿透率。

NDIS/NetAdapterCx型号与目标Windows支持必须通过官方资料及最小样机决定；Microsoft netvmini是虚拟以太网示例，不自动等于产品所需L3 TUN。借用源码必须保留实际许可证和贡献来源，不能以改项目名清除义务。

正式驱动保持Secure Boot/HVCI适配，走合法签名/测试路径，不以关闭内存完整性、全局testsiging或漏洞驱动加载来交付。签名账户/证书/HLK实验设备不足可阻塞生产签名，不应阻止可完成的源码、ABI和测试夹具。
