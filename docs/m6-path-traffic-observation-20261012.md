# M6：同一路径的方向性业务窗口

开发基线 `9136f41`，后续源码尚未进入已发布的 0.5.3。本项为 AutoQuality 补本地观测基础，**没有启用 AutoQuality，也没有把本地累计量改写为对端送达证据**。

## 产品接线

`PathTrafficObservation` 由正式 Router 的实际保留路径持有。在共同提名确认后开始；记录五秒窗口，保留最近三个完整或明确不完整的窗口和当前窗口。通过路径状态、成员状态及 IPC 返回，Runner 每30秒仅报告有业务的已完成窗口。

- 接受发送：Router 成功交给实际承载的完整内层 IP 字节，不是应用净荷、物理线路字节或对端接收。
- 交付接收：同一路径上经 MeshLink 认证、重放判断、源/目的 IP 检查后，实际写入本机 IP 适配器的字节。
- 发送拒绝单独计数；不将其与真实线路丢包或接收不足混合。
- RTT 只取 nonce 匹配的实际路径往返，分空闲和探测发送时最近一秒有业务活动两类。每类最多32样本、另记舍弃数量；P50/P95 是保留样本的分位数，不是总体统计或50Mbps容量证明。
- 同一窗口边界延续最近活动时刻；不因五秒换窗将连续业务误标为空闲。探测在途期间业务开始或停止，不改变发送时的分类。
- 状态绑定实际 PathId、资源、出口代次和发送/接收 AEAD epoch；加密会话变化清掉旧比较窗口。换路径、取消和回退分别停止或新建观测；迟到旧路径业务不能复活它。
- 长时间停顿保留真实时长并标记不完整，不补造三个五秒成功窗口；快照不会替代实际调度推进。

这项观测不创建 socket、不增加控制报文、不更改业务重传/顺序、HTTP或序号行为。默认 FakeTCP策略与UDP降级许可保持原样。

真实Router负例刻意丢掉20个数据报中的10个：发送端窗口仍正确记录本地接受20包/25600B，对端只记录已交付10包/12800B；反向7包另记。没有跨设备时钟同步或对端接收反馈，所以发送损失、对端送达、单向延迟仍为null，Qualification为QualityUnknown。

本地测试不操作现用服务、驱动、网卡或路由。现用0.3.2服务只读核查仍Running/Auto；0.5.3的标签、二进制和Akane独立候选未改写。

原生短负载使用实际C++和同进程单调时钟端到端记录，关闭pacing；最终收包统计含收尾，不是时限送达率，也不是公网单向延迟。第一组P95约2.839/2.865ms仅供该受控链路定位。没有同场景未改源码的交替A/B，不能据此宣称CPU或尾延迟相对改善；这里只确认该条件下未低于原49Mbps短回归门槛。

## 仍需推进

1. 同路径、会话和实际序号范围绑定的认证对端反馈，明确迟到、丢失、重复和不完整观察；控制计入全机维护预算，不重传业务。
2. 备用路径的认证/MTU/寿命与正式协商，保持唯一收包/端口所有权和最多Active＋Candidate，不能用新ID在同一TCP四元组运行两套握手。
3. 有足够且条件可比的方向负载证据后，接AutoQuality的3×5秒收益、30秒驻留及60秒冷却；实验仍默认关闭。
4. WAN、真实Wintun、多出口、长期负载、恢复与八真实终端Gate继续单独验收。

本项只完成被动本地观测接入，不据此宣布完整M6或M0—M9完成。源提交和产物摘要由后续收据记录。
