# 兼容业务队列、注入回执与出口见证

新增 `LegacyEgressPacing` 显式实验开关，默认 false。开启时，正式 MeshRunner 创建一个全机 EgressPacer，兼容原生进程及受管候选工厂借用同一实例。不开启时保留兼容发送行为。原生能力 `legacyEgress=1` 与后台 IPC 能力独立协商，不凭版本字符串猜测。

原生兼容业务包保持原有完整外层 IP/TCP 字节，经受限、当前用户且核对双方 PID/随机凭据的独立管道交给父进程。控制包仍走独立原生控制队列，控制许可等待不阻塞业务。父进程唯一业务队列按实际外层字节、出口与成员公平调度，WinDivert SEND_ONLY/NO_INSTALL 注入成功才计发送并回执；拒绝、取消不重传业务。此接入不修改 HTTP、SEQ 或密码载荷。

资源界限：父进程业务队列沿用全机硬上限；零 Mbps 表示不按速率等待，但仍有 128KiB 队列。原生没有业务待发队列，只有一个待完成的管道写、最多64个业务回执记录和一个退出栅栏。管道缓冲及回执队列也有限，不声称它们零成本。捕获关闭前，栅栏要求父进程取消旧代次排队包并等待实际注入完成，再允许关闭捕获。SLGE1 单独报告原生忙碌丢弃、回执成功、拒绝及峰值在途。

出口见证使用原生控制元数据中的真实源四元组，在许可前同步查 Windows 的绑定源、LUID、接口、下一跳及状态。零 LUID/未知出口归入 Unresolved 保守桶；同 LUID 多地址不增加全机额度。实验业务必须引用当前捕获代次已准备的 tuple。见证只证明 OS 路由选择，不证明物理 NIC 发出或公网映射复用。普通兼容路径先做旁路审计，不因未启用实验而强制改变既有协议。

网络变化会取消仍在准备的旧兼容实例；迟到构造结果被回收。已经被 Router 认证使用的 pending 路径先保留为 Active，避免误删当前承载。

## 本轮结果

- 短轮次：真实 C++ HTTP/udp2raw、Windows 认证管道、MeshRouter 完整1280B双向业务，速率10Mbps和0均通过；57项检查。raw-IP承载与网卡是回环夹具，不是物理 WinDivert/Wintun 或公网。
- Egress 正确性72项通过：包括0限速的有界过载、取消、失败、成员公平及共享出口。性能 Gate 此次未跑。
- 正式 Runner/准备队列/实际加密UDP夹具：19项通过；网络变化取消迟到准备，原 Active 保留。
- Windows UI/配置回归103项通过。
- 保留失败：首次遥测将退出栅栏计为业务；随后强见证发现控制/业务捕获代次初值不一致。这两处已修复，短回归通过。
- **30轮扩大回归仍 Fail（136项后）**：未启业务pacing的第一个兼容 FakeTCP 建链阶段超时，两个进程仍活跃。日志有 cipher_decrypt failed，尚未定位其与既有HTTP前导、原生协议状态或本轮改动的关系。不得删历史 Fail、扩大期限或把短回归替代30轮 Gate。另一个较早30轮结果（531项后）因上述遥测错误 Fail，同样保留。
