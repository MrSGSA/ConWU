# M5：有界 UDP 多源探索机制

基于 `a24f657` 继续实现执行计划 §8.4。**本次完成内部机制及真实 Router 接口验证，尚未接入正式候选收集、签名协商或用户设置。M5 Gate 未通过，默认没有新增探测行为。** FakeTCP＋HTTP、MeshLink 业务加密和禁止中继策略保持原行为。

## 所有权与预算

`UdpProbabilityPreparation` 实现现有 `IPreparedMeshPath`，持有一个稳定侧源或至多 32 个严格侧源。每个源继续使用 `UdpTraversal` 的唯一接收循环，分流 STUN、检查、PMTU 和最终 MeshLink 数据。所有源从同一个 `TraversalResources` 账本先领取名额再创建 socket。

显式实验作用域暂时把该 UDP 账本上限提高到 40，既有 Active、Candidate、退役引用和新增源都占用名额。结束作用域不会强制关闭 Active；它恢复普通八资源准入上限，待原引用释放后才能继续分配。本次测试中，11 个原引用仍被持有时，请求 32 个源实际只获得 29 个。默认八资源上限没有改变，辅助监听也不能利用扩池占用实验槽位。

所有源共用一个 512 包、256KiB 轮次。第一批 STUN 观察开始计同一个 12 秒单调时钟期限；没有观察时从激活开始计时。重复观察、激活和获胜路径交接不续期。搜索不能用掉最后 24 个完成包名额；全机仍受 60pps、突发 8 包及原字节速率限制。完成包可以使用搜索 48pps 之外的剩余总额度，仍计入同一个全机和轮次账本，没有新增独立令牌桶。维护保留原子账本。

检查按源轮转；某个接收循环先失败，会退出轮转，避免其他源永远等不到机会。字节余额已不足必要的全尺寸选择确认包时立即结束。失败提供 `NoDirectPathWithinBudget`，并区分 `BudgetExhausted`、`DeadlineExpired` 和没有合格候选。取消会等待正在进行的 STUN 操作和检查任务结束，再关闭准确的资源引用。

## 双方选择同一条路径

不能让两端分别取 `WhenAny` 的第一个成功源。新增内部 `SLG3` 控制格式，在原小包检查及 1344B/DF PMTU 检查后，由稳定侧选择具体的严格侧来源端点和随机源 token，经过 `Select → Ack` 确认。

- 源 token 是每次资源创建的独立随机值，不是本地 `SocketResourceId`，不暴露本地 Lease 或句柄。
- MAC 密钥绑定成员共享密钥、双方身份/启动代次/候选版本/角色、本轮 Attempt 和验证 nonce。包内方向、稳定/严格角色、目标 token、来源 token 和实际来源地址同时受检查。
- 稳定侧只向本轮授权的单个对端 IPv4 地址探测，最多 256 个不同端口；严格侧只向一个固定端点发送。收到陌生地址或未经认证的来源不能改变候选。
- 严格侧只接受指向自己、且已经完成本地 PMTU 检查的选择；重复选择可以重发确认。稳定侧只有收到匹配确认才取得获胜路径。
- 未胜出的源在交接前关闭；获胜源单独增持引用。结束准备对象不会关闭 Router 持有的源，最终路径释放后才关闭它。
- `Select/Ack` 不是业务路径的最终晋升。获胜适配器仍需通过现有 MeshLink 双向身份验证和路径内共同提名，之后才承担虚拟 IP 数据。

普通 `SLP2` 保持既有格式。当前 `SLG3` 没有对外声明 capability，也没有旧客户端自动使用它的代码路径。源检查包中的 1/2 表示本轮协议方向，真实成员身份和编号由上下文及后续 MeshLink 绑定，不把创建者固定为稳定端或传输服务端。

确定性正例使用夹具已知的稳定端点和目标端口，**并未证明算法能自动发现这些条件**。模型 30 轮从激活到提名/完整业务约 0.868–1.727 秒；回环约 1.084–1.307 秒。该计时不含先前 STUN 观察，也不是公网冷启动指标；共同轮次截止时间仍包含观察。每轮实际单侧最高 46 个控制准入、16100 字节，远低于配置上限，不把预算上限代入本轮成功概率。

PMTU 不足负例约 6.13 秒因字节预算不足退出；错误密钥和稳定端实际 APDM 的负例约 12.02 秒结束，计时含本地调度收尾。全部负例没有返回获胜业务路径。错误角色、旧 Attempt、错误目标/源 token、无效 MAC、未经授权 IP 的选择不能提交路径；随后放行合法选择仍可成功。

纯数学实验 `N=32、M=256、R=65536` 的端口集合相交为 1175/10000（11.75%），95% 区间约 11.13%–12.40%。这不是校园网 UDP 成功率，更不是 TCP 成功率。`N=64、M=1024` 只作数学成本对照，不能作为可执行实验配置。

诊断分别给出 requested/opened/sent 的源数、不同目标端口数及控制准入开销。真实外部映射数保持 `Unknown/null`；模型产物中的映射表计数表示夹具创建的记录，并不作为生产侧已确认仍存活映射数。socket 数、模拟映射数和实际公网证据不混用。

## 尚缺的正式接入

1. 必须有来自实际稳定端资源、协议和出口代次的合格证据；单 STUN、同本地端口、UDP/TCP 混用观察都不能批准启动。当前没有满足该要求的生产证据提供者。
2. 增加独立 capability、双方签名的稳定/严格角色、固定端点、允许目标地址/端口集合及对应机会窗。扩展正式 Runner 工厂/Attempt，确保准备、共同截止时间及获胜选择通过真实协调接口接线。
3. 后续已完成与 TCP 校准/预测共用名额及同 pair/出口失败五分钟冷却，见 [共享增强调度](m5-shared-enhancement-admission-20261012.md)。健康合格 Active 禁止启动、完整资格和协商仍需正式产品接入，不能仅凭资源名额自动开启探测。
4. 真实受控 NAT 抓包核实来源端点连续性及线上开销，再做有前提的校园网试验。严格双随机 NAT 不使用单稳定端相交模型。

`Invoke-TraversalValidation.ps1` 加入两种环境各 30 轮、边界用例和数学模型；`Package.ps1` 加入短机制回归、边界和数学模型。增加脚本入口不代表本轮已执行完整 Local 或整包流程。本次代码未重新打包、部署或发布；当前已核验候选仍为 [a24f657](m9-a24f657-candidate-20261012.md)。
