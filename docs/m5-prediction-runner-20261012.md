# M5：签名预测协商与正式 Runner

基于 `bdba517` 的端口窗口组件，把独立校准模型接入正式 `MeshCandidateFactory → MeshTraversalManager → MeshTraversalAttempt → NativePortWindow → MeshRouter`。继续使用原 C++ FakeTCP＋HTTP、MeshLink 和虚拟 IP 数据面；没有业务服务器中继、成员中继、外层业务重传或按序等待。

## 启用条件与边界

- `TcpPortPrediction` 是独立的默认关闭设置，依赖受管 TCP、`TcpSynObservation`、`TcpPortCalibration`、真实 capture broker 和 wireControl 能力。设置窗口按后台 `TcpPredictionVersion` 显式能力禁用旧后台不支持的选项。
- 普通 TCP 候选先尝试。后续轮次仅在双方以及协调服务都声明 `TcpPrediction=1`、本出口模型已通过校准时才进入预测。普通 Offer 不会被静默替换成预测策略，健康路径的后台升级也不使用这一策略。
- 至少一方必须有合格的稳定映射模型，且该方本轮两个不同目标的原生 SYN 观察必须相同。它是有观测支持的模型前提，不是对真实 NAT 永久稳定性的保证；双方均非稳定模型立即拒绝。
- 稳定方本轮预测端口还必须等于其新鲜观察端口；例如校准时保留本地端口、当前却被改写时，在对等 SYN 前退出，不能继续宣称该预测满足稳定端前提。
- 每个候选只授权一个 IPv4 地址和最多八个不同端口，严格限制标准十进制、有序列表、模型 ID、候选 ID/版本、阶段和签名。来源 socket、capture owner 和 Lease ID 不发布给对端。
- 仍缺真实公网 TCP 预测、30 轮双 Windows、受控 NAT 外侧抓包等证据。当前公网观察设施只有一个受控公网 IP，不满足完整独立校准的多目标条件。本轮不修改现用两端服务或公网服务配置。

## 从预约到原生路径

1. 先取得全机增强名额及足够协调额度，再创建持续持有的独占 helper/Lease/capture。源资源归属于本地模型出口；catalog 提前读取，但实际观察稍后从这个持有的源发出。
2. 发送签名 `Offer(v1 reservation) → Reserved → Measure`。Ready 不能由“已分配端口数字”代替，双方必须已持有捕获资源。重复消息不重新分配资源，也不重启时钟。
3. Measure 之后各端使用单调时钟记录整轮八秒期限。并行完成 750ms 最终观察窗口；实际源资源、capture owner、出口代次、接口、观察目标和服务 epoch 必须一致。沿用校准模型生成本轮新鲜预测。
4. 双方交换签名 `Measured(v2)`。模型、候选 ID、稳定前提、公网 IP 保持原预约绑定。双方最终候选齐备后有界并行准备原生 worker；`Ready → Start` 后才允许对等 SYN。可处理对端 Measured 被后续 Ready 合并覆盖，以及本端先准备完成、仍需等待远端 Ready 的情况。
5. 在首次取得实际报文预算、即将注入时调用本模型 `TryClaim`。**预测年龄上限仍是从本机原生探测开始计的两秒**，排队、IPC 准备和 HTTP 等待均不能续期。拒绝或异常取消所有子尝试，不能发送首个 SYN。
6. TCP 外形、既有原生握手、载荷认证及路径内共同提名继续使用这一个八秒期限。获胜路径留给 Router；取消、失败或 Attempt 结束只释放其拥有的资源。Selected 后的报文仍由原 MeshLink 会话处理。

最终候选的签名元数据最长发布八秒，以覆盖控制交换、正常时钟偏差和握手。这个 TTL **不是**两秒预测新鲜度的替代：只有各端本地单调时钟及实际注入点的 `TryClaim` 能批准首次发包。过期或退役预测不会因为元数据尚可读取而重新有效。Selected 报告沿用既有规则，允许描述已认证的 Active，而不能凭公告刷新重建路径。

## 预算、调度与失败

- 校准与预测共用一个全机高成本名额。排队取消会释放该名额；等协调额度时尚不创建新的源 socket。不同 peer 不复制增强配额。
- 所有 HTTP 操作继续使用一个 40 次/分钟令牌桶；显式预测模式的突发容量为 8，其他模式仍为 6，均不超过服务端 48 次/分钟、突发 8。临界阶段暂缓普通刷新，提前等待足额令牌；实际请求逐次计账，无预付、退还或额外隐蔽通道。整体等待仍计入 60 秒机会窗。
- 观察 SYN、各预测 tuple 的原生握手、认证和提名共用同一个 120 包/64KiB 轮次，及原全机速率预算。窗口不会因为创建多个 worker 而增加配额；原生包仍在实际注入边界计账。
- 只有新鲜观察到提名结束这一有界阶段使用 25ms 本地处理周期；其余状态保留原 100ms 周期。它不增大 HTTP 或探测速率额度。
- 拥有模型的组件只在实际路径通过认证与共同提名后回报成功。已领取的尝试两次真实失败停用模型；成员撤销、对端重启、对端取消或本地取消不伪装成 NAT 算法失败。
- 校准完成只记录资格。单纯得到模型不会标记已直连；缺少模型、旧服务、旧对端、双方不稳定、时间耗尽、观察不匹配、过期领取等均明确退出，原有健康路径保留。

## 验证方法

联调采用真实 Windows TCP helper、实际 C++ 协议测试子进程、命名管道、正式 Runner/Factory/Actor/Router、固定证书 HTTPS 协调与 SYN 观察 API。内层测试 IP 适配器及原始报文 NAT 在内存中实现：一端 EIM/APDF，另一端固定步长 APDM/APDF。严格端发往观察器和对端时确实由测试 NAT 生成不同端口；对端只向旧 helper 提示端点发 SYN 时无法通过。

模型由每端二十个明确标记的合成独立窗口注入，**不是本轮经过公网采集的校准数据**。新鲜锚点使用实际发出的原生 SYN，经受控 NAT 改写后由正式观察器读取；后续预测连接必须通过真实原生认证和 MeshLink 业务验证。稳定端交替担任协议 client/server。连接后等待原八秒期限结束，再传输双向完整 1280B 内层 IP 包，并检查最终资源回收。

## 回退与后续

默认关闭的新选项不会改变现有配置。实验用户可关闭“小窗口预测”，保留原来的受管 TCP/显式入口；需要回到现有运行版本时使用原安装目录及原配置备份。新能力源码尚需后续 M9 重打候选包，本记录不替代安装、无人登录启动、回滚或八台真实 Windows Gate。

后续仍需验证物理 WinDivert/Wintun、真实校准与预测联动、不同公网 NAT/负载/观察延迟、真实多成员全机公平性，以及预算不足时的稳定恢复。单稳定端概率探索是另一工作项，本次不以小窗口预测代替它，也不宣称双端随机严格 NAT 可用。
