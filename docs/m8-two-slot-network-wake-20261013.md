# 历史双机流程的发现解耦与唤醒恢复

日期：2026-10-13。覆盖可选兼容包的 `NetworkRunner`；默认轻量包继续使用原生 MeshRunner，不重新引入 EasyTier 依赖。

## 变化

双槽启动器订阅与 MeshRunner 相同的有界网络/SCM Resume 提示。提示提前允许失败入口重试和下一次发现请求，并请求当前 mapping 复核。已有 mapping、健康会话和正在初始化的组件保持所有权，通知风暴不创建额外并发请求。

发布与读取各保留一个异步请求。本地循环最多100ms检查一次状态；协调操作仍沿用原有2.5秒/5秒间隔。缓慢发布不再阻塞读取、映射完成、会话准备和网络事件。停止时等待在途请求响应取消并完成资源清理。原来的连接退避改用本机单调时钟，公告到期继续按协议UTC判断。

对端公告更新不再立即销毁健康直连。旧路径失效后采用仍有效的新候选。helper维护失败停止发布本机候选，并保留仍被健康会话使用的 mapping；会话退役后才释放租约，再进行普通重试。没有跨 socket 移交、没有新增中继、没有绕过控制预算。

## 验证

`out/legacy-wake-20261013.log`：26项通过。覆盖双端同时准备、同步阻塞启动、远端入口不等待本机探测、协调中断、公告更新保留Active及之后恢复、启动失败重试、阻塞HTTP期间网络提示重试、唯一在途请求、helper失败后的资源保持、通知风暴、取消与清理。

这些测试运行正式 `NetworkRunner`，但协调、会话、mapping及OS通知为可控夹具。不安装驱动、不改变在用服务或网络；不证明真实休眠、SCM派发、无人登录启动或公网恢复性能。

## 剩余范围

默认兼容路径的完整物理出口核验、旧探测取消以及真实系统生命周期仍需继续。UDP旧入口目前没有即时refresh接口，会沿用其维护周期；不能据此宣称所有映射提供者都已实现即时复核。现用0.3.2与已发布0.5.5未替换。
